# Работа с my-jarvis

- Сохраняйте существующую архитектуру и функции Чушпана.
- Пользователь разрешил обычные коммиты и push в `origin` без повторного запроса.
- Перед изменениями выполняйте `.venv/bin/python scripts/git_sync.py begin`:
  это сохраняет личные данные отдельно, создаёт локальную контрольную точку и
  приостанавливает периодические коммиты на время работы.
- После законченного изменения запускайте подходящие тесты, Ruff и форматирование,
  затем `.venv/bin/python scripts/git_sync.py complete -m "type: конкретное изменение"`.
  Выполняйте это перед итоговым ответом; не полагайтесь только на уведомление Codex.
- При работе из worktree используйте соответствующий checkout; установленная
  автоматическая публикация обслуживает только основную `main`.
- Не отключайте сканер секретов и Git hooks. Не используйте `--no-verify`, force push,
  автоматический rebase/reset и публикацию `refs/checkpoints/*`.
- При `pending_push` локальный коммит сохранён, повтор произойдёт автоматически.
  При `blocked` укажите точную причину, исправьте её безопасно; не переписывайте историю.
- Личные настройки — `config.local.yaml`, `.env`, `private/` и `data/`; они вне Git.
  Не переносите память, диалоги, авторизацию или диагностические экспорты в исходники.
- Не записывайте микрофон и не проверяйте физические устройства без разрешения.

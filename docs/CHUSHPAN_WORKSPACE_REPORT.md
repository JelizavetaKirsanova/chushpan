# Graphite Studio и состояние AI-моделей

## Что мешало раньше

- Fallback уже имел бюджет 15 с и cooldown, но не отдавал интерфейсу историю
  успешности, причину перехода и состояние восстановления каждой модели.
- UI показывал настроенную цепочку вместо фактически отвечающей модели.
- Ошибка посреди генерации могла оставить частичный ответ в истории как обычный.
  Закрытие вложенных async-генераторов могло происходить позже в другом Context.
- Три равнозначные колонки, неон, технические показатели и короткая лента
  из четырёх сообщений конкурировали со сферой. Предыдущие диалоги не открывались.
- Canvas имитировал речевые колебания без реальной амплитуды; эта имитация удалена.

## Дизайн

Рассмотрены Graphite Studio (сфера и разговор в центре), Compact Companion
(маленькое окно с выдвижными панелями) и Native Workspace (диалог в центре,
сфера вторична). Выбран Graphite Studio: голос остаётся главным, а память,
настройки и диагностика доступны без перегрузки главного экрана.

Появилась навигация Диалог / История / Мой день / Диагностика / Настройки,
графитовые поверхности, системная типографика, холодные акценты, сфера Canvas,
компактные AI-показатели. Погода, новости, таймеры, системные сведения,
экспорт и существующий автозапуск сохранены. Основная кнопка управляет
существующим wake/sleep голосового цикла, а не сном Mac.

Комбинации: ⌘1 — диалог, ⌘2 — история, ⌘, — настройки, Escape — диалог;
существующие Space и F сохранены. Добавлены focus-visible, aria-current,
disabled при отсутствии соединения, пустые состояния, адаптивные раскладки
1100/820/540 px. Reduce Motion останавливает вращение и CSS-анимации;
Canvas ограничен 15 FPS в покое, скрытый документ не перерисовывается.
Нет искусственных аудиоданных: при устаревшем или отсутствующем уровне — ноль.

История использует существующую SQLite: до 50 последних разговоров и до 200
последних сообщений выбранного диалога. Есть время, роли, прокрутка; tool-трафик
и пустые служебные сообщения исключены. Schema и рабочая база не пересоздаются.
Настройки показывают реальные параметры только для чтения. Неработающих
переключателей микрофона/голоса/модели не добавлено; менять их пока нужно
в config.yaml с перезапуском. Автозапуск остаётся существующим действующим контролом.

## Менеджер моделей

Улучшен существующий FallbackClient, второй диспетчер не создавался.
Приоритеты: предпочитаемая Gemini → резервная Gemini → локальная Ollama.
Сохранены общий бюджет облака 15 с, SDK без скрытых повторов, лимит контекста,
детерминированные локальные команды и безопасный текстовый streaming.

- Для каждой модели: успехи/ошибки, последняя задержка, состояние circuit,
  остаток cooldown и безопасная причина ошибки.
- 503/504/сеть/таймаут: исключение на 30 с. 429: на 60 с. В пределах одного
  запроса явная ошибка сразу отдаёт управление следующему кандидату.
- Восстановление проверяется следующим обычным запросом после срока. Нет
  периодических API-пингов или отдельной LLM для классификации сложности.
  Одновременные пробные запросы восстановления ограничиваются; успешная
  предпочитаемая модель возвращается в приоритет.
- 400/401/403/404 не запускают автоматические повторы через другую модель.
  Исправление конфигурации/ключа требует обычного перезапуска, .env не менялся.
- Отмена не считается ошибкой доступности модели и не увеличивает failures.
- После частичного текста или уже выполненного инструмента цепочка не
  повторяется автоматически. Серверные ID function call остаются привязаны
  к выдавшему их провайдеру.
- Когда всё недоступно, интерфейс получает понятное уведомление и остаётся
  готов к слушанию. Пользовательский вопрос сохраняется при ошибке генерации;
  неудачный частичный ответ не сохраняется как завершённый. При намеренном
  пользовательском прерывании уже выданная часть сохраняется по прежним правилам.

AI-состояние передаётся существующим WebSocket (ai_status); распознавание —
activity, команды — прежним tool, проблемы — notice. Нет новых периодических
HTTP-запросов. История запрашивается по клику тем же WS, с прежней проверкой
Origin и точным типом значения. Названия/значения интерфейса вставляются через
textContent, не HTML. В логах модели — только безопасные коды/идентификаторы
и времена; тексты истории и ключи в новые логи не добавляются.

## Измерения

| Показатель | До этого задания | После |
| --- | --- | --- |
| Общий облачный бюджет | 15 с | 15 с, сохранён |
| Пауза после 503/504 | 30 с | 30 с, плюс наблюдаемое состояние/пробное восстановление |
| Пауза после 429 | 30 с | 60 с |
| SDK-мок без UI-подписчика, медиана 200 вызовов | 0.0417 мс | база сравнения внутри новой версии |
| Тот же SDK-мок с доставкой событий HUD | — | 0.0629 мс; добавка 0.0212 мс |
| JS production gzip | около 11.31 kB | около 13.2 kB |

Мок-замер измеряет накладные расходы доставки событий, а не сеть, GPU или FPS.
На том же Mac выполнен один новый нейтральный запрос без истории/микрофона:
основная Gemini вернула 503 за 0.593 с; резервная не уложилась в оставшиеся
14.410 с. Ollama qwen3:8b ответила за 10.688 с; первый текст всей цепочки
24.442 с, полное завершение 25.694 с. Локальная команда времени — 1.314 мс.
Это не сопоставимые условия с прежним здоровым ответом Gemini 2.400 с;
процент ускорения не выдумывается. В приложении менеджер живёт между запросами,
поэтому последующие обращения используют cooldown; новый CLI-процесс начинает
с чистого состояния. Реальное сетевое время по-прежнему зависит от сервиса.

Новых runtime-зависимостей и тяжёлых графических библиотек нет. Настоящий
end-to-end голосовой замер и измерение CPU/FPS при одновременной речи требуют
ручной проверки; микрофон в этом задании не записывался.

## Проверка интерфейса

Финальные результаты: 958 backend-тестов прошли за 20.54 с; 3 frontend-теста
прошли на Node 22 через встроенный test runner. Ruff check / format --check,
TypeScript, Vite production build и git diff --check прошли. Новые тесты
проверяют circuit при 503/504/429, возврат к Gemini, отмену без ложного failure,
сохранение вопроса при ошибке, историю без tool-трафика и доставку истории
через существующий WebSocket. Прежние тесты покрывают недоступную Ollama,
авторизацию, лимит облачного бюджета, повторные действия и восстановление голоса.
Node сообщает ExperimentalWarning о встроенном удалении TypeScript-типов;
ошибок тестов нет. Дополнительные зависимости не устанавливались.

Собранная production-страница открыта в Safari на localhost. Проверены
главный экран, навигация в историю и пустые состояния. Получены скриншоты
в чате. Они показывают честный offline-preview, а не фиктивные результаты AI
или выдуманную историю. Встроенный браузер не смог открыть localhost,
поэтому использован локальный Safari. В standalone HTTP-preview нет /ws:
ошибки соединения в его консоли ожидаемы и не означают ошибку production WS.
Полная интеграция истории через WS проверена TestClient на тестовой SQLite.

## Изменённые файлы

- backend/brain/providers.py — health, circuit/recovery, события AI.
- backend/brain/conversation.py — закрытие async-генераторов, сохранение вопроса
  при ошибке и отделение неудачного ответа от завершённого.
- backend/voice.py — привязка workspace и AI-событий, распознавание/обработка,
  человеческие уведомления; голосовые модели и команды не заменялись.
- backend/memory/store.py — ограниченные read-only запросы истории.
- backend/hud/bus.py, backend/hud/server.py, backend/hud/workspace.py —
  новые события и безопасный запрос истории в существующем транспорте.
- frontend/index.html — новая структура рабочего пространства.
- frontend/src/workspace.ts, workspace_state.ts, workspace.css — навигация,
  история, реальные настройки, AI-панель и Graphite-дизайн.
- frontend/src/core.ts — сфера, настоящая амплитуда, Reduce Motion и idle-render.
- frontend/src/main.ts, panels.ts, socket.ts, types.ts — интеграция событий,
  временные отметки, управление и типы.
- frontend/package.json, frontend/tests/workspace.test.ts, tests/test_workspace.py — тесты.

Остальные изменения, существовавшие до задания, не откатывались.

## Запуск и оставшиеся ограничения

Остановить прежний экземпляр, затем:

```bash
cd ~/my-jarvis
uv run python -m backend voice --no-briefing
```

Frontend уже собран. Для пересборки: npm --prefix frontend run build.
Без микрофона: uv run python -m backend latency-check. Контроль сети
производится только с явным --live; реальные системные команды он не выполняет.

Остаются внешняя нестабильность Gemini; ручная проверка macOS-разрешений и
Youtube sleep; отсутствие редактора конфигурации в UI и пагинации за пределами
ограниченного окна истории. Для истории нужен backend, offline-preview её
не выдумывает. Живая проверка голоса, всех размеров окна и fullscreen под
нагрузкой не заменяется unit-тестами. Защиты, Whisper large-v3-turbo, Silero,
ключи, .env и существующие настройки не изменялись. Commit/push нет.

# Аудит медиатеки и macOS — 5 ноября 2026

Проверка текущей `main`, исходная точка `e378663`. В этой же рабочей папке
параллельная задача исправляет видеоплеер, проверку полного видео и смену ссылок.
Её незакоммиченные изменения сохраняются отдельно от изменений этого аудита.
Существующие функции, настройки, история и фиолетовая тема сохранены.

## Подтверждённые причины и исправления

1. **Противоречащие фильтры давали необъяснимую пустую выдачу.** Например,
   выбранная анимация одновременно исключалась настройкой `hide_animation`.
   Теперь каталог возвращает объяснение конфликта жанра, типа подборки или годов;
   интерфейс показывает его, сохраняя фильтры. OR с другим разрешённым жанром
   продолжает работать, явный поиск без ограничений может включать скрытый жанр.
   Разделители TMDB сохранены: запятая означает AND, `|` означает OR.

2. **Неизвестный год исключал совпадающие страницы.** Условие в проверке
   структурированных метаданных и в Internet Archive требовало ненулевой год.
   Теперь год сравнивается, когда он известен. Поиск без года возвращает
   ручные варианты, а карточка не становится доказательством полного видео.
   Для автоматического воспроизведения без года всё ещё нужна точная внешняя
   идентичность произведения, а также привязка самого медиа. Известный
   противоречащий год не игнорируется из-за совпадения IMDb.

3. **Обзор и клип имели один тип.** Добавлен самостоятельный тип `review`;
   русское слово «клип» тоже распознаётся. Трейлер, тизер, обзор и клип исключаются
   из просмотра полного фильма и получают отдельные подписи в интерфейсе.

4. **Кэш YouTube Music переживал изменение настройки и переустановку.**
   Раньше существования старого пути было достаточно, чтобы вернуть старую пару
   path/bundle ID. Теперь конфигурация и Info.plist читаются заново. Используется
   явно выбранный путь, затем сохранённый bundle ID; Spotlight помогает найти
   перемещённое приложение. При нескольких подходящих приложениях нужен выбор.
   Неоднозначность больше не подменяется браузерным fallback. Повреждённый plist
   обрабатывается контролируемой ошибкой.

5. **AX-проверка воспроизведения сравнивала часы как строки.** Переход
   `9:59 → 10:00` мог не считаться движением; изменение общей длительности,
   наоборот, могло им считаться. Теперь сравниваются секунды текущей позиции,
   проверяются те же трек, исполнитель и альбом. Пауза сбрасывает наблюдение.

6. **Библиотека Web App не гарантировала ссылки на плейлисты.** После SPA-перехода
   ссылки ещё загружались; кроме того, библиотека могла сохранять другой фильтр.
   Теперь выполняется ограниченное ожидание и выбирается доступный фильтр
   «Плейлисты». Если AX-путь успел измениться, только явный отказ native preflight
   до нажатия позволяет один раз найти тот же однозначный элемент заново.
   Ошибки уже отправленного действия не повторяются.

7. **Незавершённая перемотка могла выглядеть успешной.** В реальном Safari
   позиция менялась при `seeking=true`, а допуск в две секунды позволял принять
   старое значение. Теперь завершение seeking обязательно. При зависании Safari
   возвращается конкретная причина; незавершённая позиция не выдаётся за успех.
   Оставшееся ограничение реального Safari описано ниже.

8. **Подсказка системных настроек не объясняла возможный перезапуск.** Для
   Accessibility и Screen Recording теперь поясняется, что при предложении
   macOS нужно перезапустить указанного исполнителя и повторить проверку.
   Само открытие настроек не считается выдачей права. Существующий мастер первого
   запуска, сохранение отказа и чтение актуального статуса проходят регрессии.

## Что не подтверждено и что мешает полной приёмке

- Safari запускает локальное немое видео, восстанавливает позицию с отступом
  три секунды, подтверждает паузу и fullscreen. В данном окружении последующая
  перемотка **на паузе в fullscreen** остаётся `seeking=true`, хотя currentTime
  уже изменён. Этот сценарий завершается честной ошибкой; живая проверка
  дальнейшего закрытия/перезапуска и следующей серии не засчитана. Нужна
  дополнительная проверка поведения Safari/AVKit с пользовательским действием.
- Старый интеграционный сценарий `--personal` ожидает автоматическое встраивание
  прямого файла без подтверждённой идентичности медиа и останавливается на
  ожидании `.cinema-embedded video`. Это не засчитанный интеграционный тест;
  ослаблять проверку полного видео ради него нельзя.
- Холодный запуск после выхода из macOS, перенос настоящего приложения в другую
  папку и переустановка не испытывались на пользовательской копии: эти случаи
  проверены временными `.app` и моками Spotlight. Запуск работающего реального
  Web App и Favourite Songs проверены отдельно, как описано выше.
- Реальные внешние кинопровайдеры, междоменные/DRM-плееры, пользовательские
  системные диалоги TCC, холодный первый запуск, запись микрофона, BLE/AirPlay,
  физические устройства и установка новой копии в `/Applications` не проверялись.
- GitHub Actions настроен на push и pull request: frontend в Linux; Python и
  компиляция Swift отдельными macOS jobs. Моки macOS явно обозначены. Зелёный
  удалённый CI не выводится из локальных тестов. Первый запуск действительно
  подтвердил frontend и Swift и выявил неиспользуемую переменную в прежней
  `public_search.py`; она удалена. Python-job получает также macOS-зависимости
  из существующего lock-файла. Актуальный результат доступен в
  [GitHub Actions](https://github.com/JelizavetaKirsanova/chushpan/actions).

Полная приёмка критических живых сценариев пока не завершена.

# Tavily Search · Чушпан 0.2.10 (build 12)

Продолжает [интеграцию Safari 0.2.9](CINEMA_SAFARI.md). Медиатека, история,
списки, TMDB, озвучки, прогресс, подключённые источники и настройки Brave сохранены.

## Настройка

В «Фильмы и сериалы → Настройки → Поиск и Safari»:

1. Tavily выбран основным поисковым провайдером по умолчанию.
2. Введи ключ `tvly-…` в поле «Ключ Tavily API» и сохрани.
3. Нажми «Проверить подключение». Проверка использует официальный
   [GET /usage](https://docs.tavily.com/documentation/api-reference/endpoint/usage),
   не выполняя поисковый запрос. Показываются подтверждение подключения,
   использование кредитов и лимит ключа, если он задан.
4. Brave остаётся необязательным провайдером. Его старый ключ сохранён в прежнем
   закрытом файле; можно явно выбрать Brave. Автоматического переключения
   между провайдерами после ошибок нет.

Ключ Tavily хранится **только в macOS Keychain**: generic password,
service `ee.chushpan.cinema.search`, account `tavily`. Используются публичные
Security.framework API через PyObjC: SecItemAdd/Update/CopyMatching/Delete.
Ключ не передаётся в аргументах процессов, переменных окружения, URL,
HUD-снимках или LLM и не входит в Git, диагностический журнал и экспорт
медиатеки. Поле очищается перед отправкой; ключ в интерфейс не возвращается.
Статус запрашивается без чтения пароля и без диалога авторизации.
При заблокированной Связке ключей или отказе доступа файлового обходного
хранилища нет. macOS может запросить разрешение на чтение ключа приложением.

## Поиск и расход кредитов

Используется официальный [POST /search](https://docs.tavily.com/documentation/api-reference/endpoint/search)
с Bearer-заголовком. Один запрос `basic` содержит русское, оригинальное и
альтернативное название из TMDB, год, `SxxEyy`, сезон и номер серии. Приоритеты
бесплатного доступа и русской озвучки учитываются в запросе и существующем
ранжировании. AI-ответ, исходный текст и изображения не запрашиваются;
`auto_parameters` отключён, чтобы провайдер не менял глубину поиска.
Произвольный список доменов не ограничивает интернет-поиск.

Сначала проверяются сохранённая конкретная серия, ранее выбранный источник
и подключённые адаптеры. Если точная доступная ссылка уже сохранена, повторного
Tavily-поиска нет, включая перезапуск приложения. Результаты поиска также
кешируются существующим SourceManager. Неудачный ответ API не повторяется
автоматически. Поиск может расходовать кредиты согласно тарифу Tavily.

Полученные URL проходят прежнюю независимую проверку: HTTPS, публичный DNS,
robots.txt, ограничения и редиректы, название, год/IMDb, тип произведения,
сезон и серия по метаданным TVEpisode. Сниппет и рейтинг Tavily не доказывают
идентичность страницы, бесплатность, легальность, региональный доступ или
наличие работающего видео. Неизвестные условия остаются UNKNOWN. Новый
сайт требует первого явного выбора, как и раньше; затем ссылка сохраняется.

Открывается конкретная проверенная страница в Safari. Восстановление времени,
подтверждение реального движения позиции, ручной режим для несовместимых
плееров, DRM/cross-origin ограничения и сохранение прогресса используют
существующие адаптеры без подмены открытой страницы «запущенным видео».

## Ошибки

- HTTP 401 — ключ неверен или отозван.
- HTTP 403 — запрос запрещён провайдером.
- HTTP 429 — превышена частота запросов; нужно подождать.
- HTTP 432 — исчерпан лимит кредитов/использования ключа или плана.
- HTTP 433 — достигнут лимит оплаты по использованию.
- HTTP 434 — временное ограничение получения контента.
- Сеть, некорректный/слишком большой ответ и недоступный Keychain имеют
  отдельные безопасные сообщения. Тело ошибки API и секреты не показываются.

Перенаправления API не выполняются: ключ не может уйти другому хосту.
Ошибки Tavily не мешают открытию уже сохранённых доступных ссылок.

## Проверки

- Тесты настоящего протокола на MockTransport: POST /search, GET /usage,
  Bearer только в заголовке, один запрос basic с нужными метаданными,
  неверный ключ, 403/429/432/433/434/500, запрет редиректов, сеть,
  повреждённые и слишком большие ответы.
- Путь Tavily → независимая проверка серии → первый выбор нового источника →
  сохранение URL → закрытие сервиса/SQLite → повторное открытие без второго
  запроса Tavily. Проверено, что открытие страницы не подтверждает видео.
- Неподходящая серия отклоняется даже при точном сниппете Tavily. При исчерпании
  кредитов нет скрытого переключения на Brave или повторного расхода.
- Keychain: тесты отказа, блокировки, создания, обновления, удаления и статуса
  без пароля. Дополнительно реальные операции Security.framework выполнены
  на отдельной временной записи со случайной тестовой строкой; запись удалена.
  Пользовательские записи не перечислялись и не читались.
- Реальный GET /usage Tavily отклонил случайный неверный тестовый ключ
  с ожидаемым HTTP 401. Поиск с пользовательским ключом **не выполнялся**:
  ключ не предоставлен приложению. Его нужно один раз ввести в настройках.
- Проверены новый экран настроек, выбор провайдера, маскирование/очистка поля,
  проверка подключения и сообщения о лимите. Старые сценарии кинотеки
  проверены на настоящем видео без звука в Chromium и Safari, включая
  восстановление после закрытия вкладки/перезапуска, паузу и следующую серию.

Полный набор: 2291 Python-тест, 114 frontend-тестов, Ruff, форматирование,
TypeScript/Vite и проверка подписи собранного приложения.

Интеграция проверена отдельно от доступности конкретных сторонних плееров.
Tavily не снимает ограничения Safari, авторизации, подписки и DRM.

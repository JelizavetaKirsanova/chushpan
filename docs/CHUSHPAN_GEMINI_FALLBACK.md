# Проверка Gemini и резервная цепочка

30 октября 2026 года. Дополнение к этапу 4; этап 5 не начат.

## Реальный запрос

Выполнена ровно **одна генерация** через официальный Google Gen AI SDK, без
автоматических повторов. Запрошена `gemini-3.5-flash`, вопрос:
«Сколько будет 2 + 2? Ответь только одной цифрой.»

- HTTP 200, ответ `4`, finish reason STOP, время 2,21 с.
- Поле API `model_version`: **gemini-3.6-flash**. Именно эта модель реально ответила.
- Пробный API-скрипт прочитал ключ из существующей настройки и не печатал его.
- История, память, личность, файлы, изображения и инструменты не отправлялись.
- Новых запросов к 3.8/2.5 не выполнялось: их 503/404 сообщила пользовательница.

Google указывает, что устаревший идентификатор 3.5 Flash перенаправляется на 3.6.
Сохранён запрошенный пользовательницей идентификатор резерва; фактическая версия
ответа отражается отдельно. [Карточка Google](https://ai.google.dev/gemini-api/docs/models/gemini-3.5-flash).

## Порядок и границы переключения

В `config.yaml` настроено:

```yaml
llm:
  provider: gemini
  fallback: true
gemini:
  model: gemini-3.8-flash
  fallback_model: gemini-3.5-flash
  timeout_s: 15
```

Цепочка: **3.8 Flash → 3.5 Flash (сейчас отвечает 3.6) → установленная локальная
Ollama**. Повторяющиеся идентификаторы моделей не запрашиваются второй раз.

Переключение разрешено только при HTTP **429, 500, 502, 503, 504**, сетевых
тайм-аутах и ошибках соединения. HTTP **400, 401, 403, 404** и другие ошибки
конфигурации/авторизации/неизвестные ошибки останавливают запрос. Сообщение содержит
безопасное описание и HTTP-код, без текста SDK-исключения. Ошибка второй облачной
модели также не скрывается за Ollama, если она не временная.

На одну генерацию — максимум **одна попытка каждой модели**, то есть до двух
облачных запросов и одного локального. Повторы SDK отключены (`attempts=1`),
backoff и циклических повторов нет. Внешний deadline — 15 с на облачную модель,
до 30 с ожидания двух моделей, далее отдельное ожидание Ollama. Многошаговый диалог
с инструментами может требовать нескольких генераций, это не общий лимит диалога.

Модель, выдавшая tool call, закрепляется за текущим серверным request ID: результат
функции возвращается ей с исходными подписанными parts. После уже выполненного
инструмента автоматического повтора цепочки нет, чтобы не повторить действие.
После частичного ответа, блокировки или пустого/обрезанного ответа повторов тоже
нет. Новый пользовательский запрос снова начинает с основной модели.

Отсутствие ключа или ручного флага Free tier — прежний явный режим настройки:
выводится инструкция, при включённом fallback используется Ollama без обращения
к Google. Это отличается от HTTP-ошибки существующего ключа: она не маскируется.
`JARVIS_LLM__PROVIDER=ollama` по-прежнему выбирает полностью локальный режим;
`llm.fallback: false` отключает резервную цепочку.

## Логи

Логируются только провайдер, запрошенная/фактическая модель, HTTP-статус и признак
временной ошибки. Например, после успешного переключения:

```text
LLM failed provider=gemini model=gemini-3.8-flash status=503 transient=True
LLM selected provider=gemini model=gemini-3.6-flash requested_model=gemini-3.5-flash
```

Это пример формата, не дополнительный реальный вызов цепочки. Текст запроса,
ответа, ключ, URL с credentials, память, device/session ID и тело API-ошибки
в новые логи маршрутизации не включаются. Поле модели проверяется перед логированием.

## Проверки

- Полный Python-набор: **660 passed**, 16,46 с, без предупреждений. Защитный runner
  не зарегистрировал попыток реального управления Mac, аудио, сети или записи
  пользовательских данных тестами.
- В `tests/test_providers.py` проходят **55 случаев**, включая 24 добавленных
  случая этой доработки: все временные статусы, фатальные ошибки обеих моделей,
  тайм-ауты/соединение, отказ обеих облачных моделей → Ollama, ограничение попыток,
  пустой/частичный ответ, подписанные tool rounds, новый request, безопасные логи.
- Настоящий SDK с `httpx.MockTransport` выполнил ровно два HTTP-вызова при
  искусственном 503 → 200. Это проверка сериализации и отсутствия скрытых SDK
  повторов, без сети и расходов; провайдерная цепочка проверена искусственными сбоями.
- Ruff check и format --check всего проекта: успешно, 125 Python-файлов.
- TypeScript, frontend build и три Swift typecheck прошли в этом этапе;
  эта доработка их исходники не меняет.

Проверка HTTP 200 выше — реальная, но не заменяет сравнение личности Gemini/Qwen,
живой анализ экрана или реальный запуск Shortcuts. Повторные платные/облачные
пробы ради имитации ошибок не проводились; тариф и Billing не менялись.

## Изменения и сохранность

Рабочий код этой доработки: `backend/brain/providers.py`, `backend/config.py`,
`config.yaml`; тесты — `tests/test_providers.py`. Обновлены README, архитектура,
дорожная карта, протокол/отчёт этапа 4 и этот документ. Из `.env.example` удалено
обнаруженное непустое значение ключа и лишняя пустая строка в конце файла.

**Инцидент диагностики:** в конце проверки обнаружен ключ в отслеживаемом
`.env.example`; строка по ошибке попала в вывод инструмента этого чата. Значение
удалено из шаблона и в документах не повторяется. Проверка точных известных
значений в исходниках, тестах, документации и шаблоне не нашла оставшихся копий.
Рекомендуется перевыпустить ключ; автоматически он не отзывался и не заменялся.

`.env` не редактировался этой доработкой; введённый пользовательницей ключ сохранён.
Настройки голоса, wake-word, личность, память и YouTube Music не менялись.
Уже работающий голосовой процесс не перезапускался; он продолжает пополнять
память обычными сообщениями. Для применения нового кода потребуется обычный
перезапуск ассистента пользовательницей. Коммитов и push нет.

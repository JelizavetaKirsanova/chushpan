# Центр разрешений

Открывается в «Настройки → Доступ и безопасность». Каталог показывает механизм
авторизации, зависимые функции, состояние публичного API и исполнителя проверки.
Поиск, категории и фильтр проблем работают локально. При возвращении в окно
проверка повторяется без запроса прав. Ссылки открывает NSWorkspace; macOS может
проигнорировать якорь раздела, поэтому всегда показан точный ручной маршрут.
Успешное открытие настроек не считается выдачей доступа.

## Запросы по необходимости

- Микрофон: AVFoundation после явного включения прослушивания; результат callback
  перепроверяется через authorizationStatus. Кнопка запроса в центре не включает запись.
- Safari Music / подключённый Spotify: AEDeterminePermissionToAutomateTarget с
  askUserIfNeeded только при notDetermined и явной операции. Проверяет, запрашивает
  и отправляет событие один подписанный native-адаптер. После выдачи права
  продолжается ещё не отправленное действие; сценарий целиком не перезапускается.
  Прямой запуск музыки после утренней сводки включает ту же политику запроса,
  затем восстанавливает её; диагностические команды остаются без запросов.
- Календарь и геолокация: существующий помощник PersonalContext, EventKit и
  Core Location. Запрашивается только используемая часть. Маршрут desktop-календаря
  сохранён; Core Location/CoreWLAN запускаются через LaunchServices. Статусы
  проверяются в соответствующем режиме запуска, а не у соседнего процесса.
  Состояние EventKit write-only не считается разрешением чтения: при первом
  чтении или по кнопке запрашивается полный доступ, затем проверяется заново.
- AX и снимок экрана: публичные AXIsProcessTrustedWithOptions и
  CGRequestScreenCaptureAccess. Для разных исполнителей есть отдельные строки.
  Окончательное включение, а иногда перезапуск, выполняет пользователь в macOS.
- Bluetooth: штатный запрос CoreBluetooth при явном подключении существующим
  BLE-адаптером. Общая проверка не запускает сканирование или подключение.

При известном отказе повторный системный запрос не имитируется: открываются
настройки. Музыка и чтение личных данных могут до минуты ждать подтверждённого
ручного разрешения, затем продолжают только исходный заблокированный шаг.
После тайм-аута пользователь повторяет команду. Отозванное право проверяется
заново; старый успешный результат не служит постоянным разрешением.
Диагностика принудительно отключает автоматические запросы даже внутри команды.

## Ручные настройки и ограничения

Safari требует включить JavaScript из Apple Events, войти в YouTube Music и
разрешить автозапуск звука при необходимости. Это не дополнительные TCC-права.
Воспроизведение считается успешным только после прежних проверок состояния плеера.
Права действий Shortcuts принадлежат самим командам. Автозапуск включается через
существующий SMAppService. Для файлов нет общего права на все пути; доступ
зависит от выбранного файла/папки. Для Local Network нет публичной общей функции
preflight: состояние конкретного соединения проверяется в разделе устройств.
Настроенный API-ключ не доказывает доступ к удалённому сервису.

Apple Speech, камера, контакты, Фото, Reminders, мониторинг ввода, запись системного
аудио и полный доступ к диску не используются соответствующими функциями текущей
сборки. Для них нет фиктивных запросов или проверок. Finder/Music перечислены,
но отдельная активная интеграция Apple Events с ними не объявляется.

AX/Screen Capture не позволяют надёжно различить все состояния отказа публичным
preflight: отрицательный ответ показывается как «Требуется проверка».
Права разных Terminal/Codex/.app и разных исполнителей не объединяются. У сборки
ad hoc подпись, стабильные bundle identifiers и явный Apple Events entitlement
у соответствующих помощников. Сохранение TCC после изменения подписи/версии
не гарантируется. Системные кнопки не нажимаются, TCC.db не читается и не меняется.

## Места

SSID задаётся пользователем в «Места и контекст». Формат строки — `SSID | BSSID`;
BSSID необязателен и помогает различать одноимённые сети. SSID не является
доказательством безопасности сети. Пароли не запрашиваются. Наблюдения текущей
сети сравниваются по хешам и быстро устаревают; история сетей не создаётся.

Приоритет: ручной выбор → подтверждённая Wi-Fi-привязка → свежая геозона/город →
Общий. Старые явные Bluetooth-привязки сохранены как дополнительный резерв после
геолокации. Конфликтующие привязки, отсутствующий SSID и устаревшая геопозиция
не дают угаданного локального профиля. Геозоны задаются как широта, долгота и
радиус в километрах; координаты наблюдений округлены до 0,1°. Минимальный радиус
10 км, учитывается погрешность округления и измерения, граница не выбирает профиль
без достаточной точности. Городские псевдонимы остаются совместимыми.

## Диагностика

Локальный журнал хранит до 200 записей в пользовательской SQLite-базе: состояние,
операцию, безопасную ошибку, PID/PPID, bundle identifier, путь исполнителя и
отпечаток подписи. Координаты, события календаря, SSID, скрипты, ключи и содержимое
файлов в журнал не входят. Пользовательские данные и диагностические экспорты
не включаются в Git или пакет приложения.

Режим установленного исполняемого файла `--permission-status /путь/к/отчёту.json`
проверяет публичные статусы без интерфейса, микрофона, координат, запуска браузера,
воспроизведения или изменения разрешений. Он относится к текущей цепочке запуска;
не заменяет ручную проверку системного диалога из обычного окна приложения.

Автотесты используют моки системных API: отказ/неопределённость, отзыв прав,
продолжение одного действия, изоляция диагностики, сохранение идентичности
календаря, Wi-Fi-конфликты и приоритеты мест. UI-стенд проверяет реальную цепочку
WebSocket → SettingsCenter/Automations → SQLite → интерфейс с моками macOS.
Эти проверки не доказывают живое воспроизведение, качество речи или получение
координат. Реальные права во время тестирования не изменяются.

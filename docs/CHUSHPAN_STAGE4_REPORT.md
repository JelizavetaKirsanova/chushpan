## 1. Модель и провайдеры

Выбрана стабильная **gemini-3.8-flash**. Повторная проверка 30 октября 2026:
официальный каталог моделей (обновлён 28 октября 2026) и карточка модели
подтверждают идентификатор `gemini-3.8-flash` как stable Developer API; вход
изображений, текстовый ответ и function calling есть; thinking `low`/`medium`/`high`
поддерживается, `minimal` — нет. Клиент использует thinking low.
[Каталог](https://ai.google.dev/gemini-api/docs/models),
[карточка](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash).
Запрос `GET /v1beta/models/gemini-3.8-flash` к `generativelanguage.googleapis.com`
без ключа вернул **403 PERMISSION_DENIED** (нужна идентичность API), а не 404:
сам по себе этот ответ не доказывает доступность генерации для проекта.
В первоначальной проверке генерации не было; позже пользовательница сообщила
о 503 от 3.8. Единственная новая генерация к 3.5 успешна, фактическая версия 3.6.
Русский входит в поддерживаемые
языки общих Gemini-моделей.
[Документация Google](https://firebase.google.com/docs/ai-logic/models).

Используется официальный `google-genai 2.34.0`; `Pillow 13.0.0` добавлен для
безопасного декодирования/нормализации изображений. В pyproject/uv.lock отражены
зависимости; существующие установленные пакеты не обновлялись. SDK и обработка
картинок — единственные прямые зависимости этапа.

Общий `LLMClient` используется Conversation, chat, voice, briefing и ресурсным
lifecycle. В `config.yaml` выбран `llm.provider: gemini`, Ollama сохранена в
`llm.host/model/think/temperature/num_ctx/keep_alive` без изменения значений.
`JARVIS_LLM__PROVIDER=ollama` включает прежний локальный режим. Локальные модели
не удалялись/не скачивались. `bench` по назначению остаётся тестом Ollama-моделей.

В Gemini SDK передаются только декларации функций. Automatic function calling
отключён, Vertex/Enterprise отключены, host фиксирован Developer API. Все вызовы
проходят прежние validate → intent → device/session/capability → confirmation → Agent.
Частичный/заблокированный ответ не выпускает действия. Подписанные native parts
сохраняются только внутри текущего запроса, без записи в SQLite.

Gemini возвращает один полный ответ модели после завершения HTTP-запроса; это
буферизация, а не поток токенов Google. Далее общий голосовой путь разбивает текст
на предложения. Ollama сохраняет потоковую генерацию. Облачных warm-up/prime,
автоматических повторов SDK, grounding, Files API и платных встроенных tools нет.

## 2. Ключ, бесплатность и ограничения

В `.env.example` есть пустой `GEMINI_API_KEY`. В начале этапа ключ отсутствовал;
позже пользовательница добавила рабочий ключ и включила флаг Free tier в своём
`.env`. Агент файл не редактировал. Для новой установки нужно **добавить** строки
в существующий файл, сохранив прежние значения:

```dotenv
GEMINI_API_KEY=значение_своего_ключа
JARVIS_LLM__PROVIDER=gemini
JARVIS_GEMINI__FREE_TIER_CONFIRMED=true
```

Ключ создаётся в [AI Studio](https://aistudio.google.com/api-keys). Сначала проверить
допустимость проекта/региона и Free tier, отсутствие активного Billing; затем включать
флаг и перезапускать ассистента. Не вставлять ключ в чат/код/документы и не копировать
пример поверх `.env`. Для файла с ключом нужны приватные права доступа; существующие
права пользовательского `.env` в этом этапе не менялись. Ключ не является полем
Settings, не включается в config/prompt и передаётся только SDK.

На дату проверки таблица Google указывает бесплатные input/output для 3.8 Flash.
[Цены](https://ai.google.dev/gemini-api/docs/pricing). Численные RPM/TPM/RPD определяются
проектом и моделью в AI Studio; общего гарантированного лимита документация не даёт.
Квоты действуют на проект, суточные сбрасываются по Pacific time; превышение даёт 429.
[Лимиты](https://ai.google.dev/gemini-api/docs/rate-limits). Квота этого проекта неизвестна.

Есть существенное региональное условие: Google указывает Paid Services при
предоставлении API-клиентов пользователям ЕЭЗ/Швейцарии/Великобритании. Для ЕЭЗ также
отдельно описана обработка данных бесплатных запросов. Доступность бесплатного
использования именно этого проекта требует проверки применимости условий;
наличие ключа и общей строки Free tier её не доказывает.
[Условия Google](https://ai.google.dev/gemini-api/terms).

Флаг `free_tier_confirmed` — ручная проверка, а не запрос Billing API или жёсткий
денежный лимит. Приложение не подключает Billing, не повышает тариф и не выбирает
платные модели автоматически; при изменении Billing снаружи оно не может определить
это по ключу. **Выполнена одна реальная генерация Google API** — короткий запрос
к 3.5, без личного контекста. Платные сервисы не включались.

## 3. Fallback

Без ключа/проверки тарифа выводится инструкция настройки. При разрешённом fallback
запрос передаётся установленной Ollama по loopback. Реальный ответ Qwen получен во
всех семи текстовых сценариях и двух итоговых image-сценариях; источник отмечен ollama.

При настроенном ключе цепочка — 3.8 Flash → 3.5 Flash → Ollama. Переключение только
при 429/500/502/503/504 и сетевых тайм-аутах/сбоях соединения; 400/401/403/404 и другие
невременные ошибки остаются явными и останавливают запрос. По одной попытке модели,
SDK retries отключены, deadline 15 с на облачную попытку. Запрошенная и фактическая
модели логируются без содержимого/ключа. Выдавшая tool call модель закрепляется
за текущим серверным request ID, чтобы сохранить подписанный ответ функции.

Пустой, ошибочный или обрезанный ответ не считается успехом и не вызывает повтор.
Добавлен явный отказ при Ollama done_reason=length. Ошибки API обрабатываются
без текста SDK-исключения, которое могло бы раскрыть данные запроса.
После уже полученного результата инструмента текущая цепочка через другого
провайдера автоматически не повторяется: так предотвращается повтор действия.
Это может прервать многошаговый запрос с явной ошибкой; выполненную часть надо проверить.
Повторная проверка кода и тестов: без ключа/флага Gemini не вызывается; при
`fallback: true` идёт loopback-Ollama; внешний host для резерва отклоняется;
пустой/обрезанный локальный ответ и отказ после tool-result не считаются успехом;
`JARVIS_LLM__PROVIDER=ollama` остаётся явным локальным режимом.

## 4. Зрение

Новые инструменты `analyze_screen`/`analyze_image` зарегистрированы в system-группе
и привязаны к Mac Agent/capabilities. `analyze_screen` переиспользует существующий
MacDesktop.screenshot и его проверку Screen Recording; затем читает и удаляет
**только новый собственный screenshot** в finally, включая ошибку анализа.
Существующий `take_screenshot` остаётся отдельным локальным сохранением без анализа.

`screen_requested` больше не принимает «посмотри на код/ошибку», «почему этот код
не работает», «объясни, что здесь написано» и «что мне нажать» как захват экрана.
Нужны глагол просьбы и слово «экран» в текущей команде. Вставленный фрагмент кода
и цитата «посмотри на экран» внутри другого предложения не открывают снимок.
Такой вопрос идёт обычным текстовым диалогом и не требует vision-инструмента.

`analyze_image` принимает явно названный файл в разрешённом root, без URL/переходов
наверх/скрытых путей/выхода из root. PNG/JPEG/WebP: до 8 МиБ, 16 миллионов пикселей,
один кадр; проверяется реальное декодирование, удаляются EXIF/метаданные. Полностью
прозрачные пиксели не раскрываются — изображение сводится на белый фон. Исходный
выбранный файл не меняется и не удаляется.

В Gemini-профиле требуется свежий код перед захватом/передачей. Версия содержимого
файла входит во внутренний fingerprint, повторная проверка блокирует подмену до
отправки; хеш не читается вслух. Снимок создаётся в момент подтверждения, что явно
указано в описании действия. Пиксели с паролями/перепиской нужно скрыть заранее:
автоматического надёжного скрытия секретных областей нет.

Gemini получает inline image; отдельной загрузки через Files API нет. Ollama
сначала проверяет установленную модель и capability vision. На этом Mac настроенная
Qwen подтверждает vision; тяжёлые модели автоматически не устанавливаются.
Изображения не записываются в facts/messages/preferences. Локальное удаление
временного файла не означает удаление всех данных на стороне облачного провайдера.

Vision-запрос не получает tools; попытка function call отклоняется. Ответ анализа
выдаётся напрямую, без нового модельного цикла действий. Текст картинки недоверенный,
не разрешает forget, shell или управление Mac. Модель должна обозначать обрезанный
код/нечёткий текст, но фактическая точность ответов не гарантирована.

`ImageInput(bytes, mime_type, source)` подготавливает будущие iPhone/iPad-вложения.
Авторизованного upload endpoint пока нет: source и grants должен выдавать будущий
сервер, а не присланное поле JSON.

Прежние проверки forget, аргументов, истечения/replay/device/session сохранены.

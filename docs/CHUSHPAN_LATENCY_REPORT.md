## Изменения

- backend/latency.py: изолированный Profile через ContextVar, числовые этапы,
  результат этапа, без запросов/ответов/ключей. Асинхронные дочерние задачи
  используют один профиль обращения.
- backend/voice.py и audio/vad.py: wake inference, VAD-пауза, STT, время до
  первого основного звука, публикация stats при начале звука и после ответа.
  Конец речи оценивается по последнему речевому кадру VAD, с вычитанием
  накопленной тишины. Для Whisper wake-word метрика wake_detection — время
  проверки фразы; для ONNX — время успешного вызова детектора, не время от
  произнесения первого слога имени. Эти величины различны и не подменяются.
- backend/brain/conversation.py: контекст/память, первая порция и весь запрос
  модели; из SQLite сразу выбирается облачный лимит 8 сообщений вместо
  чтения 30 с последующим отбрасыванием. Личность и правила памяти сохранены.
- backend/brain/providers.py: каждая попытка и fallback, общий облачный бюджет,
  cooldown после transient-сбоев. SDK делает одну попытку; скрытых повторов нет.
  401/403/404 не маскируются автоматическим переключением. После частичного
  текста или результата инструмента повтор действия через другую модель запрещён.
- backend/local_commands.py и tools/clock.py: точные команды времени, чтения
  громкости/яркости и числовой установки уровня идут прямо в реестр инструментов.
  Сохранены intent-проверки, capabilities, подтверждения, история и наблюдение
  привычек. Неточные, составные и произвольные формулировки не угадываются.
  Ночной режим, Shortcuts, сон и существующие прочие локальные маршруты не дублируются.
- backend/tools/registry.py: отдельное время исполнения инструмента.
- backend/audio/tts.py: генерация, готовность загруженного голоса и очередь
  воспроизведения. on_start перенесён к первому блоку вывода после подготовки
  аудио, а не к извлечению предложения из очереди до resample.
- frontend: отдельные числа STT, TTS, полный отклик, этапы/попытки. «Модель»
  показывает «локально» при обходе LLM и «ошибка» при неудачном запросе,
  а не необъяснимое отсутствие первого текстового токена. Нулевые значения
  не отбрасываются через логическое and.

Суммы этапов не нужно складывать: некоторые вложены или перекрываются.
Полный отклик вычисляется отдельно от окончания речевого кадра до callback
первого основного аудиоблока. Это программный замер, не акустическое измерение
динамика. Аппаратная буферизация/задержка устройства остаётся за его пределами.
Фразы ожидания не выдаются за начало основного ответа.

## Поток и безопасность

Существующая озвучка по предложениям сохранена. Gemini SDK теперь поддерживает
чистый текстовый поток при tools=[]; в обычной беседе он выбран только для
точных «привет», «как дела», «как ты», «расскажи шутку». Инструментов в нём нет.
При обрыве после начала текста нет автоматического fallback с повтором ответа.
Вызовы инструментов по-прежнему буферизуются до полного проверенного ответа.
Здоровый live-стрим сейчас не подтверждён из-за ошибок сервиса; совместимость
потока и ранняя выдача проверены на SDK-моках. Модель и thinking low не менялись.

Whisper использует закешированный путь и MLX ModelHolder; Silero сохраняет
_voice и аудиокеш. При существующем Whisper wake-word Resources сохраняет
STT загруженным. Повторной загрузки на каждое обращение код не требует.
Микрофон, сеть и TTS используют асинхронные задачи/worker; HUD публикует
события в ограниченные очереди без ожидания браузера. Таймауты и finally
голосового цикла сохранены.

SDK streaming: https://googleapis.github.io/python-genai/ .

## Безопасная диагностика

```bash
cd ~/my-jarvis
uv run python -m backend latency-check --label before
uv run python -m backend latency-check --tts --label after
uv run python -m backend latency-check --live --label after
uv run python -m backend latency-check --live --stream --label after
```

Без --live нет API-запросов; без --tts нет синтеза. Никогда нет записи микрофона,
проигрывания звука, настоящих системных команд или открытия рабочей памяти:
временная SQLite только в RAM. --live отправляет один фиксированный нейтральный
вопрос на итерацию и использует существующие ограничения/резерв. --runs 1–5;
для каждого прогона создаётся новый SDK-клиент, поэтому это не замер прогретого
TCP-соединения обычного приложения. --label — метка результата, не откат кода.
Вывод можно перенаправить в собственный файл для сравнения версий.

Для полной голосовой трассы перезапустить обычный экземпляр Чушпана и смотреть
панель задержек и VOICE_TIMINGS / LLM_TIMING. Новые логи содержат только времена,
номера попыток и безопасные идентификаторы моделей, без текста речи и ключей.
Живую запись в этом проходе не делали. Commit/push нет.

# RGB-подтверждения и пользовательская палитра

## Причина блокировки

В версии `1e81063` положительный ответ на тест цвета добавлял в
`LEDState.confirmed` только `color:R,G,B`. Общий допуск `rgb` появлялся лишь после
трёх отдельных тестов основных цветов. `Devices.features()` требовал `rgb` для
произвольного цвета, а UI блокировал остальные пресеты. Успешная запись сама
никаких допусков не добавляла — это правило сохранено.

Дополнительно при аудите установленного приложения обнаружена сборка из
`4c0601b`, предшествующая новым драйверам. Личный журнал той сборки содержал
незавершённый тест цвета, без записанного физического подтверждения и без
отпечатка драйвера/GATT. Такой журнал нельзя объявлять подтверждением нового
драйвера ELK-BLEDDM. Личные данные в этот документ и Git не скопированы.

## Исправленная процедура

После одной тестовой RGB-команды пользователь явно подтверждает, что выбранная
лента показала ожидаемый цвет. `confirm_probe()` добавляет точный цвет и `rgb`.
Это разрешение использовать тот же RGB-сериализатор для этой ленты, а не
доказательство точности каждого оттенка. Питание и яркость остаются отдельными
функциями; ACK/окончание BLE-записи не подтверждают физическое выполнение.

Подтверждения и незавершённая проверка сохраняются в прежнем личном LED-журнале.
После перезапуска карточка восстанавливает вопрос о наблюдении из этого журнала,
без новой отправки. Проверка принимается только для текущего id теста выбранного
устройства, с локальным Mac Agent, разрешениями и проверкой местоположения.

Изменение адреса/прошивки/структуры GATT либо несовместимого драйвера сбрасывает
допуски. Отпечаток драйвера учитывает GATT, режим записи и шаблоны команд;
изменение названия или ссылки на источник при тех же командах их не сбрасывает.
Отпечаток прежнего формата распознаётся только для идентичного профиля.
Старые записи физического подтверждения RGB можно восстановить только при
совпадении профиля и точного подтверждённого цвета. Предустановленный legacy-red
не превращается в общий RGB-допуск. Между ELK-BLEDOB и ELK-BLEDDM допуски не переносятся.

## Редактор и библиотека

В каждой RGB-карточке есть R/G/B 0–255 с ползунками и числовыми полями, HEX,
системный picker и большой образец. Пустой/неверный ввод не зажимается молча:
он показывает ошибку и блокирует применение/сохранение до исправления.
Стандартные, любимые и пользовательские цвета выбираются для предпросмотра.
**Управляющая запись выполняется только по кнопке «Применить»**, с проверкой
допуска выбранной ленты. Недоступный пресет показывает причину и процедуру
«Проверить RGB». Повторный клик во время отправки не ставит RGB-запись в очередь.

Предпросмотр сохраняется отдельно для каждой ленты через локальную операцию
`color_preview`; эта операция никогда не подключается к BLE. Предпросмотр также
работает при отсутствии связи с backend, но до восстановления связи не сохраняется.
Он не становится фактическим состоянием устройства. Лента продолжает иметь
раздельные журналы отправленных и подтверждённых данных. После неопределённого
результата нет автоматического повтора записи.

Именованные цвета хранятся в личной SQLite-базе (`user_colors`), независимо от
подключения BLE. ID, название, RGB, вычисленный HEX, избранность, даты создания/
изменения и ревизия сохраняются после перезапуска. Изменения защищены от
перезаписи устаревшей ревизией, названия уникальны без учёта регистра.
Удаление требует отдельного подтверждения. Есть сортировка по избранности,
названию и последнему изменению. Выбор существующего цвета заполняет редактор;
«Сохранить изменения» позволяет переименовать и изменить каналы.

Новые голосовые команды проходят через существующие `voice_plan()` /
`device_command`, выбирают устройство и используют его драйвер:

- «Чушпан, сделай ленту RGB 180 80 255»;
- «Установи красный 255, зелёный 100, синий 50»;
- «Поставь мой цвет Ночной фиолетовый»;
- «Сохрани этот цвет как Лавандовый»;
- «Сделай ленту в общаге розовой» — при назначенном месте и текущей локации.

«Этот цвет» берётся из предпросмотра выбранной ленты, затем последнего отправленного
или прочитанного цвета. Сохранение в библиотеку не посылает управляющих команд.
При нескольких лентах требуется имя, однозначное место или действующий выбор.

## Файлы

- `backend/led.py`, `backend/ble_profiles.py`: допуск RGB, совместимость отпечатков,
  восстановление проверки, сохранение прежней защиты от повторной записи.
- `backend/devices/colors.py`: приватная постоянная библиотека и RGB/HEX-валидация.
- `backend/devices/center.py`, `backend/devices/service.py`: библиотечные операции,
  snapshot, причины блокировки, локальная голосовая маршрутизация.
- `frontend/src/color_editor.ts`, `frontend/src/devices.ts`,
  `frontend/src/devices.css`: панель и палитра в существующей фиолетовой стилистике;
  расширенные BLE-данные в закрытом раскрывающемся разделе.
- `tests/test_color_library.py`, `tests/test_led.py`,
  `frontend/tests/color_editor.test.ts`, `frontend/tests/devices.test.ts`: проверки.

Часть начальных backend-изменений была сохранена общим параллельным коммитом
`12029b0`. Его история не переписывалась. Завершающий коммит этой задачи включает
только файлы RGB/устройств, тесты и документацию. Непосредственно главная страница
с котом и другие разделы приложения не изменялись.

## Проверка и границы

Автоматические проверки используют mock BLE, временную SQLite и тестовые имена.
Проверяются один физически подтверждённый цвет → RGB, отдельные блокировки
питания/яркости, сохранение после перезапуска, отрицательное/устаревшее
подтверждение, разные ленты, смена профиля/GATT, ошибки и отсутствие автоповтора.
Редактор проверяется на границах 0/255, некорректном вводе, RGB ↔ HEX, библиотечном
CRUD, сортировке, избранности и отсутствии управляющих событий при предпросмотре.

Нативная визуальная проверка выполнена в том же Cocoa WebView, который использует
Чушпан, с вымышленной карточкой: HEX `#FF6432` синхронизировал 255/100/50;
ввод 256 заблокировал «Применить»; выбор пользовательского фиолетового восстановил
RGB и поля редактирования. Палитра проверена визуально, BLE-диагностика закрыта
по умолчанию. Тестовый WebView не подключался к оборудованию и личной базе.

Реальные BLE-команды в этой задаче не отправлялись. Сообщение пользователя о
видимой реакции теста учтено как контекст, а не как автоматический допуск для
другого драйвера. После запуска новой сборки требуется одна явная проверка RGB
для текущего драйвера, если соответствующее подтверждение ещё не сохранено.
Включение/выключение, яркость, цветопередача и повторный запуск на настоящих двух
лентах остаются предметом физического тестирования с разрешением пользователя.

Проверенный комплект собирается отдельно от незавершённой параллельной задачи
памяти. В общей рабочей копии полный прогон зафиксировал 13 ошибок тестов памяти/
подтверждений на её промежуточной версии; эти файлы не менялись в RGB-задаче.
Изолированный прогон включает весь набор тестов без исключения файлов.
Установленный `/Applications/Чушпан.app` автоматически не заменяется: готовая
сборка выдаётся отдельно, чтобы не запускать личный профиль/оборудование при проверке.

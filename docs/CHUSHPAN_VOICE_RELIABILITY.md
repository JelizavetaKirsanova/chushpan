# Голосовая активность и задержки — 2 ноября 2026

Изменения внесены в существующий конвейер. Основное приложение оставлено
остановленным. По просьбе пользовательницы выполнены только проверки **без
микрофона**. Записей её голоса не создавалось. В замерах воспроизводился звук
синтезированных нейтральных ответов; отдельный стенд интерфейса работал без
аудиовхода, аудиовыхода, LLM и инструментов устройств и затем был остановлен.

## Фактическая архитектура и причины

Вход macOS преобразуется в mono PCM16 16 kHz. Опциональный WebRTC обрабатывает
эхо и шум, затем Silero VAD собирает реплику. Для русской фразы «эй чушпан»
активацию проверяет **локальный Whisper**, а не предобученный английский ONNX.
Транскрипция обращения с вопросом повторно не декодируется. После проверки
адресата идут детерминированные маршруты, затем при необходимости Conversation
с Gemini/Ollama и реестром инструментов. TTS синтезирует следующие предложения
параллельно воспроизведению предыдущих; владельцем аудиовыхода служит одна задача.

Найдены конкретные причины:

- `config.yaml` показывал безопасные значения, но эффективные настройки из
  `.env` переопределяли их: `JARVIS_WAKEWORD__ENABLED=false` и
  `JARVIS_AUDIO__BARGE_IN=true`. Приложение слушало постоянно и обходило проверку
  обращения. На сохранённой нейтральной фоновой фразе это воспроизвелось как
  один принятый запрос и ответ без имени.
- `VoiceLoop._check_wake_phrase()` не проверял нативные метрики уверенности
  Whisper; `addressee.decide()` принимал имя до проверки уверенности.
  В ветке ONNX не учитывался период защиты после озвучки.
- Окончание реплики ожидало фактически 0,992 с тишины. STT занимал около
  0,5–0,6 с, поэтому даже локальная команда начиналась позже желаемой секунды.
- Переход Gemini → Ollama после HTTP 429 добавлял обработку большого контекста.
  В исходном replay: 3474 токена, 10,20 с prefill. Это происходило даже с
  `thinking=false`: выключение reasoning само по себе эту задержку не устраняет.
- Некоторые простые формулировки с запятой перед «ответь одним предложением»
  не попадали в быстрый маршрут. Приветствие первого хода и вводное «Конечно.»
  могли звучать раньше полезного ответа. Служебная фраза ожидания занимала
  метки первого смыслового фрагмента. Длинная пауза после неё не выделялась.
- Продление диалога не имело абсолютного предела. Обычные уточняющие вопросы
  распознавались слишком узко, а «Пока, Чушпан» попадало под запрет упоминания
  имени. Голосовая остановка могла отменить ответ и запустить ещё один ответ.

## Реализованное поведение

В `.env` изменены два несекретных флага: активация включена, общее перебивание
выключено. `.env.example` соответствует этому режиму. Пользовательский характер,
файл личности, голос, история и разрешения инструментов сохранены.

- Отдельная стадия активации проверяет начало реплики, речевые признаки и
  настоящие `avg_logprob`, `no_speech_prob`, `compression_ratio` Whisper.
  Нет метрик — нет автоматической активации. Чувствительность изменяет реальные
  пороги; ONNX-порог применяется только в режиме ONNX. Числа не выдаются за
  вероятность обращения или идентичность говорящего.
- Есть ограничение частоты проверок и cooldown повторных активаций; VAD сам
  не разрешает ответ. Текст собственного недавнего TTS и акустический хвост
  защищены независимо от VAD.
- По умолчанию окно продолжения — 25 с, абсолютный предел сессии — 180 с.
  Только принятая реплика продлевает окно. Дополнительный вопрос вроде
  «А почему небо голубое?» проходит без имени в активном окне. «Пока, Чушпан»
  закрывает его. Режим «Только по имени» отключает продолжение после ответа.
- Перебивание требует распознанного обращения, нативной уверенности и защиты
  от эха. В консервативном режиме проверяется только явная остановка.
  «Чушпан, стоп» останавливает молча; ручная кнопка отменяет текущую задачу
  даже в старом режиме постоянного прослушивания. Безымянное перебивание
  сохраняет прежние дополнительные ограничения гарнитуры/AEC.
- WebRTC действительно переключает локальное шумоподавление. Настройки
  сохраняются в SQLite (`voice/controls`) и загружаются при запуске.
  Ошибка сохранения откатывает изменение нативного обработчика. Статус
  микрофона меняется только после фактического запуска/остановки входа.
- VAD ждёт 650 мс, фактически 0,640 с на сетке кадров. Preroll/tail и минимум
  короткой реплики сохранены; пауза 384 мс внутри предложения проверена тестом.
- Простые запросы используют короткий системный контекст с **полной прежней
  личностью** и релевантными фактами, без инструкций недоступных инструментов.
  Сложные задачи сохраняют полный контекст, инструменты и reasoning.
  `llm.think_for_simple` позволяет вернуть reasoning для простых вопросов.
- Информационный поток Gemini озвучивается по предложениям, в том числе при
  доступных инструментах. Незавершённые function calls не выполняются.
  Сообщения об успехе действий остаются за проверяемым результатом инструмента.
  После начала текста действует отдельный тайм-аут бездействия потока;
  частичный ответ не повторяется на другом провайдере.
- Для простых вопросов нет служебной озвучки ожидания. Вводное предложение
  соединяется с первым смысловым, без удаления его слов. Длительные действия
  сохраняют уведомление начала, которое не считается подтверждением выполнения.

Трассы SQLite содержат VAD start/end, ожидание конца речи, wake/STT, маршрутизацию,
модель и её первый токен, thinking, инструменты, синтез и вывод аудио. Начало VAD
может иметь отрицательный сдвиг относительно конца реплики — нулевой точки
показателя задержки. В статистике раздельны первый звук, содержательная речь,
полное время, пауза после ожидания и паузы между фрагментами. Проверки активации
сохраняются отдельно и не улучшают среднюю задержку ответов нулевыми значениями.
Диагностические метаданные проходят белый список; сырое аудио туда не входит.

## Реальные замеры

До правок сохранены исходники и эффективные аудионастройки, затем выполнен
replay на замороженной версии. Сравнение использует одинаковые синтезированные
фразы и настоящие Silero VAD, Whisper, провайдеры, Silero TTS и аудиовыход.
Начало отсчёта — последний речевой кадр VAD, конец — успешная запись первого
содержательного аудиоблока. Это **не измерение живой речи или акустического
выхода динамика**. По одному образцу на сценарий в каждом полном прогоне;
результаты не являются оценкой p95 живого использования.

Последний полный прогон, до → после:

- Локальная команда, маршрут Gemini: **1,702 → 1,353 с**.
- Простой вопрос, маршрут Gemini с фактическим резервом Ollama после 429:
  **12,990 → 5,392 с**.
- Обычный диалог, маршрут Gemini с фактическим ответом Ollama:
  **2,126 → 1,704 с**.
- Локальная команда, выбранная Ollama: **1,640 → 1,218 с**.
- Простой вопрос, выбранная Ollama: **3,276 → 3,360 с** — улучшения в этом
  последнем образце нет. Первый текст модели пришёл раньше, но осмысленный
  аудиофрагмент получился длиннее.
- Обычный диалог, выбранная Ollama: **2,124 → 1,629 с**.

Промежуточные прогоны после изменений дали 9,04 и 10,15 с для холодного
облачного резерва и 1,81 и 2,35 с для простого вопроса Ollama. Диапазон важнее
единственного лучшего числа: кэш модели, длина предложения и доступность
Gemini влияют на результат. Контекст простого запроса уменьшился с 3474 до
1984 токенов; prefill последнего облачного резерва занял 3,26 с. Цель менее
секунды для локальной команды пока не достигнута: VAD + STT занимают ~1,15 с.

Отдельный локальный A/B на одном нейтральном вопросе с предварительной
обработкой одинакового системного префикса: первый содержательный текст
Ollama **4,615 с с thinking → 0,569 с без thinking**, полный ответ
**6,326 → 2,081 с**. Одна пара, без микрофона и озвучки; не экстраполируется
на сложные задачи. Нативный интервал thinking составил 4,08 с.

Исходные JSON и сравнение: [diagnostics/voice-v2](diagnostics/voice-v2).
`after-vad-with-waiting.json` сохраняет промежуточный прогон, где панель
обнаруживает 5 с тишины после заглушки. `after-vad.json` — итоговый прогон,
в котором у простых вопросов заглушек уже нет.

## Проверки и воспроизведение

Итог: **1495 Python-тестов за 31,63 с**, **20 frontend-тестов**, Ruff,
форматирование 168 Python-файлов, TypeScript/Vite и `git diff --check` прошли.
Один существующий тест потокового тайм-аута был нестабилен при бюджете 35 мс;
масштаб времени увеличен с сохранением условия «длительность потока больше
исходного бюджета». Отдельный тест проверяет зависание после первого текста.

Покрыты ложная активация, уверенность, cooldown, собственное эхо, окончание
сессии, естественное уточнение, остановка, сохранение/ошибка настроек,
реальное нативное шумоподавление, потоковые вызовы инструментов, отсутствие
LLM у локальных команд, fallback, прежние BLE/музыка/память/сценарии и безопасность.

Реальный Whisper + Silero VAD проверены на синтезированной фоновой речи,
обращении с командой, тишине, шуме, а также двух настоящих CC0-записях
[кашля и щелчка из ESC-50](../tests/fixtures/audio/README.md).
Фоновая речь: **1 принятый запрос до → 0 после**; обращение: **1 → 1**.
Кашель/щелчок/тишина/шум не вызвали ответа в обоих прогонах. Их ложное
срабатывание на исходной версии в этих образцах не воспроизвелось.

```sh
.venv/bin/python -m backend voice-check
.venv/bin/python -m backend voice-check --decode
.venv/bin/pytest -q
.venv/bin/ruff check backend tests
.venv/bin/ruff format --check backend tests
npm --prefix frontend test
npm --prefix frontend run build
```

`voice-check` без флагов не загружает модели. `--decode` запускает настоящие
локальные VAD/Whisper, синтезирует тестовые фразы в RAM и подаёт их в VoiceLoop
с заглушками ответа/выхода. Микрофона, реального LLM и вызовов устройств там нет.
Отчёт без транскрипций: `data/diagnostics/voice-check.json`.

Полный замер с **явно разрешённым звуком**, без микрофона:

```sh
.venv/bin/python -m backend latency-check --pipeline --with-vad --live --play-audio --runs 1 --label sample
```

В изолированном интерфейсе проверены применение порогов, обоих режимов,
таймера, переключение WebRTC, сохранение после обновления страницы, честный
статус остановленного микрофона и подробная трасса реального replay.
Снимки: [настройки](diagnostics/voice-v2/voice-settings.png),
[диагностика паузы](diagnostics/voice-v2/performance.png).

## Ограничения

Живой микрофон, реальная комната, телевизор, голос пользовательницы и физический
звук динамика не проверялись — это её явное ограничение. Синтезированная фоновая
речь не заменяет запись телевизора. Телевизор, произносящий точное обращение,
может активировать ассистента: идентификации говорящего здесь нет.
Длительные паузы человека больше 650 мс могут завершить реплику; параметр
`vad.silence_ms` остаётся настраиваемым. Акустическое эхо зависит от комнаты;
его проверка здесь — нативный обработчик с воспроизводимой моделью эха.

Gemini в сравнимом прогоне вернул 429, поэтому здоровый облачный путь 1–3 с
этим прогоном не подтверждён. Холодный резерв и вытеснение кэша всё ещё могут
давать длительную задержку. Измерения и панель показывают её, не объявляя
вводную фразу успешным содержательным ответом. Реальные BLE, музыка, календарь,
Shortcut и sleep/wake Mac в этой задаче не запускались; регрессии проверены моками.

# Обнаружение ELK BLE и подключение нескольких лент

## Причина

В `LEDStrip.discover` использовались два последовательных ограничения:
`service_uuids=[FFF0]` на уровне сканирования и точное сравнение имени с
`settings.led.name` (по умолчанию ELK-BLEDOB). ELK-BLEDDM 39 не проходила сравнение
имени. Контроллеры, не рекламирующие FFF0, отбрасывались ещё до этого сравнения.
Центр устройств дополнительно оставлял только имя и скрывал RSSI и сведения о профиле.

Сканирование теперь асинхронное, ограничено тайм-аутом и отменяется вместе с запросом.
Одновременные запросы поиска используют общую блокировку сканера. Список включает
все обнаруженные BLE-устройства. Семейство ELK-BLE и реклама FFF0 — только признаки
кандидата. Ограничение первых 30 результатов для BLE снято. Нет привязки к конкретному
UUID новой ленты и нет подключения или управляющих пакетов при поиске.

Bleak документирует, что фильтр сервисов оставляет только объявления с этим сервисом;
в macOS идентификатором устройства служит UUID, относящийся к конкретному Mac:
[сканер](https://bleak.readthedocs.io/en/stable/api/scanner.html),
[CoreBluetooth](https://bleak.readthedocs.io/en/stable/backends/macos.html).

## Подключение через интерфейс

Перед проверкой убедись, что запущена обновлённая `/Applications/Чушпан.app`, а не
старая копия из `dist/`. Сам по себе push в Git не обновляет установленное приложение.
Сборка 0.3.3 (16) включает `build-info.json` с исходным коммитом, временем сборки,
признаком наличия ba705ed и SHA-256 основных файлов.

1. В обновлённом приложении открой «Устройства» и нажми «Найти устройства».
   Дождись завершения индикатора. При необходимости нажми «Повторить поиск».
2. Найди ELK-BLEDDM 39. В строке показаны имя, сигнал в dBm, Bluetooth LE и
   предварительный результат определения совместимости. Неизвестные устройства
   находятся в отдельной группе и не объявляются поддерживаемыми.
3. Нажми «Подключить». Выполняется только проверка соединения и перечисление GATT.
   `gatt_match` означает совпадение выбранных service/write UUID и режима записи,
   `gatt_mismatch` — несоответствие профилю, `unsupported` — отсутствие драйвера.
   Наличие notify не является условием записи. Ни один результат не доказывает протокол.
   Соединение после проверки закрывается. При ошибке видна причина и доступен повтор.
4. Нажми «Далее», задай имя, «Дом» или «Общага» и комнату. Можно назвать ленту
   «Новая лента», чтобы использовать команду «Включи новую ленту».
5. Сохрани устройство. Автопроверка без управляющих команд включается по умолчанию
   после успешной проверки подключения; флажок можно снять перед сохранением или
   изменить в настройках устройства. Она выполняется один раз за соединение
   интерфейса с backend для каждого доступного устройства, последовательно и
   с проверкой местоположения. После ошибки доступна ручная кнопка переподключения.
6. Сначала нажми «Диагностика» в карточке. Для проверки протокола открой
   «Проверить управление». Раскрытие панели ничего
   не отправляет. Каждый «Тест» отдельно требует согласия и отправляет один пакет
   выбранного драйвера. Для ELK-BLEDDM используется отдельный кандидат;
   см. [BLE_DDM_AUDIT.md](BLE_DDM_AUDIT.md). Только наблюдаемый результат и ответ «Да, вижу результат»
   разрешают функцию. Для RGB достаточно одного явно подтверждённого теста цвета; отдельно —
   включение, выключение и яркость. Не запускай эти тесты до готовности проверять
   физическую ленту.

Обычная панель использует эти допуски: питание, палитру, RGB и яркость. Тёплый белый
остаётся RGB-приближением (255, 48, 32); отдельный белый канал и цветовая температура
не подтверждены. Команды для отдельного белого канала не добавлены.

## Хранение, голос и восстановление

Используется существующая приватная SQLite `device_registry`, без новой базы или
переноса личных данных в Git. Добавлено необязательное поле `ble_name`, совместимое
со старыми записями. Рекламируемое имя сохраняется отдельно от пользовательского;
неизвестная прошивка новой ленты не выдаётся за прошивку исходной ELK-BLEDOB.
Новая лента не наследует подтверждения команд старой. Журналы и допуски каждой
ленты разделены по стабильному ID и UUID; перезапуск их не удаляет.

Каждая команда подключается к выбранному UUID. Сохранён существующий предел двух
попыток подключения до записи. После начала записи повтор запрещён: потерянный ответ
не доказывает, что лента не выполнила команду. Одновременно зарегистрировано может
быть несколько лент; команды проходят через существующие блокировки и выполняются
независимо по цели, без рассылки на похожие имена.

Голос использует существующие `voice_plan`, `device_command` и защищённый реестр:

- «Включи новую ленту» — для имени «Новая лента» или такого голосового синонима.
- «Сделай ленту фиолетовой» и «Сделай тёплый белый свет» — для единственной подходящей
  ленты текущего места. Если их несколько, требуется название.
- «Установи яркость 50 процентов» — тот же выбор ленты; явная «яркость экрана Mac»
  сохраняет управление экраном. Короткая форма с `%` сохраняет прежний разбор.
- «Выключи все ленты дома» — выбирает ленты профиля «Дом», исключая общие и общажные.
  Существующая защита местоположения проверяется при исполнении: удалённый канал
  управления другим профилем не создаётся.

## Автоматическая проверка и границы

При неполном списке включи «Показать все BLE-устройства без фильтров» и запусти
новый поиск. Этот режим отключает даже определение семейства: все BLE-устройства
показываются без обещания совместимости. У поиска есть уникальный ID, время
окончания и счётчики сканера, backend и исключений. В «Сборка и диагностика поиска»
видны фактический executable, Python, Bleak, backend CoreBluetooth и статус TCC.
Фильтры списка зарегистрированных устройств (локация, текст, категория, соединение)
к результатам поиска не применяются. Перед повторным поиском старые строки очищаются;
запоздалый ответ другого запроса не принимается.

Локальный `data/logs/engine.log` содержит JSON-записи `BLE_DISCOVERY` с одним `scan_id`:
`ws_received`, `backend_requested`, `scanner_start`, `scanner_complete`,
`scanner_device`, `backend_device`, `backend_token`, `backend_candidates`,
`backend_publish`, `ws_send`, `frontend_received`, `frontend_rendered`.
Пропущенный устаревший ответ отмечается `frontend_ignored`, отмена —
`scanner_cancelled`. У каждой строки есть результат включения или причина исключения;
некорректный macOS UUID исключается отдельно, не прерывая весь список. В журнале
UUID заменён коротким хешем. Эти журналы и результаты живых проверок остаются
в приватных данных; не следует добавлять их в Git.

Для сравнения интерпретаторов можно запустить установленный executable с
`--ble-runtime /private/tmp/chushpan-ble-runtime.json`: режим только читает версию,
сборку и разрешения, не сканирует. Флаг `--no-auto-listen` при обычном запуске
подавляет автоматическое включение микрофона только для этой сессии, сохраняя
пользовательские настройки. Он нужен для диагностики BLE из настоящего приложения.

Все BLE-тесты используют подставной транспорт; реальный Bluetooth, микрофон и лента
не запускаются. Проверяются семейства имён, отсутствие рекламы FFF0, неизвестные
устройства, RSSI, GATT и свойства характеристики, ошибки и повтор, отмена,
неблокирующий поиск, сохранение UUID/места/автопроверки, отдельные профили лент,
запрет наследования допусков, независимая адресация и голос.
Frontend-тесты проверяют индикатор, группы, явное подключение, ошибки, устаревшие
ответы, автопроверки без команд, палитру и отдельное согласие на тест управления.
Визуальная проверка проводится на изолированном UI с вымышленными UUID и без backend.

Проверка 6 ноября 2026 года: 181 профильный Python-тест и все 149 frontend-тестов
прошли, `npm run build`, Ruff и проверка форматирования изменённых Python-файлов
прошли. В общем Python-прогоне прошли 2489 тестов; один desktop-тест создания
Unix-сокета получил `PermissionError` песочницы и затем прошёл отдельно с разрешённым
локальным сокетом. После этого дополнительно добавлены и пройдены проверки отмены,
нативной ошибки конструктора клиента и голосового контекста.

На физической ELK-BLEDDM 39 остаются непроверенными: обнаружение из подписанной
`.app` с её macOS-разрешениями, подключение/отключение, формат питания/RGB/яркости,
видимый тёплый белый, разрыв связи, переподключение после возврата питания,
работа нескольких контроллеров и восстановление после реального перезапуска.
Совпадение FFF0/FFF3/FFF4 не отменяет эти проверки.
Сборка frontend проверяется отдельно; установленная `.app` в этой задаче не заменяется.

## Изменённые файлы

- `backend/led.py` — общий поиск, данные объявлений, ошибки Bluetooth, проверка GATT.
- `backend/devices/service.py` — метаданные кандидатов, блокировка сканера,
  проверка подключения и сохранение имени/автопроверки.
- `backend/devices/models.py` — необязательное исходное BLE-имя.
- `backend/devices/center.py` — голосовые имена, яркость, неоднозначность и профили.
- `frontend/src/devices.ts`, `frontend/src/devices.css` — существующий фиолетовый UI.
- `tests/test_ble_discovery.py`, `tests/test_led.py`, `tests/test_critical_fixes.py`,
  `frontend/tests/devices.test.ts` — имитации BLE и регрессии интерфейса/голоса.
- `docs/led-strip.md`, `docs/device-center.md`, `docs/BLE_DISCOVERY_FIX.md` — документация.

# Чушпан для macOS

Самостоятельное приложение для Apple Silicon / macOS 26.2+. Один процесс Cocoa
показывает существующий интерфейс WebKit и меню, один дочерний Python-процесс
обслуживает прежние голосовой цикл, SQLite, сценарии, WebSocket и интеграции.
Закрытие окна по умолчанию скрывает его. Повторное открытие через Finder/Dock
показывает это же окно и не загружает модели заново. ⌘Q завершает приложение.

## Почему PyInstaller

Выбран **onedir / windowed**: Python, расширения arm64, PortAudio, MLX/Metal,
Torch, Piper, VAD, BLE и интерфейс поставляются внутри `.app`; распаковки при
каждом запуске нет. py2app также умеет самостоятельные сборки, но его alias mode
зависит от исходников и установленного Python. Отдельная Swift-оболочка потребовала
бы дополнительного IPC и второго UI-слоя. Здесь Cocoa используется через уже
имеющийся PyObjC, а существующий Python-бэкенд сохранён.

Документация: [PyInstaller macOS](https://pyinstaller.org/en/stable/feature-notes.html),
[py2app](https://py2app.readthedocs.io/en/stable/tutorial.html),
[SMAppService](https://developer.apple.com/documentation/servicemanagement/smappservice/mainapp).

## Сборка и установка

Команды нужны только разработчику для сборки, не для запуска приложения.
Нужны arm64 Python 3.12, Node.js/npm и Command Line Tools (`xcode-select --install`).
Полный Xcode и платная учётная запись Apple для локальной сборки не нужны.

```bash
uv sync --locked --group macos-build
.venv/bin/python -m scripts.update_macos
```

Временная сборка: `~/Library/Caches/Chushpan/Builds.noindex/`; единственная установка:
`/Applications/Чушпан.app`. [Проверки, сохранение резерва, очистка и откат](MACOS_UPDATES.md).
Первый перенос личных данных выполняется отдельно через явный `--migrate-from`;
для обычного обновления он не нужен.
Можно также скопировать `.app` в Applications через Finder. Установщик проверяет
подпись до замены, использует временную копию и не запускает приложение или микрофон.
Не обновляй открытую копию: сначала выбери «Завершить Чушпана» в её меню.

Запускай двойным нажатием в Finder, из Dock, Spotlight или Launchpad. Интерфейс
тот же, что у команды `voice`. В настройках появилась категория **Приложение**.
При первом запуске прослушивание выключено. Для начала явно выбери **Включить
прослушивание**: macOS запросит доступ, если ещё не выдавался. Если один компонент
не загрузился, история и настройки остаются доступны, ошибка видна в настройках
и локальном журнале. Модели загружаются при включении голоса, не при открытии окна.
Минимальная версия текущей сборки определяется поставляемым MLX: его arm64-библиотека
имеет deployment target macOS 26.2. Сборка проверялась на macOS 26.6.2; для более
старых систем потребуется отдельное окружение со совместимым MLX и новая проверка.
Обычные команды/сценарии сохраняют прежние проверки согласия.

## Данные и перенос

`~/Library/Application Support/Chushpan` содержит:

- `data/jarvis.db` — история, память, сценарии и прежние настройки в SQLite;
- `.env`, `config.local.yaml`, `private/` — только личные данные;
- `models/voices`, `models/wakeword` — внешние модели;
- `application.json` — параметры оболочки;
- `data/logs/application.log`, `runtime/` — журнал и временные файлы процесса.

Сборка использует перечень публичных ресурсов, не копирует `.env`, `data/`,
`private/`, `config.local.yaml` и голосовые модели. Локальный установщик по явному
`--migrate-from` копирует данные отдельно от `.app`. SQLite переносится через online
backup, включая зафиксированный WAL. Исходники не удаляются; существующие файлы
назначения не перезаписываются. Историю нужно переносить **до первого запуска**,
иначе установщик откажется заменять существующую базу. Кнопка переноса в настройках
копирует только недостающие файлы, не объединяет две базы. Символические ссылки,
старые lock-файлы, журналы и скомпилированные кэши не переносятся.

Большие Whisper-модели продолжают использовать локальный кэш Hugging Face;
Ollama — своё хранилище. Их нет внутри `.app`. При отсутствии локального Ollama
первое включение голоса проверяет loopback endpoint и запускает один `ollama serve`
из установленного Ollama. Уже работающий сервер используется совместно и не
завершается Чушпаном. Сервер, запущенный самим Чушпаном, завершается вместе с ним.
Для нового Mac модели предварительно устанавливаются через существующий setup.

## Автозапуск, фон и разрешения

Переключатель регистрации в **Приложение → Запуск** использует штатный
`SMAppService.mainAppService` (macOS 13+). Статус `approval_required` означает,
что нужно подтвердить объект входа в системных настройках. Новые LaunchAgents
или скрытые службы не создаются. Если установлен старый `local.my-jarvis.voice`,
сначала отключи прежний автозапуск, чтобы он не запускал вторую копию из проекта.
Приложение обнаруживает этот конфликт и отказывается включать новый автозапуск.

Запуск в строке меню имеет приоритет над показом окна. Автопрослушивание действует
только с уже выданным доступом к микрофону; на старте разрешение не запрашивается.
После сбоя движок перезапускается не больше трёх раз с паузами. Микрофон после
перезапуска требуется включить заново. При выключенном прослушивании аудиопоток
закрыт, ожидание построено на событиях. Экономия памяти использует прежний профиль
`economy`; применяется при перезапуске движка. Восстановление сессии использует
прежнюю историю диалога; выполняемые команды, таймеры и сценарии не проигрываются.

Раздел разрешений читает статус микрофона, Accessibility и записи экрана в текущем
процессе. Automation, Bluetooth и уведомления имеют отдельные системные настройки;
неподтверждённые права не выдаются за разрешённые. Геолокация/календарь используют
существующий помощник **Чушпан — утро** с прежним bundle ID. Swift-помощники уже
скомпилированы в сборке: пользователю не нужен компилятор для их запуска.

Bundle ID основного приложения: `ee.chushpan.desktop`. Локальная ad-hoc подпись
проверяется при сборке и установке; обычные повторные запуски сохраняют одну
идентичность. После пересборки ad-hoc подпись может потребовать повторной выдачи
некоторых прав. Для распространения без предупреждений Gatekeeper нужны Developer
ID, подпись вложенных исполняемых файлов, hardened runtime и нотариализация Apple.
Текущий локальный выпуск не нотариализован. Защита macOS не отключается.

## Проверки без микрофона и устройств

```bash
.venv/bin/pytest -q
.venv/bin/ruff check backend scripts tests
.venv/bin/ruff format --check backend scripts tests
npm --prefix frontend test
npm --prefix frontend run build
# Импорт упакованных библиотек, без загрузки моделей и аудиопотоков:
/Applications/Чушпан.app/Contents/MacOS/Chushpan --self-test /tmp/chushpan-imports.json
# Отдельная тестовая копия данных, без микрофона/моделей/сценариев:
CHUSHPAN_APP_DATA=/tmp/chushpan-smoke /Applications/Чушпан.app/Contents/MacOS/Chushpan --smoke
```

В `--smoke` включение микрофона, миграция и изменение автозапуска запрещены.
Проверяются настоящее окно, меню, повторное открытие, фон и завершение процессов;
этот режим не доказывает распознавание, TTS или физические интеграции.
Для полной проверки отдельно нужны: разрешённый микрофон и реальная фраза,
озвученный ответ, выбранный безопасный сценарий, запуск после выхода/входа в macOS,
Spotlight/Launchpad и восстановление после реального сбоя. Не отмечай эти пункты
выполненными по результату unit-тестов.

## Выпуск новой версии

Обнови версии в `pyproject.toml`, `backend/desktop/__init__.py` и `.spec`, обнови
lock-файл и описание выпуска. На чистом arm64 окружении выполни проверки и сборку,
проверь `codesign --verify --deep --strict`, импорты и чистую тестовую копию данных.
Для релиза с Developer ID настрой подпись и нотариализацию перед распространением;
не подписывай личными секретами внутри исходников. Загрузка `.app`/DMG в GitHub
Releases — отдельное действие. Кнопка обновлений читает только последний release
из существующего GitHub; она не скачивает и не устанавливает код автоматически.

## Архитектура

Backend — Python 3.12, один процесс с `asyncio`, CLI в `backend/__main__.py`.
`chat.py` и `voice.py` используют общие `Settings`, `Conversation`, реестр
инструментов, SQLite и системную инструкцию. Отдельный процесс нужен окну
`pywebview`: Cocoa требует главный поток. Swift-помощники предоставляют
Accessibility, EventKit и CoreLocation.

Голосовой путь: `Microphone` → кадры 16 кГц → VAD/сегментация → локальное
распознавание фразы → Whisper → `Conversation` → Ollama/tool calls → разбиение
на предложения → Silero/Piper/`say` → аудиовыход. Состояния:
ожидание, прослушивание, размышление, речь; события передаются через `HudBus`.

Frontend — TypeScript без React, Vite, CSS и SVG-анимация ядра. Это HUD с
транскриптом, погодой, новостями, состоянием Mac, таймерами, экспортом и
переключателем автозапуска. `FastAPI` раздаёт `frontend/dist` и WebSocket `/ws`;
универсального HTTP API для диалога или вызова инструментов нет.
Frontend получает типы при компиляции, но входящие события не валидируются схемой
во время выполнения. Отдельного frontend test runner и browser/E2E-тестов нет.

## Состояние подсистем

### Backend и frontend

**Реализовано:** CLI, текстовый/голосовой режимы, потоковые ответы, состояния,
HUD, нативное окно, блокировка второго голосового экземпляра, экспорт.
Все 61 Python-модуль backend импортируются. TypeScript и production-сборка проходят.

**Настройка/проверка:** полный пользовательский проход с реальными устройствами,
обработка сбоев окна и разрешений. Сборка обновила только игнорируемый `frontend/dist/`.

**Проблемы:** первый полный прогон дал сбой теста завершения HUD; отдельно и в
повторном полном прогоне результат указан в разделе проверок. Изменений кода для
его устранения не делалось. Нет автоматических тестов самого DOM/клавиатуры/браузера.

### LLM и система инструментов

**Реализовано:** собственный async-клиент Ollama; поток JSON; tool schemas;
кэширование префикса; повтор пустого ответа; исключение внутреннего thinking из
озвучки и БД; история вызовов инструментов. Реестр содержит 19 инструментов при
выбранном YouTube Music и подключённой памяти; голосовой режим с активацией
добавляет двадцатый, `go_to_sleep`. Утренний сценарий выполняется кодом отдельно.

**Настройка/проверка:** реальные ответы модели и выбор инструментов в этом аудите
не генерировались. Тесты проверяют протокол с подставным Ollama/обработчиками.

**Проблемы:** нет полноценной валидации JSON Schema, общего контроля разрешений,
общего тайм-аута инструмента или ограничения количества параллельных вызовов.
`max_rounds=3` допускает выполнение инструментов и на четвёртой итерации
`range(max_rounds + 1)`: последняя попытка не ограничена текстовым ответом.

**Подтверждено:** уже работающий Ollama `0.40.13`, loopback-адрес

### STT, VAD, TTS и активация

**Реализовано:** `mlx-whisper`/Whisper Small, русский STT, локальный Silero VAD,
фильтрация типичных галлюцинаций, речь с фразой и запросом в одном высказывании,
follow-up 8 с, тайм-аут после активации 6 с. Фраза — «Эй, Чушпан»
(`эй чушпан` в настройках). Она распознаётся Whisper; `hey_jarvis.onnx` — резервный
путь при `phrase: null`, не текущая русская модель активации.

**Подтверждено:** Whisper config и `weights.npz` (~481 МБ) есть в локальном
Hugging Face cache. Файл Silero `silero_v5_6_ru.pt` (~148 МБ) есть.
Текущий голос — Silero `eugene`, 24 кГц; произношение «Чушпа́н» добавляется только
в озвучке. Дополнительные Piper-модели и английский wake model также присутствуют.
Импорты STT, TTS, аудио, VAD/AEC доступны.

**Настройка/проверка:** разрешение macOS на микрофон, реальные вход/выход,
ложные активации, фактическая речь и разборчивость. Во время аудита звук не
записывался, не синтезировался реальной моделью и не проигрывался.

**Ограничения:** `barge_in=false`, поэтому прерывание голосом сейчас выключено;
`echo_cancellation=true` используется только вместе с barge-in. При выбранной
фразе Whisper остаётся загруженным даже при выгрузке LLM. «Сон» и `sleep` в HUD
не выключают захват микрофона: он нужен для обнаружения следующей активации.
Если STT cache отсутствует, `_model_path()` пытается скачать модель из интернета.

**Реализовано:** `ru-RU`, русские инструкции/CLI/HUD/даты/склонения/таймеры,

Тесты личности, русского языка и общей личности для разных режимов проходят.

**Настройка/проверка:** фактическое соблюдение характера моделью, произношение

### Память

**Реализовано:** `data/jarvis.db`, SQLite, таблицы `conversations`, `messages`,
`facts`, `preferences`; миграция старых сообщений; параметризованные SQL;
продолжение диалога; факты между сессиями; дедупликация; замена/удаление;
музыкальные предпочтения в namespace `youtube_music`; экспорт Markdown.
`PRAGMA quick_check` в режиме только чтения: `ok`. Найдены 7 диалогов,
48 сообщений, 1 факт, 1 предпочтение; содержание не выводилось.
В музыкальных предпочтениях есть ключ `default`; реальный ID не публиковался.

**Настройка/проверка:** политика хранения/удаления/резервирования, права файлов,
восстановление и миграции на копии БД. Лимит фактов — 100 по 300 символов,
все факты вставляются в системный prompt; история ограничена 30 сообщениями.

**Отсутствует/проблемы:** семантический поиск, embeddings/RAG, важность/источник
факта, сроки хранения, автоматическая защищённая резервная копия, шифрование.
`forget` не проверяет явную просьбу; `remember` использует эвристический regex,
а история диалога сохраняется автоматически, даже когда факт не запрошен.
Удаление факта не удаляет его прежние упоминания из истории/экспортов/логов.
Коррекция сначала удаляет старый факт и затем добавляет новый отдельной операцией.
Неотслеживаемый `:memory:.ses` сохранён как пользовательский файл; не удалялся.

**Реализовано:** Open-Meteo forecast/geocoding с кэшем, RSS-новости ИИ,
сводка при запуске раз в день. Явное «Доброе утро, Чушпан» запускает отдельный

**Ограничения:** календарь доступен только утреннему сценарию, отдельного LLM

`fullAccess`; исходник не содержит записи событий. Работоспособность live Delfi/
RSS/API в этом аудите не проверялась; разметка сайтов может меняться.
Нет общего интернет-поиска и учебной интеграции TalTech.

**Реализовано:** Safari Web App + публичный `ytmusicapi`, fallback через AX,

**Подтверждено:** выбран `youtube_music`; установленный
`~/Applications/Music.app` обнаружен по манифесту и совпадает с настроенным bundle ID.

**Настройка/проверка:** вход в web app, Accessibility для конкретного приложения

плейлистов нет. API-авторизация необязательна; при необходимости файл должен
оставаться в игнорируемом `private/`, а не рядом с публичными исходниками.

## Существенные риски и технический долг

1. **Перед расширением управления Mac — общий контроль действий.** Сейчас есть
   список включённых групп, allowlist имён инструментов и отдельные проверки
   intent для сохранения факта/назначения плейлиста/лайка. Общего подтверждения,

   `open_app`, громкости, таймеров, `forget` нет. Prompt — инструкция модели,
   а не граница разрешений. Внешние новости и память могут влиять на модель.
2. **Удаление памяти без явной просьбы.** `backend/tools/memory.py:81` не
   проверяет `user_text`. Подтверждено на синтетическом факте в `:memory:`:
   контекст «Расскажи анекдот» не помешал `forget(id=...)` вернуть `ok=true`.
   Реальные факты не затронуты. Regex `remember` также не является строгим
   разрешением: содержит общие слова и не покрывает все отрицания.
3. **Аргументы LLM могут нарушить выполнение диалога.** В
   `backend/tools/registry.py:97` схема только передаётся Ollama. Пример с
   безопасным fake handler: JSON `1` приводит к необработанному `AttributeError`
   на `.items()` до `try`; строка вместо integer проходит в handler.
   `[]`/`null` трактуются как пустые аргументы. Нет JSON Schema validation
   (`required`, enum, типы, `additionalProperties`); неизвестные ключи отбрасываются.
4. **WebSocket доверяет локальной среде.** Привязка по умолчанию к loopback,
   проверяются browser origins; чужой web origin отклоняется тестами.
   Но origin может отсутствовать, отдельного секрета/аутентификации нет.
   Локальный процесс может читать транскрипт и посылать `wake`, `sleep`,
   `autostart`, `export`. Настройка внешнего bind расширяет воздействие.
   Прямого вызова shell или LLM handler через `/ws` нет; `wake` включает слушание.
5. **Запуск приложений шире фиксированного списка.** `open_app` допускает любое
   установленное приложение/путь, кроме пустой строки и ведущего `-`.
   Это не shell-инъекция: используется `create_subprocess_exec("open", "-a", name)`.
   Однако launch/activation и стартовые действия произвольного приложения
   выполняются с правами текущего пользователя без дополнительного согласования.
6. **Параллельные действия и ограничения.** `_run_tools` запускает все вызовы
   одного ответа через `asyncio.gather`. Общей сериализации изменений системы
   и лимита числа вызовов нет; отдельные музыкальные операции защищены lock.
   Описанный выше лимит rounds не является строгим пределом побочных действий.
7. **Чувствительные локальные данные.** SQLite/логи/экспорты не зашифрованы
   приложением; debug-лог реестра включает аргументы и первые 300 символов
   результата. Ошибки некоторых общих инструментов возвращаются модели целиком.
   Музыкальный адаптер уже скрывает auth/HTTP ошибки — этот подход можно повторно использовать.
8. **Модели как доверенный исполняемый материал.** Silero загружается через
   `torch.package.PackageImporter.load_pickle`. `setup.sh` скачивает voice-файл
   без отдельной проверки digest/подписи и без атомарного завершения download.
   При повреждённом/подменённом файле нельзя считать его безопасным только
   потому, что путь локальный. В этом аудите реальный pickle не загружался.
9. **Неполные границы настроек/диагностики.** Часть строк/тайм-аутов не имеет
   enum/числовых ограничений; настройки допускают внешний LLM/HUD host.
   `doctor` проверяет Spotify даже при выбранном YouTube Music; отметка custom
   wake phrase не доказывает работоспособность STT; `check_voice` проверяет файл,
   а не реальный синтез. `doctor`, `config`, `prompt` не являются полностью
   безэффектными: возможны геокодирование/кэш/открытие и миграции БД/LLM generation.

**Может ли LLM выполнять произвольный shell?** В текущем реестре такого
инструмента нет. Используются фиксированные executable/операции без
`shell=True`; shell-метасимволы не превращаются в команды. Python-помощники
`run`/`process` технически запускают процессы, но не зарегистрированы как
универсальный инструмент. Нельзя приравнивать это к общему sandbox: handler
исполняется с правами процесса, а открытие приложения, AppleScript/JXA,
AX и будущие расширения всё равно требуют контроля действий.

**Микрофон и экран:** разрешения выдаёт TCC macOS конкретному приложению запуска.
App bundle содержит `NSMicrophoneUsageDescription`, Spotify — Apple Events usage.
Проверка цифровой тишины может предупредить об отказе микрофону, но не управляет
разрешением. Screen Recording нужен старому screenshot-пути Spotify;
YouTube Music/Safari используют AX, без screenshot и без Safari JavaScript.
Accessibility даёт широкие права приложению, хотя текущие handler ограничивают
цели. Текущее состояние TCC не читалось, разрешения не запрашивались и не менялись.

## Готовность к этапу 2

Проект имеет пригодную базу: реестр, существующие инструменты Mac, отдельные
адаптеры, тесты, локальную LLM и сохранённую русскую личность. Можно планировать
этап 2 на этой базе, не переписывая аудио, память и музыку.

Безопасное расширение управления Mac **условно готово**: первым условием этапа 2
должны стать общая проверка разрешений/аргументов и запрет произвольного shell;
также нужно разобрать нестабильность lifecycle-теста HUD. Реальные TCC/голосовые
сценарии пока не подтверждены. Это условия следующего задания, а не выполненные
исправления. На этапе 1 изменения ограничены тремя файлами документации.

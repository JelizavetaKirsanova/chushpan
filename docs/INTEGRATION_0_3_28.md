# Интеграция пяти разделов — 0.3.28, сборка 60

Исходная точка проверки — `86a9343`. Главная, устройства, сценарии,
освещение и медиатека объединены в существующем приложении без нового редизайна.
Коммиты `8964ee2`, `a0352f1`, `fb38905`, `de07a76`, `86a9343` входят в историю.

## Исправления

- Сценарии сохраняют и проверяют собственные опубликованные документы с
  read-only датами. Импорт JSON валидируется до замены черновика, сохраняет
  несохранённую работу при отказе и поддерживает отсутствие лимита времени.
  Новые IF имеют валидное начальное условие.
- Освещение выбирает только видимые устройства при массовом выборе, действительно
  снимает выбор и восстанавливает карточки после изменения поиска. Инспектор
  соответствует цели команды; проверка возможностей учитывает скрытые выбранные
  устройства. Измеренная яркость приоритетнее отправленной, состояние команды
  подтверждается конечным ответом. Панели и диалоги используют обе темы.
- Изменения прогресса, избранного и плейлистов локальных файлов атомарны в
  IndexedDB. Видео сохраняется при обновлении данных, а остальные элементы его
  карточки получают актуальные значения. Запоздавшие события/загрузки аудио
  не сбрасывают позицию следующего трека. Ручные сериалы и специальные сезоны
  доступны без метаданных каталога.
- Удаление локальных связей плейлиста следует за подтверждением SQLite.
  JSON экспорт/импорт включает пользовательские плейлисты; старые копии
  совместимы, существующие записи объединяются без удаления.
- Селектор темы доступен в свёрнутой панели. Light/dark/system и обработка
  изменения системной темы проверяются отдельными тестами.
- По скриншотам установленной сборки исправлены конфликты светлой темы:
  кнопки, поля, карточки, дата, значки и активная навигация. Индикатор состояния
  больше не перекрывает часы. Проверка реального CSS в Chromium подтверждает
  одинаковую геометрию обеих тем на широких и узких экранах.
- Нативный WebView больше не очищает своё хранилище при запуске. Первый
  фактически занятый loopback-порт сохраняется атомарно в `web-origin.json`
  с правами `0600` и используется при рестарте. Занятый порт или повреждённый
  файл останавливают запуск без скрытого переключения на пустое хранилище.
  Cocoa pywebview игнорирует `storage_path`; данные хранит WKWebsiteDataStore,
  а профили разделяются origin. Файлы WebKit и `web-origin.json` нужно сохранять
  вместе. Старые сборки с private mode могут очистить WebKit при откате.
- Манифест сборки содержит хеши сценариев, локальной медиатеки, переноса
  плейлистов, нативного хранения и изображений баннеров всех пяти разделов.
- Изменяемые метаданные локальных файлов вынесены в отдельное IndexedDB-хранилище:
  обновление прогресса больше не пересохраняет Blob/File. Старые файлы и их
  метаданные читаются без перезаписи содержимого. Регрессия проверяет upgrade,
  60 конкурентных операций и полный рестарт Chromium/WebKit на временных файлах.
  В узком окне команды музыкального сервиса переходят на отдельную строку,
  не перекрывая громкость.

## Зависимости

В lock-файле обновлены только certifi 2026.10.19, filelock 4.2.1,
opentelemetry-api 1.45.2 и setuptools 84.1.0. Аудит отдельного окружения
сборки проверил 115 registry-пакетов: известных уязвимостей и пропусков нет.
Общая среда разработки не обновлялась под работающим чужим процессом.

Npm audit сообщает четыре high-записи для цепочки
Vite → tinyglobby/fdir → picomatch 4.0.7: это одна
[ReDoS-уязвимость](https://github.com/advisories/GHSA-fc5q-39xc-vjpf).
На 17 ноября 2026 исправленной опубликованной версии нет. Эти зависимости
используются при разработке/сборке; `npm audit --omit=dev` сообщает 0.
Принудительный downgrade Vite не применялся. Production bundle содержит
статический интерфейс, а не Node/Vite.

## Границы проверки и существующие ограничения

Автоматические проверки перед сборкой: 239 frontend-тестов и 2891 backend-тест
прошли без падений. Backend запускался в отдельной среде с исправленными
зависимостями. TypeScript, Ruff, Python formatting, проверка lock-файла и
production-сборка прошли. Сохраняется предупреждение Vite о размере JS-chunk
более 500 kB. Изолированный Chromium проверил импорт пяти типов файлов,
повторное открытие IndexedDB и 60 конкурентных операций без потери данных.

Первоначальный sandbox-прогон выявил EPERM при bind Unix-сокета; повтор вне
sandbox прошёл. Ошибка round-trip метаданных сценария также была устранена;
окончательные полные прогоны не используют отключённых тестов или исключений.

Проверки физических устройств, микрофона и пользовательских сценариев
не выполняются без отдельного разрешения. Для native UI используется копия
существующей SQLite с отключёнными автоматическими подключениями/заданиями;
оригинальные записи не изменяются. Тестовые локальные файлы не содержат
пользовательских данных.

У сценариев есть типизированные входные переменные и привязки параметров;
универсального конструктора ANY/ALL, циклов, присваивания и выражений для
изменяемых переменных нет. MQTT/Home Assistant не представлены рабочими
драйверами. Эффекты и расписания зависят от возможностей драйвера и работающего Mac.

Каталог, история и плейлисты хранятся в SQLite. Локальные файлы, их прогресс
и локальные связи плейлистов находятся в IndexedDB и не входят в JSON-копию
каталога. Прямое голосовое управление этими локальными файлами не реализовано.
Поддержка внешних источников и кодеков остаётся зависимой от сайта/проигрывателя;
неподдерживаемые форматы открываются внешним приложением.

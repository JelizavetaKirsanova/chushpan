# Диагностика блокировки ночного сценария

## Установленная причина

NightRoutine.run вызывает NightPreflight.check до любых изменений. В конце
check выполняется all(status in {granted, reviewed}); любой иной статус
блокирует сценарий. Возвращаются checks и отдельный blocking_checks.

В текущей конфигурации night.shortcut_permissions_reviewed=false. Это
гарантированная блокировка Shortcuts permissions=unknown даже при Accessibility
и Safari Automation=granted. Значение не менялось автоматически: это отметка
ручной проверки прав самой команды, а не системное TCC-разрешение.

Дополнительно исправлено сравнение UUID экранов: разный регистр одного UUID
больше не считается различием дисплеев. Для BetterDisplay выводится стадия
сбоя: inventory, builtin_display, external_display, video_display_configuration.

## Кто выполняет действия

| Действие | Исполнитель |
| --- | --- |
| Общая диагностика TCC | временный Swift-процесс permissions.swift |
| Safari Automation и JavaScript | настоящий native-помощник youtube_safari.swift, NSAppleScript внутри него |
| Desktop Accessibility/дисплеи | отдельный Swift-помощник ytmusic_ax.swift |
| Чтение системной громкости | osascript, Standard Additions |
| Запуск Youtube sleep | /usr/bin/shortcuts run после разрешений и подтверждения |
| Действия внутри Shortcut | Команды/системный исполнитель; собственные разрешения |

Новый read-only youtube_permissions проверяет Accessibility, Apple Events
через AEDeterminePermissionToAutomateTarget(..., false) и, только при granted,
константное выражение JavaScript в существующей вкладке. Не открывает вкладки,
не меняет плеер и не вызывает диалоги разрешений. Возвращает PID/PPID,
executable и исходный OSStatus. Недоступный реальный помощник блокирует запуск;
его права не подменяются granted от общего диагностического процесса.

В логах PERMISSION_PROCESS / NATIVE_PROCESS / SHORTCUT_PROCESS — только PID,
PPID и executable. Аргументы команд, ключи и окружение не выводятся.

## Как проверить и устранить

1. Перезапустить обычный экземпляр Чушпана для загрузки обновлённого Python-кода.
   Сказать «Чушпан, проверь разрешения ночного режима». Это локальный маршрут
   без Gemini, подтверждения и ночного запуска. Обычный голосовой диалог
   сохраняется по существующим правилам истории; CLI night-check память не открывает.
2. Для отдельного отчёта:

   ```bash
   cd ~/my-jarvis
   uv run python -m backend night-check --json --pid 66847
   ```

   --pid читает только PID/PPID/executable выбранного процесса и его детей;
   не проверяет TCC этого PID. Системные проверки относятся к процессу запуска
   команды. Для приложения достовернее команда из пункта 1.
3. Системные настройки → Конфиденциальность и безопасность → Универсальный
   доступ; Автоматизация → Safari: проверить именно приложение/исполнитель,
   указанное macOS для обычного запуска Чушпана. Не выдавать права случайному
   Python только из-за похожего имени. Если записи Automation ещё нет, нужен
   штатный запрос разрешения из фактического приложения; эта диагностика
   намеренно не создаёт его и не запускает действия ради появления запроса.
4. Safari → Настройки → Разработчик → Автоматизация → Разрешить JavaScript
   из событий Apple (в других версиях: Разработка → одноимённый пункт).
   Для проверки нужна существующая обычная вкладка.
5. Проверить действия Youtube sleep без её запуска. Команды → Настройки →
   Дополнения → Разрешить выполнение скриптов; Конфиденциальность и безопасность
   → Автоматизация для Команд → Safari/System Events, если к ним обращаются
   действия; Универсальный доступ для исполнителя нужен при управлении UI.
6. Только после ручной проверки отметить в существующем разделе night файла
   config.yaml shortcut_permissions_reviewed: true. Не создавать второй раздел
   night. Сам файл в этом проходе не менялся. Это не выдаёт системных разрешений.
7. Повторить диагностику: blocking_checks должен стать пустым. При неизвестном
   статусе не считать действие разрешённым.

Тесты проверяют отказ без ручной проверки, эквивалентность UUID по регистру,
приоритет статусов настоящего Safari-помощника, отсутствие чтения аргументов
процессов и корректный поиск приложения за Python.app. Ночной сценарий,
видео, яркость, громкость и сон не запускались. .env и ключи не менялись,
коммиты и push не выполнялись.

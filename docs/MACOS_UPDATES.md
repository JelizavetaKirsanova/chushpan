# Одна установка Чушпана

Пользователь открывает только `/Applications/Чушпан.app`: из Finder, Spotlight
или единственной закреплённой иконки Dock. Bundle ID остаётся `ee.chushpan.desktop`.
Резервы и тестовые пакеты не являются установленными приложениями.

## Обновить

Закрой приложение через ⌘Q. Из корня проекта:

```bash
.venv/bin/python -m scripts.update_macos
```

Команда собирает приложение в уникальной временной рабочей папке внутри
`~/Library/Caches/Chushpan/Builds.noindex/`, проверяет его и заменяет только
`/Applications/Чушпан.app`. В `dist` готовый `.app` больше не создаётся.
Не открывай тестовые пакеты через Finder или `open`: это может зарегистрировать
их в Launch Services. Сборщик не вызывает `lsregister` и не меняет Dock.
Установщик обновляет уже закреплённую иконку на основной путь, удаляя старую
закладку файла: она не должна следовать за предыдущим пакетом в резерв.

До замены проверяются Bundle ID, версия, arm64, подпись, отсутствие личных данных
и внешних символьных ссылок, целостность копии в скрытом staging на том же томе.
Временный пакет **не запускается**: даже импорт UserNotifications может неявно
зарегистрировать его в Launch Services. Проверка `--self-test` выполняется только
из `/Applications/Чушпан.app` после замены, импортирует поставленные модули с
отдельным `CHUSHPAN_APP_DATA` и не открывает окно, микрофон и физические устройства.
Если заключительная проверка или регистрация не удалась,
предыдущий пакет возвращается на основной путь. Одновременные обновления запрещены
блокировкой. Запущенное приложение установщик сам не завершает.

Предыдущий пакет целиком сохраняется в
`~/Library/Application Support/Chushpan/Updates.noindex/<timestamp>/Чушпан.app`.
Каталоги `.noindex` исключают служебные пакеты из поиска; зарегистрировать установщик
может только основной путь и его встроенного помощника. Никакого общего сброса
Launch Services нет. Журнал последней установки — `Updates.noindex/last-install.json`.
Не удаляй каталог Updates.noindex: там находится резерв для отката.

При принудительном завершении установщика между двумя переименованиями (например,
SIGKILL или выключение питания) резерв остаётся на диске; журнал транзакции
`Updates.noindex/<timestamp>/receipt.json` содержит его путь. Новая установка
блокируется до восстановления через
`.venv/bin/python -m scripts.install_macos --recover`. Восстановление сохраняет
прерванный новый пакет и возвращает проверенный резерв на основной путь.

## Очистка и откат

По умолчанию сборка остаётся в `.noindex`, а установщик выводит точного кандидата
на очистку. Для явного разрешения перенести только новую проверенную сборку
в Корзину после успешной установки:

```bash
.venv/bin/python -m scripts.update_macos --trash-build
```

Это не очищает Корзину и не удаляет родительскую рабочую папку, резерв предыдущей
версии, другие сборки, исходники или пользовательские данные. Очистка проверяет
журнал успешной установки, версии и SHA-256 исполняемого файла обеих копий.
За пределами `Builds.noindex` эта операция запрещена. Старые сборки и резервы
автоматически не удаляются.

Откат к предыдущему сохранённому приложению:

```bash
.venv/bin/python -m scripts.install_macos --rollback
```

Откат тоже проверяет пакет и сохраняет заменяемую версию. Для раздельных этапов
доступны `scripts.build_macos` и `scripts.install_macos`; второй читает проверенный
путь из `build/macos/last-build.json`, а не ищет случайный `.app` в `dist`.

## Сохранность данных

Установка не переносит и не удаляет SQLite, WAL/SHM, настройки, память, сопряжения,
Keychain, логи или резервные снимки. Одноразовый `--migrate-from` остаётся явной
операцией копирования без замены существующей базы и для обычного обновления не нужен.

Git Sync сохраняет пользовательские данные отдельно от Git. Пакеты с любым именем
`*.app` и служебные native-каталоги больше не включаются в новые снимки. Существующие
снимки сохраняются; возрастные кандидаты записываются в локальный
`.git/chushpan-sync/backup-retention-candidates.json` для проверки вместо удаления.
Диагностические экспорты и журналы установки нельзя коммитить в исходники.

Старая CLI-оболочка создаётся только в `data/.legacy-apps.noindex` и не регистрируется
в Launch Services. Её `LSUIElement` скрывает отдельную иконку Dock. На установленном
Mac обычный запуск и настройку входа выполняй в основном приложении; прежний
LaunchAgent голосового CLI должен оставаться припаркованным, чтобы не включался
второй голосовой цикл при входе.

# Конструктор сценариев: реализация и границы проверки

Дата: 2 ноября 2026 года.

Программный путь от сохранения сценария до результата зарегистрированной интеграции
проверен на моках. Полная аппаратная и визуальная приёмка ещё не завершена.
Работа продолжена с коммита `64a5be4`; существующие интеграции, диалоги,
голосовая модель и встроенный ночной сценарий сохранены.

## Что реализовано

- Раздел «Сценарии»: создание, редактирование, копирование, удаление,
  включение/выключение, описание, иконка и сохранение в существующей SQLite.
- Редактор блоков: действия из реестра, последовательности, параллельные ветки,
  задержки, IF/ELSE, переменные, условия и обработка ошибки «остановить/продолжить».
  Блоки перемещаются кнопками или перетаскиванием в пределах одной группы.
- Триггеры: голос, ручной запуск и расписание по времени/дням недели.
  Расписание работает, пока открыт backend; пропущенные запуски после его остановки
  автоматически не воспроизводятся. Для опасных сценариев требуется ручной запуск.
- Число голосовых фраз не ограничено; одна фраза — до 500 символов.
  Дубликаты и конфликты между сценариями отклоняются. Версии защищают от
  перезаписи изменений другого окна.
- Точное распознавание после нормализации, локальное сопоставление русских понятий,
  уточнение при неоднозначности. Известные команды и сохранённые точные фразы
  обходятся без LLM. Модель может вернуть только структурированные намерения
  с проверкой устройства, параметров и исходной просьбы.
- Безопасные сценарии запускаются сразу; опасные действия и настройка «всегда»
  требуют одноразового кода, связанного с полной версией сценария.
- Обучение фразе, проверка распознавания без исполнения, явная запись следующей
  реплики через существующий локальный голосовой контур, редактирование/удаление
  правил и история обучения. Разговорное исправление предлагает сохранение;
  правило не создаётся без явного ответа. Временный контекст находится в RAM.
- Реестр устройств/действий и экран разрешений. Неизвестный статус доступа
  не превращается в «предоставлено». Наличие настройки LED не считается
  доказательством текущего Bluetooth-подключения.
- Журнал шагов перед отправкой команды, реальные интервалы выполнения,
  статусы `running`, `confirmed`, `sent`, `unverified`, `failed`, `interrupted`.
  События обновляют интерфейс во время выполнения и после каждого шага.
  Отправленный BLE-пакет не объявляется подтверждённым физическим состоянием.
- Блокировка конфликтующих сценариев и прямых команд через общий реестр,
  защита от повторной обработки события, отсутствие автоматического повтора
  прерванного или неизвестного действия.

## Исправления продолжения

- Голосовой контур совместим с существующими тестовыми двойниками.
  Контекстная голосовая фраза проходит только с выданным сервером разрешением.
- Обычные локальные команды пропускают ненужный семантический перебор.
  Точные фразы индексируются; временный контекст больше не создаёт запись SQLite
  на каждую реплику.
- `youtube sleep`, `Youtube sleep`, `YouTube Sleep` разрешаются через единственную
  разрешённую запись и фактический список Shortcuts. UUID обязателен; неоднозначное
  имя или другой UUID блокирует запуск. Команда вызывается по UUID, существующее
  имя выводится в результате. Создания, переименования и редактирования Shortcut нет.
- Шаблон «Я спать» использует имя разрешённой существующей команды. Старые
  сохранённые варианты регистра также работают. Шаблон остаётся выключенным
  до проверки интеграций пользователем. Исходный встроенный ночной сценарий сохранён.
- Уведомления доступны на экранах обучения, устройств и разрешений. Исправлены
  значки узкой навигации, имя пункта «Сценарии», состояние после потери соединения,
  обновление редактора после обучения и перенос блоков между разными группами.
- Неподтверждённый уровень яркости не считается успехом даже при общей отметке
  подтверждения в ответе инструмента. Ошибка сбрасывает предположение о подключении.
- Запуски расписания выполняются отдельными отменяемыми задачами; долгая задержка
  одного сценария не блокирует проверку остальных расписаний.

## Автоматическая приёмка

Команды последнего полного прогона:

```sh
.venv/bin/pytest -q
npm --prefix frontend test
npm --prefix frontend run build
.venv/bin/ruff check backend tests scripts
.venv/bin/ruff format --check backend tests scripts
git diff --check
```

Результат: **1639 backend-тестов**, **20 frontend-тестов**, TypeScript/Vite,
Ruff, проверка форматирования 186 Python-файлов и проверка diff — успешно.
Все устройства, микрофон, STT/TTS и Shortcuts в автоматической приёмке заменены
моками или тестовыми транспортами.

Сквозной тест `test_editor_websocket_sqlite_voice_registered_transport_and_ui_receipt`
сохраняет сценарий через настоящий `/ws` FastAPI, читает его из SQLite, передаёт
голосовую реплику через `VoiceLoop` с моками STT/TTS, вызывает существующий
зарегистрированный `MacDesktop.brightness`, проверяет единственный вызов
`desktop_brightness(level=37)` и получает событие интерфейса с результатом 37%.
После этого сценарий удаляется через тот же WebSocket.

Дополнительно проверены изменение и копирование сценариев, 1500 фраз после
повторного открытия SQLite, различные формулировки и составные команды,
контекст, отрицания/цитаты/шум, отключённый сценарий и инструмент,
ошибки и продолжение после ошибки, параллельность, отмена, версии подтверждения,
повтор события и разрешённая Shortcut с подтверждением и без него.

## Что проверено кликами в интерфейсе

На изолированном сервере с временной SQLite и моками устройств:
создан сценарий «Проверка редактора», добавлена собственная фраза,
выбрано действие яркости, сохранено значение 35%, выполнен тест и получен
статус «выполнен и проверен». В журнале показана измеренная длительность.
Проверка понимания той же фразы показала точное совпадение и 100% оценки
сопоставления без повторного выполнения действия.

Повторную визуальную проверку после исправлений, а также ручные клики
редактирования/удаления завершить не удалось: инструмент браузера сообщил
`Local browser use is disabled in Work settings`. Эти операции проверены
автоматически через сервис и WebSocket, но не объявляются проверенными
кликами в финальной сборке. Проверка всех элементов native WebKit также остаётся
ручной. Тестовый сервер остановлен.

## Измеренная задержка

Воспроизводимая команда без личных настроек, сети и физических устройств:

```sh
.venv/bin/python scripts/benchmark_automations.py --samples 100 --phrases 1500
```

Последний замер, по 100 прогретых запросов с чередованием базового и нового пути:

- Обычная команда яркости без обработчика сценариев: медиана **1,4582 мс**,
  p95 **1,6915 мс**.
- Та же команда с обработчиком сценариев: медиана **1,5552 мс**,
  p95 **1,8455 мс**; разница медиан **+0,0970 мс**.
- Сохранённая фраза → исполнитель → ответ с мок-дисплеем:
  медиана **35,0900 мс**, p95 **35,7775 мс**.
- Точный поиск по последней из 1500 фраз: медиана **0,0155 мс**.
- Первое построение индекса: **36,9940 мс**.

Это реальные измерения локального программного пути, включая SQLite, но без
STT, синтеза речи, BLE и системных вызовов устройства. Они не доказывают
голосовой отклик менее 1,5 с и не являются измерением микрофона пользователя.
Встроенная статистика сохраняет отдельные этапы намерения, поиска, планирования,
выполнения и проверки результата; существующие STT/первый звук/общая длительность
сохранены.

## Ручная настройка и оставшиеся ограничения

1. Перезапустить Чушпана для загрузки нового backend и интерфейса.
   Проверить создание, изменение, перенос блоков, сохранение и удаление
   в обычном macOS-окне, включая восстановление после разрыва соединения.
2. С отдельного явного разрешения проверить реальную речь и физическое действие:
   сначала один безопасный сценарий яркости, затем LED, BetterDisplay и Shortcuts.
   Реальные устройства, запись микрофона, воспроизведение и сон Mac в этой работе
   не запускались.
3. Проверить права именно приложения запуска. Для внешнего экрана проверить
   `night.external_uuid` при нескольких дисплеях. Для Shortcut проверить её
   содержимое и разрешённый UUID. `safe_without_confirmation: true` допустимо
   только после ручной оценки конкретной безопасной команды; значение по умолчанию
   сохраняет подтверждение. Настройки `.env`/`config.local.yaml` не изменены.
4. Локальное умное сопоставление использует словарь понятий и русские формы слов,
   а не универсальную embedding-модель. Похожесть может потребовать уточнения
   или обучения новой фразе. Отрицания, цитаты и условные просьбы блокируются.
5. LED не предоставляет надёжного readback физического цвета/яркости: успешная
   запись остаётся статусом «отправлено». Непроверенные режимы ленты не добавлены.
   Прямое управление iPhone/iPad и громкостью телевизора не реализуется без
   существующего поддерживаемого порта. Интерфейс сообщает об этом явно.
6. Сценарии и журналы сохраняются локально. Статус подключения в реестре и
   временный контекст уточнения требуют новой проверки после перезапуска.
   История интерфейса ограничена последними 100 запусками, а блоки одного
   сценария — 500 блоками и 12 уровнями вложенности.

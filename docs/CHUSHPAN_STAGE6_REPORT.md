## Результат

Реализован отдельный путь обычного YouTube Video: официальный Data API v3,
пагинация/пакеты по 50, полный локальный кэш, собственная SQLite-история,
выбор непросмотренного и закрытый Safari controller. YouTube Music сохранён.

Живая приёмка воспроизведения пока не выполнена: отдельного YouTube API-ключа
и плейлиста в конфигурации нет. Реальные видео, яркость, физический телевизор
и Youtube sleep в этой сессии не запускались. Все проверки HTTP и воспроизведения
используют mocks. Это реализованный код с проверенными контрактами, а не
заявление об уже работающем на телевизоре воспроизведении.

## Что реализовано

- Чтение `playlists.list`, всех страниц `playlistItems.list`, пакетного `videos.list`.
  Получение ID, названий, каналов, длительности, позиции, доступности и канонического URL.
  Search API и неофициальные способы обхода ограничений не применяются.
- Отдельные `YOUTUBE_API_KEY`, `YOUTUBE_SLEEP_PLAYLIST_URL`, `YOUTUBE_CACHE_TTL`.
  Ключ имеет тип SecretStr и передаётся заголовком, не в URL. Ключ Gemini не подставляется.
- Подключение ссылкой/текущим плейлистом Safari, список/счётчик/принудительное обновление.
  Модель не может заменить распознанные параметры своей догадкой.
- Таблицы `youtube_playlist_cache`, `youtube_video_history`, отдельные preferences.
  Все шесть статусов из задания, достоверный прогресс, число/время запусков,
  источник/дата обновления и ручные метки. История аккаунта YouTube недоступна и не удаляется.
- Приоритет `unwatched`, случайный/последовательный/длинный/короткий выбор,
  диапазон длительности, канал, исключение недавних запусков, явное разрешение повторов.
  Отсутствие кандидатов не снимает фильтры молча. Отрицательная команда про вчера
  меняет фильтр следующих выборов и сама ничего не запускает.
- Один инструмент `youtube_sleep` в существующей группе media и адресном Mac Agent.
  Общий текстовый/голосовой маршрут; авторизация, grants и проверка текущего intent.
  Массовый reset — свежий код, привязанный к устройству, сессии, плейлисту и версии истории.
- Safari: только фиксированные скрипты, проверенные ID, окно/вкладка/страница; одно
  подходящее окно переиспользуется, неоднозначность даёт отказ. Посторонние вкладки
  не закрываются. HTTP/открытие URL/реклама не считаются подтверждённым стартом.
- Пауза, продолжение, состояние/остаток; проверка результата плеером. Обычный Autoplay
  выключается; если результат не подтверждён, успех не объявляется. Автоочереди нет.
- Выбор телевизора по текущему UUID через NSScreen/CGDisplay, проверка bounds;
  полноэкранный режим при однозначном AX-соответствии. При отключении TV — явный
  fallback на текущий экран. Окно с посторонними вкладками не перемещается.
- Старый «Я спать» по умолчанию сохранён: 10% → 25% → существующий Youtube sleep.
  Опциональный `night_autoplay: true`: выбор/проверка одного ролика перед наблюдателем,
  проверка активности Safari и журнал против повторов. Ошибка ролика не запускает
  наблюдатель. Пока он мог работать, отдельная замена видео блокируется.
- Кэш TTL, ограниченные повторы/общее время/число запросов; cooldown квоты,
  stale fallback только для временных ошибок. Авторизация/конфигурация не скрываются.
  Логируются метод и счётчики, HTTPX URL с ID плейлистов подавлены.
- Атомарное сохранение выбранного ролика, счётчика и результата. Для этого
  `MemoryStore.set_preference` использует существующий вложенный transaction context:
  он больше не завершает чужую внешнюю транзакцию. Ошибка после открытия ролика
  честно сообщает о возможном воспроизведении и не вызывает автоматический повтор.

## Ручные действия и ограничения

Полная инструкция: [CHUSHPAN_YOUTUBE_API.md](CHUSHPAN_YOUTUBE_API.md).
Нужно включить API, создать отдельный ограниченный ключ, добавить ключ/ссылку
в существующий `.env`, перезапустить ассистента и проверить список. Затем осознанно
проверить реальный Play/паузу/TV, историю после рестарта и ночную команду.
Настройки ключа в Google Cloud не проверялись: ключ ещё не создан/передан проекту.

Поддержан Safari. Chrome/другой браузер, YouTube account watch history, приватные
OAuth-плейлисты, автоматическое включение физического телевизора и автоматический
переход между роликами не реализованы. Для приватного списка понадобится отдельный
OAuth readonly поток; публичный/доступный по ссылке путь полностью подготовлен.
DOM/Autoplay/реклама/consent могут помешать проверке плеера; без доказательства
запуск не засчитывается. Полный экран/перенос проверены только на контракте и
компиляции, физическая проверка обязательна.

Старый Youtube sleep следит за **активной** вкладкой, включая последующие ручные
переключения. Исправление этого ограничения потребовало бы согласованного изменения
самого Shortcut; оно не делалось. Неподтверждённые/частичные ночные шаги не повторяются
автоматически; ручной reset журнала допустим только после остановки команды.

Найденное существующее ограничение хранения секретов: `.env` имеет режим 0644.
Его содержимое и права в этом этапе сохранены. При добавлении YouTube-ключа стоит
ограничить чтение владельцем (`chmod 600 .env` из корня проекта).

# Ночная команда и восстановление голосового цикла

## Причины, найденные в коде

1. Локальная маршрутизация night_mode уже существовала перед Gemini, но её
   список не включал «включи режим сна» и «запусти ночной режим». Очистка
   обращения не принимала точку после имени (Whisper действительно выдавал
   «Эй, Чушпан. …» в предыдущей проверке). В спящем состоянии строгая проверка
   wake-word «эй чушпан» также не принимала ночную команду с одним «Чушпан».
   В результате команда не попадала в локальный маршрут, а модель могла
   попытаться вызвать действие, для которого исходный текст не проходил intent.
2. На ожидание STT и полный голосовой запрос не было верхней границы времени.
   Незавершённая wake_task исключала проверку следующих обращений; незавершённая
   основная task оставляла THINKING/SPEAKING, где при barge_in=false кадры
   намеренно игнорируются. Ошибка VAD могла завершить основной цикл.
   Callback старой задачи мог также сбросить состояние новой. В TTS загрузка
   модели могла упасть после установки _speaking=True, а ошибка плеера обходила
   сброс флага. Это воспроизводимые дефекты кода; точный исторический сбой
   пользовательского сеанса без его трассировки установить нельзя.

## Исправления

- backend/night.py: точный список команд и распознавание адресованной ночной
  команды с пунктуацией STT. Поддерживаются все четыре запрошенные формы,
  а также остаток после удаления wake-word. Обычное упоминание сна не подходит.
- backend/brain/conversation.py: существующий локальный маршрут, логи диспетчеризации
  и таймаут 120 с. Эти команды не передаются Gemini.
- backend/voice.py: адресованная ночная команда активирует существующий путь;
  STT ограничен 20 с, голосовой запрос/оповещение — 180 с; ошибки и отмена
  освобождают состояние через завершение задачи. Callback проверяет владельца
  текущей задачи. Ошибки кадров перехватываются со сбросом VAD/сегментатора.
- backend/audio/stt.py: отмена ожидания не ставит повторные вызовы в очередь
  за ещё работающим нативным STT. Поток MLX не завершается принудительно:
  при зависании самого нативного GPU-кода может потребоваться перезапуск.
- backend/audio/tts.py: флаг _speaking устанавливается после загрузки и
  сбрасывается в finally, отмена/ошибка останавливает воспроизведение.
- backend/audio/capture.py: при отсутствии кадров 10 с аудиопоток переоткрывается;
  цифровая тишина отличается от отсутствия кадров и проверяется SilenceWatch.

Логи: WAKE_DETECTED, RECORDING, STT_RESULT, COMMAND_MATCH, COMMAND_START,
COMMAND_END, LISTENING_RESUMED, ERROR. STT_RESULT содержит длину и признак
ночного запроса, без полного текста разговоров. COMMAND_END означает завершение
попытки, а не гарантированный успех; результат действия сообщается отдельно.

Сценарий не дублирован: остаются существующие выбор непросмотренного видео,
Safari/телевизор, уровни 10%/25%/30% и Youtube sleep. Отдельный встроенный таймер
YouTube этот код не устанавливает: окончание видео ожидает существующий Shortcut.
Сохранены проверка разрешений, allowlist и подтверждение свежим кодом,
а также блокировка/журнал повторных запусков. После таймаута действие не повторяется
автоматически; нужно проверить журнал и фактическое состояние.

## Ручная проверка

```bash
cd ~/my-jarvis
uv run python -m backend voice --no-briefing
```

Проверить четыре фразы. Должны появиться COMMAND_MATCH night_mode и запрос
подтверждения существующего сценария. Чтобы не менять настройки Mac, код не
подтверждать. Для реального запуска осознанно подтвердить код; проверки
разрешений могут заблокировать запуск с отдельным объяснением.
После ошибки или таймаута сказать «Эй Чушпан, какая погода?» и проверить
LISTENING_RESUMED / WAKE_DETECTED. Не запускать параллельно второй экземпляр.

Автотесты используют подставные STT/TTS/инструменты: реальный ночной сценарий,
видео, яркость, громкость и сон Mac не выполнялись. .env, ключи, память,
модель голоса и существующая Youtube sleep не изменялись. Commit/push нет.

Итоговые проверки: 923 passed без предупреждений; Ruff check и format --check
прошли (148 Python-файлов); git diff --check прошёл. Добавлены проверки всех
ночных фраз, локальной маршрутизации без Gemini, сохранения подтверждения,
восстановления после ошибок/таймаутов STT, ответа и TTS, устаревшего callback,
ошибки VAD и переоткрытия микрофона без реальной записи.

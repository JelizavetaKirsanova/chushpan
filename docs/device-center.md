# Центр устройств

Раздел «Устройства» использует существующие `Devices`, `ToolRegistry`, WebSocket HUD,
приватную SQLite и менеджер мест сценариев. Устройства из визуального референса не
создаются. При запуске импортируется только реально настроенная техника и этот Mac;
её доступность и физическое состояние до отдельной проверки остаются неизвестными.

## Графический интерфейс

- Строка поиска фильтрует устройства по названию, комнате и синонимам; Enter отправляет
  текст через существующий чат, кнопка микрофона использует существующий голосовой UX.
- Фильтры мест, избранное, раскрываемые комнаты и группы строятся из общего реестра.
- Выбор карточки меняет панель возможностей; при ширине окна до 1190 px она открывается
  отдельным модальным окном. Есть Escape, возврат фокуса и reduced-motion.
- Вкладки: управление, настройки, история последних 30 команд центра устройств.
- Настройки сохраняют название, место, комнату, голосовые синонимы, избранное и
  опциональную проверку соединения при открытии карточки. Фонового сканирования нет.
- Отдельные окна: поиск среди зарегистрированных устройств, четырёхшаговый мастер,
  выбор местоположения, редакторы профилей/комнат/групп, аудиовывод и AirPlay.

Мастер не запускает поиск при открытии. Поиск и проверка соединения включаются
пользовательницей; ожидание можно отменить. Поздние ответы отменённого поиска не
заменяют результаты нового. Найденное устройство не считается управляемым:
совместимость проверяется отдельно, а состояние появляется только после чтения.
Сохранение непроверенного устройства помечено явно и не выполняет команд питания.

## Поддерживаемые адаптеры

**ELK-BLEDOB / BLE.** Сохранён существующий протокол, профиль GATT FFF0/FFF3/FFF4,
защита прошивки и локальное подтверждение тестов функций. Обычные RGB, питание,
яркость и цветовые пресеты доступны согласно подтверждённым возможностям конкретного
контроллера. Неизвестные команды не отправляются. Связь устанавливается не более двух
раз до записи; после начала записи автоматического повтора нет. BLE/GATT не сообщает
физические питание/цвет/яркость: отправленные значения хранятся отдельно от `state`.
Тёплый белый — только явно подписанная RGB-имитация, отдельный белый канал не заявлен.

**Mac / BetterDisplay.** Сохраняются существующие инструменты громкости, яркости,
плеера, батареи, блокировки с подтверждением и яркости внешнего дисплея. Питание,
входы и громкость телевизора не добавляются без соответствующего адаптера.

**CoreAudio.** Публичный нативный помощник читает доступные аудиовыходы, их стабильные
UID и текущий default output. Смена выхода считается успешной только после обратного
чтения `kAudioHardwarePropertyDefaultOutputDevice`. Bluetooth-устройства и AirPlay
появляются здесь, когда macOS предоставляет их как аудиовыходы. Команда «Верни звук
на Mac» выбирает только единственный реально найденный встроенный выход; при
неоднозначности требуется выбор в меню. Аудио конкретного приложения может иметь
собственный маршрут, независимый от системного выхода.

**AirPlay / Bonjour.** `NWBrowser` ищет `_airplay._tcp` и `_raop._tcp` в `local.` только
по запросу. Поиск не подключает приёмники и не запускает музыку. Для не опубликованного
в CoreAudio приёмника открываются системные настройки звука с инструкцией. Для
зеркалирования отдельно открываются настройки дисплеев. Завершение AirPlay-аудио —
выбор встроенного выхода Mac. Прямой пульт приёмника, его громкость, автоматическое
спаривание, отправка произвольного видео и управление зеркалированием не реализованы:
поддерживаемого универсального адаптера для них здесь нет. Кнопки Mac управляют
медиаплеером Mac и не изображают управление самим приёмником. Статус трансляции
из Bonjour не выводится.

**Локальный HTTP / WLED.** Ручное добавление по IP частной сети, проверка `/json`,
питание, абсолютная яркость и RGB главного сегмента через документированный JSON API.
После записи читается состояние и сравнивается с запросом. Если ответ потерян,
результат остаётся неизвестным; повторная запись не выполняется. Произвольные URL,
порты, публичные/служебные адреса, перенаправления и учётные данные не принимаются.
Bonjour-поиск WLED и универсальное управление любым HTTP-устройством не заявлены.
Другие системы умного дома требуют собственного проверенного адаптера.

## Голос, группы и сценарии

`device_command` регистрируется в существующем ToolRegistry с разрешением
`mac.system`; неизвестные ID не принимаются. Точные названия и синонимы разбираются
локально без LLM. Составные действия со светом используют существующий `compile_plan`.
При неоднозначности требуется уточнение; другой профиль не разрешает удалённое
управление без реального канала. Общая команда группы возвращает результат каждого
участника и частичные ошибки. Ошибка одного устройства не означает успех остальных.

Редактор сценариев получает действия устройств и групп из того же реестра:
включение/выключение, RGB, поддерживаемые яркость и громкость, плеер Mac, выбор
аудиовыхода, открытие системного AirPlay и проверка доступности. ID цели фиксирован
в определении возможности и не подменяется параметром блока. Используются существующие
последовательности, параллельные ветки, условия и задержки; асинхронный вызов ожидается
до получения результата. Отправка BLE остаётся `sent`, подтверждение WLED/CoreAudio —
`confirmed`. Частичная ошибка останавливает обязательный шаг по правилам движка.

Местоположения общие с редактором сценариев. Ручной выбор сохраняется и имеет
приоритет; автоопределение использует существующие разрешения, свежие наблюдения и
явные привязки. Переключатель режима сам не запрашивает геолокацию. При неизвестном
месте локальное устройство другого профиля заблокировано. «Общее» не является
доказательством сетевой доступности.

## Хранение и диагностика

Аддитивная миграция версии 2 создаёт комнаты, группы и ограниченный журнал команд
рядом с существующим `device_registry`; старые JSON-записи получают значения по
умолчанию. Метаданные используют optimistic revision, проверку дублей и стабильные ID.
Удаление устройства очищает членство в группах; переименование комнаты переносит
назначенные устройства транзакционно. Результаты не изменяют ревизию метаданных.

Конфигурация, результаты и история находятся только в приватной SQLite. Новые адаптеры
не принимают секреты и не сохраняют их в БД или Git. Интеграция с аутентификацией пока
не добавлена; при её появлении секреты должны храниться в существующем Keychain.
Запросы имеют тайм-ауты и отмену; повтор одного ID команды не повторяет отправку.

В статистику добавлены подписи этапов поиска, соединения, отправки, подтверждения и
выполнения. Существующие трассы BLE сохранены. Число в карточке — длительность
последней команды центра, а не измерение голосовой задержки или аппаратной реакции.

Необходимы разрешения Bluetooth для BLE и локальной сети для Bonjour/HTTP, где macOS
их запрашивает. Геолокация нужна только для включённого автоопределения, микрофон —
для явно включённого голоса. Apple Events/Accessibility требуются только отдельным
существующим медиаплеерам и интеграциям; CoreAudio их не требует. Кнопка разрешений
ведёт в существующие настройки Чушпана с системными переходами.

## Проверка

Автотесты подменяют BLE, HTTP, Bonjour и CoreAudio, не сканируют сеть и не записывают
микрофон. Проверены SQLite, миграции, дубли, группы, частичные ошибки, идемпотентность,
отмена, местоположение, голос без LLM, реальное выполнение блока сценария на
подменённом BLE и согласование ответа с HUD. Нативный Swift-помощник компилируется
без запуска. Визуальная проверка в браузере выполнена на изолированных тестовых
данных, включая ширину 900 px и мастер подключения.

Физические LED/Bluetooth/AirPlay, TCC установленной `.app`, звук и сетевые WLED требуют
отдельной ручной проверки с разрешения пользовательницы. Сборка frontend выполнена;
установленная копия `.app` этим изменением не заменяется. Помощник `devices` включён
в штатную macOS-сборку и PyInstaller manifest.

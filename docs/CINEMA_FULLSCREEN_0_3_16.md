# Чушпан 0.3.16: полноэкранный просмотр и универсальные сценарии

Проверка 8 ноября 2026 года выполняется на `/Applications/Чушпан.app`. Успешным запуском считается соответствие произведения, сезона, серии, дорожки, полного хронометража и рост времени самого плеера. Загрузка страницы и отправка команды Play отдельно успехом не считаются. Для междоменного iframe время читается через доступный таймер Safari Accessibility, а не выдаётся за прямое чтение HTMLMediaElement.currentTime.

## Исправления

- Порядок запуска: точная страница → сезон/серия → озвучка → Play → восстановление позиции → подтверждение движения времени → полный экран видео. Для HTML5 используется доступный Fullscreen API, для проверенного iframe — семантические AX-кнопки, их подсказки и штатные клавиши плеера с проверкой фокуса.
- Полный экран подтверждается API для выбранного iframe или HTML5-видео. Полноэкранное окно Safari, body/html и просто отправленная команда не подтверждают результат. Кнопки проверяются по роли, подписи, принадлежности помеченной странице/iframe и попаданию указателя; случайные координаты не используются.
- В настройках медиатеки есть автоматический полный экран (по умолчанию включён), продолжение с позиции (включено) и отдельный автопереход к следующей серии (по умолчанию выключен).
- Выход из полного экрана сохраняет воспроизведение. После выбора следующей серии Чушпан восстанавливает её собственную позицию и повторяет проверку полного экрана. Обнаружение автоперехода сайта требует его явного обратного отсчёта, соседнего номера серии, прежней озвучки и двух последовательных показаний нового таймера; время новой серии не записывается в предыдущую.
- Сохранённый рабочий сценарий имеет приоритет. Kinogo поддерживает внутренний поиск точных страниц и отдельный адаптер структуры страницы; метаданные обнаружения и проверка видео разделены. Добавлены общие шаблоны сайта/плеера и управление ими. Сценарии содержат данные, а не произвольный пользовательский JavaScript.
- Исправлены переходы состояний обычного просмотра, повторные попытки разных плееров и отмена поиска. Ошибка восстановления не затирает сохранённую позицию. Автоматическое чтение ключа поиска не вызывает системный диалог авторизации Keychain.
- При повторном запуске Venom кнопка Play сначала не имела AX-подписи; нажатие середины iframe не запускало видео. Теперь адаптер наводится на реальные кнопки и распознаёт подсказку «Смотреть (пробел)», затем подтверждает полный таймер и его движение. При отсутствии полной длительности диагностика сообщает о незагруженном видео отдельно от остановившегося таймера.
- Меню озвучек читается после загрузки видео, с ожиданием динамических пунктов. Верхние элементы iframe прокручиваются ниже фактической закреплённой шапки сайта, нижние кнопки — в видимую нижнюю область. Защита от кликов через перекрывающие панели сохранена.

## Accessibility и подпись

Причина прежнего отказа: TCC сопоставляла разрешение ответственного процесса `ee.chushpan.desktop` со старым CDHash ad hoc подписи. Нативный исполнитель `local.chushpan.ytmusic-ax` запускался внутри установленного пакета; разрешение отдельного файла не исправляло несовпадение основного приложения.

Для последующих локальных обновлений настроена одна постоянная идентичность Code Signing. У основного приложения и помощников один сертификат; designated requirement основного приложения привязан к `ee.chushpan.desktop` и сертификату, а не к меняющемуся CDHash. Сборщик проверяет сохранённую идентичность и прекращает сборку, если она недоступна. Начальный переход на сертификат потребовал одобренного пользователем штатного обновления одной записи Accessibility; последующие обновления 29 → 30 → 31 → 32 → 33 сохранили доступ без повторного запроса.

Это локальная подпись для этого Mac, не Developer ID и не нотариализация Apple. TCC.db и SIP не изменялись, отдельное разрешение помощнику не потребовалось. Центр разрешений выполняет свежую проверку AX API и показывает фактическую цепочку процессов, идентификаторы, пути, доверие и необходимость перезапуска.

## Реальная проверка установленной сборки 32

Положительные просмотры начинались кнопкой карточки в интерфейсе установленного приложения. Для сохранности личной истории использовалась изолированная проверочная медиатека того же пакета, без подмены адаптера. Настоящие Safari, сетевые страницы и видеоплееры использовались во всех перечисленных просмотрах.

- «Последнее королевство», S01E01, LostFilm: `https://kinogo.online/serialy/33039-poslednee-korolevstvo.html`. Полная длительность 59:02; восстановление 30:00 подтверждено на 30:02 → 30:09, затем Fullscreen API подтвердил именно iframe.
- Переход S01E01 → S01E02: через управление установленного приложения первая серия перемотана к концу; после обратного отсчёта сайта Чушпан выбрал вторую серию, восстановил её сохранённые 0:43 и подтвердил 0:46 → 0:54 из 58:42, LostFilm, полный экран. Полные 59 минут не просматривались.
- «Во все тяжкие», S01E01, LostFilm: `https://kinogo.online/serialy/35536-vo-vse-tjazhkie.html`. Страница найдена внутренним поиском, хронометраж 58:06, рост 0:01 → 0:09, полный экран подтверждён API. Выход сохранил рост 0:09 → 0:11; повторное включение подтверждено.
- «Рэкетир 2»: `https://kinogo.online/filmy/17749-rjeketir-2.html`. Страница найдена автоматически, полная длительность 1:51:52, рост 0:01 → 0:07. Фактическая дорожка «Оригинал», отсутствие LostFilm явно сообщено. Полный экран, выход с ростом 0:07 → 0:10 и повторное включение подтверждены.
- Сборка 30 отдельно прошла полное завершение через ⌘Q во время просмотра S01E01, сохранение 31:01 и запуск из /Applications с восстановлением около 31:03 → 31:10 и полным экраном. Видеоплеер также визуально занимал весь физический экран без панели Safari.

Повторный запуск S01E02 и переключение озвучки в сборке 32 не всегда проходили: встречались незагруженная полная длительность и безопасно отклонённые клики по перекрытому меню. Эти случаи не признаны успехом; для них внесены описанные выше дополнительные исправления. Принудительный выбор несовместимого «Плеера 3» также не дал успешного автоматического восстановления; ограничение запасных источников сохраняется.

## Повторная проверка сборки 33

Установлена чистая сборка коммита `1b6656ed65cb490b76c18abd76480a02c87ac46c`. Глубокая строгая проверка подписи пройдена. Свежий помощник, запущенный установленным worker, вернул обе проверки AX-доверия true и AXError 0; перезапуск или отдельное разрешение помощнику не требуются.

Из карточки в интерфейсе вновь запущена S01E02 с сохранённых 4:14. Подтверждены LostFilm, полная длительность 58:42, рост 4:16 → 4:23 и полный экран выбранного iframe. Смена озвучки в установленном контексте всё ещё получала безопасный отказ попадания по элементу, хотя в диагностическом запуске проходила. Этот результат не признан успехом.

Дополнительно обнаружено, что AX-дерево может возвращать элементы поверх видео до их доступности для указателя. Добавлено ограниченное ожидание того же элемента после отказа попадания: путь и все подтверждённые поля проверяются заново, а нативная проверка попадания обязательна для каждой попытки. Изменившийся элемент не нажимается. Это проверено отдельными регрессионными тестами.

Установлена 0.3.16 (34), исходный коммит `0633a55bffa3e5544c733fce9cf772795381bdef`. Подпись проверена глубоко и строго; предыдущая версия сохранена установщиком для отката. Свежая проверка внутри установленного worker: обе проверки доверия true, AXError 0, отдельное разрешение помощнику и новый запрос Accessibility не нужны.

Скриншот дополнительно подтвердил, что сам видеоплеер занимает физический экран без панелей Safari; виден кадр сериала.

## Вкладки, данные и проверки

Исходное состояние Safari в проверке сборки 32: четыре пользовательских окна и 21 вкладка. После каждого из десяти последовательных неудачных поисков список окон, URL и порядок вкладок точно совпал с исходным; ни одной служебной вкладки не осталось. Отдельная отмена поиска в процессе также вернула IDLE и исходные окна/вкладки. После положительных просмотров собственная видеовкладка закрывалась. Наблюдение сразу во время закрытия иногда получало временную ошибку Apple Events; повторная проверка подтверждала полную очистку.

Контрольные хеши шести личных таблиц (произведения, серии, медиатека, история, метаданные и ссылки) до изменений и после проверки сборки 32 совпали. Проверочные позиции и результаты поиска записывались только в отдельный локальный профиль. Фиолетовый интерфейс и личная медиатека сохранены.

Автоматические проверки: 264 теста Python медиатеки, 195 тестов интерфейса, TypeScript, сборка интерфейса, Ruff и форматирование. Эти результаты не заменяют реальные проверки видео выше. Сетевые проверки относятся к текущему подключению этого Mac и настройке региона EE; географическое положение внешнего IP независимо не подтверждено.

Отдельная Playwright-проверка точного URL «Последнего королевства» в изолированном Chromium получила HTTP 403 за 0,9 с. Полный JSON-отчёт и скриншот сохранены вне исходников. Плеер и рост currentTime в этом сеансе не подтверждены; защита не обходилась. Это отличается от успешного просмотра через текущий пользовательский Safari и не означает отсутствия произведения.

Поддержка всех сайтов не заявляется. Не проверены все возможные плееры и озвучки, HTTP 403 и сетевой тайм-аут не воспроизводились отдельными управляемыми внешними сценариями в финальной сборке. DRM, CAPTCHA, авторизация и ограничения доступа не обходятся. Playwright служит отдельной диагностикой; при обычном совместимом просмотре используется существующий Safari/AX без запуска тяжёлого дополнительного браузера.

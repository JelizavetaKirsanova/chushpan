# Чушпан 0.3.16 (37): полноэкранный просмотр и проверка воспроизведения

Проверено 8 ноября 2026 года на `/Applications/Чушпан.app`, исходный коммит `3da12292a23f271628f03d4f176e188a281ce73e`. Приложение собрано и установлено штатным `scripts.update_macos`; строгая глубокая проверка подписи и проверки установщика пройдены. Предыдущий пакет сохранён установщиком для отката.

Успех означает совпадение произведения, сезона, серии, дорожки, полного хронометража и движение таймера видео. Открытие страницы отдельно успехом не считается. Для междоменного iframe показания читаются через Safari Accessibility; это не прямое чтение `HTMLMediaElement.currentTime` внутри чужого origin. Основные положительные просмотры начинались кнопками карточек установленного приложения. Для сохранности личной истории использована отдельная проверочная медиатека того же установленного пакета.

## Найденные причины и исправления

**Accessibility.** TCC сопоставляла разрешение ответственного процесса `ee.chushpan.desktop` со старым CDHash подписи ad hoc. Нативный помощник `local.chushpan.ytmusic-ax` запускался внутри приложения; отдельное разрешение помощнику не исправляло идентичность основного процесса. Теперь приложение и помощники подписываются одной постоянной локальной идентичностью Code Signing, а designated requirement привязан к bundle identifier и сертификату. Сборщик прекращает сборку, если настроенная идентичность недоступна. Одобренное пользователем штатное обновление разрешения потребовалось при переходе на сертификат; обновления 29 → 37 сохранили разрешение без новых запросов.

В сборке 37 свежая проверка из установленного worker подтвердила обе проверки AX-доверия `true`, чтение `AXWindows` с AXError `0`, отсутствие необходимости перезапуска и отдельного разрешения помощнику. Worker — `/Applications/Чушпан.app/Contents/MacOS/Chushpan`, помощник — `Contents/Frameworks/native/ytmusic_ax`; `Resources/native` ссылается на него. В этой цепочке нет внешнего Python, shell или компиляции Swift при просмотре. Центр разрешений показывает идентификаторы, пути, подписи, родителя процесса и результат настоящей проверки API. Это локальная подпись этого Mac, не Developer ID и не нотариализация Apple; TCC.db и SIP не изменялись.

**Safari fullscreen.** Видео может находиться в отдельном AX-диалоге и пространстве macOS. После возврата к окну Чушпана Safari иногда предоставляет только стандартное окно с панелью «Нажмите для выхода из полноэкранного режима», без AX-дерева видеоплеера. Раньше снимки просматривали все окна, а действия искали плеер лишь в сфокусированном окне. Команды перемотки и выбора озвучки теряли доступ к реальным элементам.

Теперь помощник ищет единственное окно с точным URL, помеченным уникальным ID сеанса, и работает только с его выбранным iframe. Если Safari скрывает полноэкранное дерево, адаптер использует штатный выход из fullscreen. Резервное нажатие панели разрешено только при точном совпадении URL в адресной строке, единственной штатной подписи, проверенной геометрии и попадании указателя в найденный элемент. Случайные координаты не используются. После действия плеер повторно проверяется и fullscreen восстанавливается; неудача восстановления явно сообщается.

**Порядок и интерфейс.** Запуск выполняется в порядке: точная страница → сезон/серия → дорожка → Play → сохранённая позиция → движение таймера → fullscreen. Полноэкранное состояние подтверждается API выбранного iframe или HTML5-видео; полноэкранное окно Safari и растянутый `body` успехом не считаются. Поддерживаются стандартный HTML5 API и проверенные обычные кнопки/клавиши доступного плеера. Неподписанная Play-кнопка распознаётся по появляющейся подсказке после наведения на сам элемент.

Исправлены сохранность введённого таймкода при фоновых обновлениях, возврат селектора к подтверждённой дорожке после ошибки и свежий замер позиции перед закрытием фонового плеера. Ошибка восстановления не затирает прежний прогресс. В настройках есть автоматический fullscreen и продолжение с позиции (включены по умолчанию), отдельный автопереход (по умолчанию выключен). Фиолетовый дизайн сохранён.

## Вкладки, данные и диагностика

В сборке 32 десять последовательных реальных поисков отсутствующего произведения и отдельная отмена вернули точные исходные 4 окна и 21 вкладку. В сборке 37 после закрытия S01E02 служебных вкладок осталось 0, число пользовательских окон и вкладок сохранилось. Строгое сравнение с более ранним снимком заметило изменения адресов в пользовательском окне, поэтому этот конкретный замер не выдан за полное совпадение URL. Их причина не устанавливалась и адреса не восстанавливались. Исходный снимок сохранён отдельно; перед последующими просмотрами зафиксирован новый контрольный снимок. После другого сериала и фильма полное сравнение с ним прошло. Пользовательские вкладки не закрывались слепыми Cmd+W.

Контрольные хеши шести личных таблиц до работы и после всех проверок 37 совпали, включая чтение актуального состояния WAL. Все тестовые позиции, дорожки и оценки остаются в отдельном профиле. Микрофон во время проверок выключен. В конце запущен обычный личный профиль из `/Applications`: в интерфейсе подтверждена прежняя позиция пользователя 17:52 для S01E02; проверочная медиатека больше не открыта.

Отдельная Playwright-диагностика точной страницы сериала в изолированном Chromium получила HTTP 403 за 0,9 с. Плеер и движение currentTime в этом сеансе не подтверждены. Это отличается от успешного пользовательского Safari и не доказывает отсутствия произведения. Отчёт JSON и скриншот сохранены локально; защита не обходилась. Сетевые результаты относятся к текущему подключению Mac и настройке EE; географическое положение внешнего IP независимо не подтверждено.

Автоматические проверки: **274 теста Python медиатеки**, **196 тестов интерфейса**, TypeScript, сборка интерфейса, Ruff, форматирование, компиляция Swift и `git diff --check`. Интерфейс не менялся после этих 196 тестов. Эти проверки отдельно от реальных видео выше.

Логи и диагностика хранятся в `private/cinema-qa-0.3.16-37-20261108`, исключённом из Git. Полные снимки пользовательских URL в публичный отчёт и исходники не включены. Playwright используется для явной диагностики; обычный просмотр не запускает отдельный тяжёлый браузер.

Поддержка всех сайтов, плееров и озвучек не заявляется. DRM, CAPTCHA, авторизация, платный и региональный доступ не обходятся. Для неизвестного либо несовместимого плеера остаётся ручной выбор/обучение. Управляемые внешние сценарии HTTP 403 и сетевого тайм-аута через установленное приложение в этой сборке отдельно не воспроизводились.

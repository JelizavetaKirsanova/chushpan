# YouTube Music во вкладке Safari

По умолчанию используется `media.youtube_music.transport: safari`.
Основной сервис выбирается через `media.provider: youtube_music` и существующие
настройки интерфейса/SQLite. Spotify сохранён; при ошибке автоматического перехода
на другой сервис нет. Ночной сценарий обычного YouTube и Shortcut `Youtube sleep`
отделены от этого музыкального адаптера.

## Что реализовано и что пока не подтверждено

Python использует нативный Swift-помощник: он сначала проверяет Automation Safari
без показа диалога, затем выполняет AppleScript **в том же процессе**. Проверка
и выполнение больше не разделены между Python ctypes и `osascript`.
Помощник имеет встроенный Info.plist с объяснением запроса Apple Events.
Сборка кэшируется по содержимому Swift и plist в `data/native/`.

Адаптер работает с публичным DOM обычной вкладки `https://music.youtube.com/`.
Cookies, токены, приватные API и `ytmusicapi` в этом режиме не используются.
Прежний Web App адаптер остаётся отдельным совместимым режимом `transport: webapp`.

Проверка 01.11.2026 через установленное `data/Чушпан.app`: после разрешения
пользовательницей Automation Safari получены `automation=granted`, JavaScript
разрешён, вход в YouTube Music выполнен. Настоящий Favourite Songs найден в
библиотеке. Первый Play был отправлен, но за тайм-аут источник не загрузился:
`ready=false`, позиция 0. Это ошибка подтверждения, не успешный запуск.
Позже трек загрузился и стоял на паузе. Однократное продолжение готовой очереди
подтверждено: позиция выросла с 14.17 до 14.95 с, источник очереди совпал с
Favourite Songs, звук плеера включён. Пользовательница ответила «Да, слышно».
Затем полный запуск `music-check --live "Включи Favourite Songs"` из того же
установленного приложения прошёл после исправления открытия вкладки перед
навигацией: `live_ok=true`, `playback_confirmed=true`, код возврата 0.
Полный голосовой запуск со STT после перезапуска приложения отдельно не проверен.

## Безопасная диагностика

Из корня проекта:

```sh
.venv/bin/python -m backend music-check --json
```

Команда не открывает вкладки, не ищет треки, не меняет громкость и не запускает музыку.
`--library` только считает видимые плейлисты на уже открытой странице.
Отчёт содержит PID/PPID и исполняемый файл помощника и Python, состояние Automation,
наличие вкладки, JavaScript, авторизацию и стадии поиска/воспроизведения.
Аргументы процессов, названия треков, адреса страниц и секреты не выводятся.
`tab_found: null` означает, что наличие вкладки ещё не удалось проверить.

В самом работающем приложении скажи:
**«Чушпан, проверь YouTube Music»**.
Это использует его текущий адаптер, не требует Gemini и не запускает музыку.
Отчёт Terminal не подтверждает разрешения отдельного приложения «Чушпан».

## Разрешения и ручное подтверждение

1. Открой Safari и одну вкладку `https://music.youtube.com/`; войди самостоятельно.
2. В работающем Чушпане скажи:
   **«Чушпан, разреши управление YouTube Music»**.
   Это явный запрос Apple Events чтением числа окон Safari, без запуска музыки.
   Подтверди системный диалог.
   Для запуска из Terminal аналогичная явная команда:
   `.venv/bin/python -m backend music-check --request-access --json`.
3. Если ранее отказала: Системные настройки → Конфиденциальность и безопасность →
   Автоматизация → **приложение/процесс, указанный macOS в запросе** → Safari.
   Это может быть Чушпан, Python или приложение запуска; права Terminal автоматически
   не считаются правами приложения. Помощник при каждой операции снова проверяет доступ.
4. Safari → Настройки → Дополнения → включить функции для веб-разработчиков;
   затем Настройки → Разработчик → **Allow JavaScript from Apple Events**.
   В старых версиях Safari переключатель расположен в меню «Разработка».
   См. [настройки разработчика Apple](https://developer.apple.com/documentation/safari-developer-tools/developer-settings).
5. Если получен `autoplay_blocked`: Safari → Настройки → Веб-сайты →
   Автовоспроизведение → music.youtube.com → **Разрешить всё автовоспроизведение**.
   См. [инструкцию Apple](https://support.apple.com/en-euro/guide/safari/ibrw29c6ecf8/mac).
   При необходимости включи звук вручную в плеере и вкладке.
6. Повтори диагностику именно в выбранной среде запуска.

Для этого нового DOM-адаптера не требуются Screen Recording, Accessibility или
Remote Apple Events/общий доступ. Проверки разрешений ночного сценария сохранены отдельно.
Не сбрасывай TCC и не предоставляй права всем приложениям.

## Команды и проверка результата

- «Включи музыку» — продолжает текущую очередь. Если очередь недоступна, просит
  выбрать песню; случайный плейлист вместо неё не назначается.
- «Включи мой плейлист» — использует сохранённый основной плейлист.
- «Включи Favourite Songs», «Включи феврит сонгс», «Включай мой феврит сонгс тогда»,
  «Включи мой любимый плейлист» — разрешают название через настоящую библиотеку.
  Название в конфигурации не считается доказательством существования плейлиста.
- «Давай, включай» после предложения включить Favourite Songs принимает конкретное
  предложение. Проверки сессии, Mac Agent и доступности плейлиста сохраняются.
- «Поставь Нервы», «Включи исполнителя …», «Включи песню …» — поиск в интерфейсе.
  При неоднозначности выдаются варианты; случайный результат не выбирается.
- «Следующий трек», «Предыдущий трек», «Пауза», «Продолжай», «Сделай громче»,
  «Что сейчас играет?» — управление музыкальным плеером.
  «Продолжай» направляется в музыку только при музыкальном контексте.
- При нескольких вкладках Music адаптер просит оставить одну и ничего не закрывает.
  При одной — повторно использует её. При явном запуске музыки может создать одну вкладку.
- Успех запуска требует состояния playing, готового медиа, совпадения выбранного
  названия/исполнителя или плейлиста, отсутствия рекламы и продвижения позиции
  между двумя измерениями. Нулевой/выключенный звук в HTML-плеере — отдельная ошибка.
  Физическую слышимость на выбранном устройстве всё равно проверяет пользователь.
- Открытие сайта, найденный трек и подтверждённое воспроизведение — разные состояния.
  После неподтверждённого запуска идентичная команда не запускает его повторно
  автоматически; проверь плеер, затем перезапусти Чушпана для новой чистой проверки.
- Библиотека/поиск ограничены видимыми результатами; DOM сайта может изменяться.
  Отсутствующий элемент приводит к ошибке, а не к заявлению об успехе.

## Живая проверка — только вручную

После разрешений и авторизации подготовь текущую очередь, затем явно выполни:

```sh
.venv/bin/python -m backend music-check --live "Включи музыку" --json
```

**Эта команда включает звук.** Для поиска можно отдельно использовать
`--live "Включи песню Blinding Lights"`; при неоднозначности сначала уточни
название и исполнителя. Автоматические тесты эти команды не запускают.

Убедись, что слышна нужная музыка и одновременно растёт позиция плеера.
В отчёте ожидаются `live_ok: true`, `playback_confirmed: true`.
Повтори из голосового приложения, затем проверь паузу/продолжение, следующий/
предыдущий трек и отсутствие новых вкладок. Отдельно проверь, что музыкальные
команды не управляют вкладкой ночного обычного YouTube.

## Разбор диалога 01.11.2026, 22:37–22:39 (Europe/Tallinn)

Проверена сохранённая SQLite-история разговора №18, UTC 20:37–20:39.
В 22:37 инструмент вернул пустую **неполную** библиотеку, после чего LLM придумала
наличие основного Favourite Songs. В 22:38 на «Давай, включай» не было вызова
воспроизведения. На «Включай мой феврит сонгс тогда» ответ «Включил» тоже записан
без вызова инструмента. Первопричина ложного успеха — непризнанное намерение и
непривязанное короткое согласие, после которых текст LLM заменял действие.

Живая диагностика выявила дополнительные ошибки DOM: первой выбиралась пустая
ссылка миниатюры с тем же адресом, поэтому настоящий плейлист исчезал из списка;
кнопка `Favourite Songs – воспроизвести` не соответствовала старому шаблону;
загрузка страницы асинхронна. Исправлены выбор текстовой ссылки, точное сопоставление
кнопки с названием и ожидание кнопки. Повтор разрешён только после явного
`play_button_missing`, когда клика точно не было. Неоднозначный сбой Apple Events
не вызывает повторный Play.

При запуске в фоновой вкладке наблюдались неготовый медиаэлемент и позиция 0;
после открытия вкладки медиа загрузилось, но оставалось на паузе. Явная навигация
теперь выбирает именно найденную вкладку Music и выводит её окно перед загрузкой.
После этого полная команда прошла живую проверку. Диагностика состояния вкладки
ничего не переключает. Настройки Safari/автовоспроизведения не изменялись.

В текущем интерфейсе ссылка плеера ведёт на альбом, без ID плейлиста. Подтверждение
плейлиста допускает точное совпадение видимого источника очереди **и** ID открытой
страницы с реально выбранным плейлистом. Одна открытая страница не подтверждает
воспроизведение: дополнительно нужны готовый медиаэлемент и растущая позиция одного
и того же трека. Запрос «Что сейчас играет?» тоже проверяет прогресс чтением.

`music_command` возвращает `execution_status` (`confirmed` или `failed`) и
`execution_events`: `requested`, при доказанной отправке `submitted`, затем
`confirmed` или `failed`. `playback_confirmed` явно указывает результат проверки.
Ошибки и результаты сохраняются существующей системой истории SQLite. Список
плейлистов и результат запуска получают детерминированный ответ, без нового
LLM-ответа, который мог бы придумать успешное выполнение.

## Регрессии и ручная проверка

- Предложи Favourite Songs и ответь «Давай, включай». В истории должен быть
  `music_command`, а не один текстовый ответ. Точное старое предложение и обе
  реплики 22:38 воспроизведены в регрессионном тесте с fake media API.
- Проверь четыре варианта названия выше. Неоднозначный или отсутствующий плейлист
  должен давать выбор/ошибку, без создания нового плейлиста.
- При остановившейся позиции, недоступном источнике, отключённом звуке или рекламе
  успех не объявляется. Проверки отказа Automation/JavaScript/авторизации,
  нескольких вкладок и неподтверждённой отправки покрыты тестами без реальных прав
  и устройств. Для ручной проверки не нужно отзывать уже предоставленные права.
- «Сделай мне светлую розовую ленту» и «Сделай мне светло-розовую ленту» теперь
  разбираются одинаково: RGB `(255, 16, 32)`. Причиной расхождения был разбор двух
  прилагательных, а не разные права. Пакеты и проверки Bluetooth не изменены.
- Сохрани факт через существующее подтверждение с кодом, затем спроси
  «Что ты только что запомнил?». Ответ берёт конкретный ID из успешного результата
  `remember` текущего разговора и читает сохранённый факт. Незавершённое сохранение
  не считается успешным. Проверены перезапуск и изоляция сессий, включая ошибочную
  STT-фразу из 22:39 «Что-то только что запомнил».
- Согласие после предложения не разрешает `assign`, запись памяти или действия
  без доступного Mac Agent. Проверки подтверждения опасных действий сохранены.

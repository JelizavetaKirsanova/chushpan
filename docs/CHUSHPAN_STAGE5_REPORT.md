## Что реализовано

- Расширена прежняя SQLite-память: семь категорий, источник, даты, актуальность,
  confidence, sensitive и revision. Исходные facts/messages/preferences сохранены.
- Локальное извлечение поддержанных явных нечувствительных утверждений текущего
  пользователя; ограниченный релевантный контекст для Gemini и Ollama.
- Просмотр, объяснение источника, исправление, неактуальность, удаление/очистка;
  изменения проходят прежнее подтверждение с привязкой к устройству/сессии.
- Шесть сохраняемых параметров характера поверх прежнего `personality.md`.
- Наблюдение повторов только по отдельному opt-in, одно предложение после трёх
  успешных действий, без создания или самозапуска автоматизаций.
- Детерминированный текстовый/голосовой сценарий «Чушпан, я спать» с BetterDisplay
  и существующим `Youtube sleep`, журналом, защитой от повторов и частичными ошибками.
- План iPhone/iPad заменён на Apple Shortcuts; публичного сервера и портов нет.

## Схема и политика памяти

В существующую `facts` аддитивно добавлены:

- `category`: profile, preference, habit, project, episode, correction, personality.
- `source`: вид источника, request ID и тип устройства, либо legacy_unknown.
- `updated_at`, `confidence`, `status` (active/stale), `sensitive`.
- `semantic_key` для устойчивого слота, например education; `revision` для правок.

`id`, `content`, `created_at` и прежние таблицы не удаляются/не переименовываются.
Значение памяти — прежний `content`. Старым записям не выдумывается источник;
дата обновления первоначально равна дате создания. Confidence отражает уверенность
исходного утверждения, не доказанность факта и не откалиброванную вероятность.

`memory_suppression` содержит хеши удалённого/устаревшего содержимого и слотов,
без копии забытого текста. `preferences` хранит существующую музыку, опцию/счётчики
привычек, границу контекста и журнал/lease ночного сценария в отдельных namespaces.
Параметры характера — записи category=personality в той же facts.

Запись/обновление слотов сериализованы SQLite-транзакцией; несколько изменений
характера либо сохраняются вместе, либо откатываются. Подтверждение правки привязано
к ID/revision/содержимому и сессии. Старые remember/replaces/forget совместимы.

Автоматический разбор намеренно консервативный: поддержаны утверждения об учёбе,
отмене мобильного приложения, именованном проекте и прогрессе, предпочтениях общения,
кофе/чая/объяснений. Проверяются отрицания, неопределённость, вопросы, цитаты,
шутки, многострочный код и признаки чувствительности/секретов. Произвольные
жизненные события не считаются фактами автоматически; для них есть явный remember
с категорией, проверкой и кодом. Это локальные правила, не скрытая LLM-классификация.

В Gemini/Ollama попадают до **6 релевантных нечувствительных записей, до 1600
символов их содержимого**; параметры характера добавляются отдельно. Поиск лексический
с глобальным учётом предпочтения общения и отмены мобильного приложения;
эти ограничения сами по себе не становятся целью команды «забудь это» и не
предлагаются как проекты для продолжения. Содержимое остальных слотов отбирается
по теме. Поддержан конечный набор слотов; последнее явное утверждение слота
обновляет его, более сложные сведения доступны через явное remember.
Поиск работает
с небольшим набором русских словоформ, не векторная семантическая память. История
Gemini по-прежнему ограничена прежними восемью сообщениями текущего разговора.
Явный запрос продолжения выбирает проекты; несколько проектов требуют уточнения.
«Напомни, что мы делали с Gemini» может вернуть до трёх подходящих пользовательских
реплик с датами, без превращения их в факты. Отсутствующий контекст признаётся неизвестным.

Удаление/неактуальность не дают автоматически восстановить факт из прежней истории:
история никогда не разбирается в новые факты; подавление блокирует старые значения,
а граница контекста исключает прежние сообщения из дальнейших LLM-запросов. Это
консервативно сбрасывает и часть полезного старого контекста. Исходная история и
старые экспорты остаются локально, физическое удаление всех копий не обещается.
Явная новая просьба запомнить через код может вернуть намеренно забытый факт.

При недоступной SQLite chat/voice переходят на историю текущей сессии в памяти
с предупреждением: постоянные записи не выдаются за успешные. Изменения профиля,
музыкальных preferences и ночные действия отказываются безопасно. Ночной сценарий
не запускается, если нельзя сохранить журнал до побочных эффектов.

## Характер и привычки

Разумные исходные значения 0–10, близкие прежнему характеру:

- Сарказм 7; мат 3; дерзость 6.
- Болтливость 3; инициативность 2; технические объяснения 7.

«Будь понаглее», «Поменьше мата», «Отвечай короче», «Объясняй программирование
подробнее», «Хватит меня подкалывать» готовят конкретные значения и просят свежий
код. «Сарказм: 5» задаёт точное значение; для остальных доступны русские названия
параметров. «Покажи настройки характера» только читает.

Приоритет: безопасность/достоверность → серьёзность ситуации → текущая просьба →
параметры → базовая личность. Серьёзная тема исключает шутки; 0 мата запрещает мат;
0 сарказма/дерзости убирает подколы. Настройки не меняют STT/TTS/тембр и не обучают веса.
Новая подача проверена на уровне контекста/сохранения; качество всех будущих ответов
LLM и отсутствие каждой неудачной шутки гарантировать нельзя.

Наблюдение привычек исходно выключено. «Можешь замечать мои привычки» + код
включает только счётчики успешных открытий приложений/полного ночного сценария;
не содержимое файлов/экрана, не психологические оценки. На третий успех — не более
одного предложения по действию. «Не замечай мои привычки» + код удаляет счётчики
и выведенные из них привычки, сохраняя явно записанные пользовательницей факты.
Автоматизации не создаются и не активируются.

## Ночной сценарий

Фразы: «Чушпан, я спать», «Чушпан, спокойной ночи», «Чушпан, включи ночной режим»,
«Я пошла спать». Цитата, отрицание и составная непонятная просьба не запускают его.
Распознавание выполняет код до LLM; тот же путь используется после STT.

До любых изменений — описание действий и свежий 90-секундный код, проверка
аутентифицированной device/session, mac.system + mac.shortcuts и адресного Agent.
Простое «да», чужой/просроченный/повторный код не запускают сценарий.

Порядок после подтверждения:

1. Прочитать online-дисплеи CoreGraphics и сопоставить UUID с BetterDisplay.
   Встроенный экран определяется CGDisplayIsBuiltin, не названием/main display.
2. Сохранить предыдущую яркость/статус до изменения; установить встроенному
   **hardwareBrightness=0.10** и перечитать результат.
3. Выбрать только настроенный UUID HISENSE; сохранить общую/доступные компонентные
   значения, задать **brightness=0.25** по общей шкале BetterDisplay, перечитать.
   Другие внешние дисплеи не выбираются даже при отсутствии HISENSE.
4. Проверить точные имя/UUID существующего `Youtube sleep`, записать намерение
   запуска, запустить через фиксированный Shortcuts CLI с очищенным окружением.
5. Коротко сообщить подтверждённые шаги и начало ожидания либо конкретные пропуски.

BetterDisplay **5.2.1 (54014)** реально установлен. Используется его встроенный
официальный CLI, без установки другого приложения и без HTTP/URL-токенов.
Проверки выявили две особенности: get требует PTY, UUID-селектор чувствителен
к регистру. Адаптер ограничивает время/вывод, передаёт UUID в верхнем регистре,
не даёт LLM выбирать произвольные CLI-флаги. [Документация разработчика](https://github.com/waydabber/BetterDisplay/wiki/Integration-features%2C-CLI).

Реальный **read-only** адаптер подтвердил: HISENSE — внешний, Color LCD — встроенный.
Прочитаны общая/аппаратная/программная яркости: HISENSE 0.252/0/0.505,
встроенный 1/0.999/1. Ноль аппаратного чтения сам по себе не доказывает поддержку
DDC. Шкалы различаются: 25% общей яркости нельзя подменять 25% softwareBrightness.
Другие настройки телевизора/HDMI/HDR/громкости не меняются.

В редакторе read-only проверен **Youtube sleep**, UUID
`1646EE92-B628-481D-9499-CED5B05EC32D`: один AppleScript повторно читает `video.ended`
активной вкладки переднего окна Safari, раз в 5 с; после окончания усыпляет Mac.
Скрипт не открывает YouTube и не включает музыку. Он добавлен один в allowlist с
описанием этого эффекта; его содержимое и другие Shortcuts не менялись.

Ожидание запускается отдельно от короткого tool timeout: через ~0,3 с возвращается
статус **начала**, а не завершения видео/сна. Он может продолжать работать после
закрытия ассистента. Если вкладка изменится, поведение определяется исходным скриптом;
если видео нет/оно бесконечное — ожидание может не завершиться. Если видео уже
закончилось, Mac может уснуть до окончания озвучки. Это ограничения существующего
Shortcut, который нельзя было переписывать. Нужны разрешённые Automation Safari/
System Events и доступ JavaScript from Apple Events; автоматически они не включались.

SQLite lease исключает параллельные запуски из двух экземпляров. Журнал сохраняет
done/started/unknown до побочных эффектов; повторная просьба не перезапускает
длительный watcher и не повторяет шаг с неопределённым исходом. Предыдущие значения
сохранены для будущего восстановления; автоматического восстановления сейчас нет.
При отсутствии внешнего экрана/BetterDisplay/Shortcut остальные допустимые шаги
продолжаются; полный успех не объявляется при ошибках. После аварии lease истекает
через 10 минут, но unknown/started в журнале всё равно препятствуют повтору.

## Ручная приёмка

Не поднимай вторую копию voice поверх прежней. Обычный перезапуск пользовательницей
применит код и аддитивную миграцию. Для текстовых проверок из проекта:

```sh
cd ~/my-jarvis
uv run python -m backend chat
```

1. Скажи/напиши «Я учусь в TalTech на IT-разработчика», затем «Что ты обо мне помнишь?».
   Должна появиться одна запись, а не копия каждого сообщения. Запиши её реальный ID.
2. `/quit`, снова `uv run python -m backend chat`, спроси про учёбу: факт должен сохраниться.
3. «Исправь факт НОМЕР: Я теперь учусь на другой программе»; проверь старое/новое
   в описании и введи полученный код. Старое значение не должно сосуществовать как актуальное.
4. «Забудь факт НОМЕР» + свежий код; либо после выбора одного факта — «Забудь это».
   После перезапуска он не должен возвращаться из прежней истории. «Это уже неактуально НОМЕР»
   сохраняет запись в статусе stale; «Очисти память» + код удаляет факты, не музыку/историю.
5. «Отвечай короче» + код; «Покажи настройки характера» до/после перезапуска.
   «Поменьше мата», «Хватит меня подкалывать» и точное «Сарказм: 5» проверяются так же.
6. «Мой проект Чушпан: сейчас проверяем память», затем «Продолжим»/«Напомни, что мы
   делали с Gemini». Ожидай реальный контекст/уточнение/честное отсутствие, не выдуманный прогресс.

Для просмотра без модели:

```sh
uv run python -m backend memory
uv run python -m backend memory show НОМЕР
uv run python -m backend night status
```

7. Для **разрешённой тобой живой** проверки ночи подготовь Mac к возможному сну,
   проверь подключение HISENSE и нужное видео Safari. В работающем обновлённом voice
   скажи «Чушпан, я спать». До кода яркость/Shortcut не должны меняться.
   Только если согласна с описанными действиями, произнеси полученный код.
   Проверь встроенные 10% и общие 25% в BetterDisplay, не сравнивай разные шкалы.
8. В Командах проверь, что запущен именно существующий Youtube sleep с указанным UUID,
   без дубликата. Подтверждение говорит о начале ожидания, не об уже завершённом сне.
9. Для частичного отказа можно самостоятельно отключить HISENSE перед отдельной
   проверкой: внутренний шаг и разрешённый Shortcut должны продолжиться, голос —
   назвать отсутствие внешнего. Повтор не должен создавать ещё один watcher.

Если нужен повтор теста, сначала **сама останови** Youtube sleep в приложении
Команды, проверь состояние Mac. Затем можно сбросить только журнал:

```sh
uv run python -m backend night reset --confirm-stopped
```

Эта CLI-команда сама не меняет яркость и не запускает сценарий. При ещё существующем
сохранённом PID она откажет. Сброс не является отменой уже работающего Shortcut.
При неизвестном состоянии сначала разберись с Командами, затем выдавай новый код.

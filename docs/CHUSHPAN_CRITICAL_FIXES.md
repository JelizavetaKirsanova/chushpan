# Исправления диалога, команд и задержек Чушпана

Аудит и проверки: 1 ноября 2026 года, Europe/Tallinn.
Изменён существующий Python backend. SQLite, personality.md, голосовой цикл,
BetterDisplay, «Я спать», существующий `Youtube sleep` и настроенные модели сохранены.

## Найденные причины

1. `command_text` удалял имя только в начале строки. «Привет, Чушпан. Сделай…»
   оставалось приветствием, а вставка «сделай мне» не проходила точный LED-парсер.
   Запрос уходил к LLM и затем не совпадал с проверкой явного намерения.
2. `followups.SHORT` не содержал «давай открой». Распознавание предложения не
   принимало «Могу просто открыть список твоих плейлистов». Для одиночного
   «открой» даже существующее предложение принудительно отбрасывалось.
3. Незавершённое предложение удалялось в начале каждого нового полного запроса,
   включая запросы, завершившиеся ошибкой.
4. Локальная ветка удаляла всю историю после вызова инструмента и при повторении
   старого ответа моделью. Это уничтожало смысловые уточнения текущего разговора.
5. До отправки локального запроса вычислялся отрицательный бюджет истории:
   16 384 × 2 − длина system − длина схем JSON с `ensure_ascii=True` − резерв.
   На полном реестре: 41 инструмент, system 7941 символ, экранированные схемы
   36 834 символа, бюджет примерно −16 103 символа. Даже короткая история исчезала.
   Проверка локальной Ollama с теми же 41 инструментами показала **6850 токенов**
   полного промпта: прежняя оценка была чрезмерной.
6. Защита от повтора сравнивала начало ответа только со старыми ответами ассистента.
   Повтор текущего пользовательского текста одним большим чанком не отлавливался.
7. Диагностический `latency-check` пересоздавал клиента на каждом повторе и терял
   cooldown отказавшего облачного провайдера. Рабочий голосовой цикл использовал
   один клиент, поэтому прежний benchmark не воспроизводил его жизненный цикл.
8. После перехода на Ollama через резервную цепочку не выполнялся предусмотренный
   фоновый прогрев её контекста: обёртка продолжала считаться только облачной.

## Что изменилось

### Прямые команды и выполнение

Общая нормализация принимает приветствие с именем, «я тебя прошу», вставку «мне»
после глагола и «пожалуйста». Отрицания, цитаты и произвольные вводные не удаляются.
Одинаковая нормализация используется маршрутизатором и проверкой намерения.

Без LLM выполняются:

- «Привет, Чушпан. Сделай ленту светло-розовой» → LED RGB `(255,16,32)`.
- «Я тебя прошу, сделай мне LED-ленту светло-розовой» → тот же LED-инструмент.
- «Включи свет» → проверенное включение LED.
- «Открой YouTube» → новый узкий инструмент `open_website`, только фиксированный
  `https://www.youtube.com`; ответ подтверждает передачу запроса macOS.
- «Поставь яркость 20%» → существующий инструмент яркости Mac. Для ленты по-прежнему
  нужно явно сказать «яркость подсветки/ленты».

Сначала выполняется защищённый инструмент, затем формируется ответ по результату.
Характер не может заменить выполнение репликой «сделай сама». Bluetooth-запись
по-прежнему не выдаётся за подтверждённый физический цвет.

### Ожидающие действия и SQLite

В существующем `dialogue_pending` сохраняются идентификатор предложения,
`source=assistant`, `state=proposed`, исходное предложение, инструмент, точные
аргументы, время создания и срок действия десять минут.

«Да», «давай», «давай, открой», «открой», «сделай», «попробуй» принимают конкретное
предложение. Разрешены только перечисленные в коде операции: чтение плейлистов,
поддерживаемые команды LED и открытие YouTube. Голосовой ответ без нового обращения
допускается только при существующей активной сессии и прежних акустических проверках.
После истечения голосовой сессии нужно снова обратиться к Чушпану; предложение
в SQLite при этом может оставаться действующим.

Права устройства, авторизация и Mac Agent проверяются заново. Контекстное «да»
не разрешает удаление файлов, смену настроек безопасности, произвольный URL или
опасные системные действия. Для опасных действий сохранён свежий код подтверждения.
Автоматические заметки таймеров не создают новое предложение действия.

Принятие предложения атомарно забирает его из SQLite, поэтому два одновременных
«давай» не запускают его дважды. Ошибочное чтение может предложить явную повторную
попытку; запись Bluetooth автоматически не повторяется. «Не надо» отменяет
предложение. Новая неоднозначная альтернатива или явное «сменим тему» сбрасывает
его; обычная команда или ошибка в том же разговоре не стирает предложение.

Пользовательская реплика, assistant tool call, результат инструмента, итоговый
ответ и новое предложение сохраняются одной транзакцией. Роли, аргументы и
результаты остаются в SQLite; редактируется только копия для отправки модели.
Обработка исключения не записывает один STT-текст повторно.

Сессия привязана к conversation ID, а сообщения — к device/session/request ID.
Проверено восстановление предложения и истории после закрытия БД и нового
экземпляра Conversation, включая доверенный контекст iPhone с тем же серверным
session ID. Другие сессии не получают чужую историю или ожидающее действие.

Важная граница: рабочий мобильный endpoint, pairing и токены iPhone в этом
репозитории ранее не были реализованы; они описаны как будущий этап в
`CHUSHPAN_SHORTCUTS.md`. Этот аудит сохраняет совместимость внутреннего API и
не открывает HUD в сеть. Передача с реального iPhone по HTTP здесь не заявляется
проверенной или реализованной.

### История и характер

История остаётся в контексте после инструмента и при повторной генерации после
обнаруженного эха. Повтор пользовательского текста не озвучивается; модель получает
короткое указание ответить на смысл с сохранением уточнений.

Перед отправкой в Ollama применяется отдельный бюджет из компактного UTF-8 JSON.
Оценка «четыре байта на токен» — приближение с резервом 2048 токенов, а не настоящий
токенизатор. При переполнении убираются старые завершённые реплики; system и текущая
цепочка вызовов инструментов сохраняются. Тот же путь работает при резервном
переходе с Gemini на Ollama и прогреве. Полный реестр инструментов не урезан.

`personality.md` не изменён. В общем промпте закреплены выполнение разрешённой
команды перед шуткой, реальная причина ошибки и запрет повторять STT, добавлять
погоду, события, личные факты и случайные прозвища без оснований.

### Bluetooth

Проверенные RGB, включение, выключение и яркость сохранены. Неизвестные режимы
по-прежнему требуют отдельного `led probe` с ручным наблюдением. Ошибка адаптера,
выключенный Bluetooth и запрет доступа различаются по причине, которую вернул Bleak.

Если старый UUID не найден, запись не выполняется и устройство не выбирается
по одному совпадению имени. Новый `led discover` асинхронно ищет кандидатов
четыре секунды. UUID меняется в локальной конфигурации после проверки человеком;
это сбрасывает подтверждения старого профиля. Отправки команд во время поиска нет.

## Измерения скорости

Все замеры выполнены на этом Mac. Микрофон не записывался, звук не воспроизводился,
личная история не отправлялась модели. Замеры не являются гарантией времени
каждого будущего запроса.

- **Маршрутизация, 200 повторов каждого примера:** из шести приведённых точных
  команд до изменений распознавалась одна, после — все шесть. Медиана нового
  маршрутизатора 0,0024–0,0073 мс, p95 до 0,0089 мс. Это только разбор текста,
  без STT, Bluetooth, macOS и TTS. Основная экономия — исключённый LLM-запрос.
- **Полная локальная команда времени:** 2,0–3,3 мс в трёх проходах через Conversation,
  реестр и временную SQLite в памяти. Это измерение backend без озвучки.
- **Нейтральный потоковый LLM-запрос:** «Что такое радуга? Одно короткое предложение».
  До исправления benchmark с новыми клиентами: первый текст 14,98 / 10,06 / 6,11 с,
  полный ответ 15,85 / 10,98 / 7,15 с. Модель ответа — Ollama `qwen3:8b`.
- **Тот же benchmark с общим клиентом:** первый текст 6,90 / 3,53 / 5,95 с,
  полный ответ 8,08 / 4,58 / 7,01 с. Gemini сообщил о лимите запросов; во втором
  и третьем проходах оба облачных кандидата пропускались по cooldown.
  Это диагностическое сравнение разных последовательных замеров, а не чистое
  измерение ускорения LLM: состояние сервиса и кеша между ними менялось.
- **STT Whisper large-v3-turbo:** самостоятельно синтезированная фраза
  «Сделай ленту светло-розовой», mono PCM16, 1,6625 с. Загрузка и прогрев 1,83 с;
  распознавание 0,505 / 0,531 / 0,516 с, результат непустой во всех проходах.
  Модель использовалась офлайн, без скачивания.
- **Silero TTS:** загрузка и прогрев 2,58 с; синтез «Проверка скорости» после
  прогрева — 0,0196 с. Это время получения массива звука первого предложения,
  а не старта физического аудиоустройства.
- **Холодный полный локальный промпт:** 6850 токенов, 22,33 с prefill. Поэтому
  после фактического перехода на Ollama теперь снова используется предусмотренный
  фоновый прогрев. Новая просьба отменяет его, чтобы не ждать фоновой операции.
  Прогрев не вызывает системные инструменты и не обращается к Gemini.

Профиль голосового запроса публикует `stt_s`, `llm_first_token_s`,
`llm_first_text_s`, `llm_total_s`, `tool_execution_s`, `tts_first_audio_s`,
`total_response_s`. Сохранены прежние поля HUD и список `stages`.
Первый токен не суммируется между раундами, время LLM и инструментов суммируется.
`null` означает неиспользованный или неизмеренный этап. `total_response_s` в голосе
считается от конца входной речи до окончания ответа; прежний `response_s` — до
начала озвучки. Метрики не содержат текста запросов, ключей и аудио.

Лимит Gemini кодом не устранён. Для сложных ответов через Ollama по-прежнему
возможна задержка в несколько секунд, а холодный полный промпт дороже. Настройки
моделей, thinking, контекстного окна и профиля памяти не заменялись ради скорости.

## Проверка и воспроизведение

```sh
uv run pytest -q tests/test_critical_fixes.py tests/test_dialogue_context.py tests/test_led.py
uv run pytest -q
uv run ruff check backend tests/test_critical_fixes.py tests/test_tools.py tests/test_llm_conversation.py
uv run python -m backend latency-check --runs 3
uv run python -m backend latency-check --live --stream --tts --runs 3
uv run python -m backend latency-check --stt-file path/to/mono-pcm16.wav --runs 3
```

`--live` явно включает нейтральный сетевой запрос; остальные команды не требуют
облака. Сохранённые локальные результаты находятся в `data/critical-fixes/`:
`before.json`, `after.json`, `live-latency.json`, `live-shared-client.json`,
`stt-latency.json`, `local-context-count.json`. Эта папка исключена из Git.

Регрессии A–G находятся в `tests/test_critical_fixes.py`. Дополнительно проверены
цитаты и отрицания, привязка безопасного предложения, отказ после смены прав,
свежий код опасного действия, атомарность истории, полный реестр инструментов,
текущая цепочка tools, приветствие в голосовом маршруте, один STT-вызов,
переиспользование LLM-клиента, отмена прогрева и поиск UUID без управления лентой.
Тесты BetterDisplay, Shortcuts, ночного сценария, памяти и голоса выполняются
в общем наборе. Живой `Youtube sleep` в рамках аудита не запускался.

Итог: **1304 теста пройдены**; Ruff и проверка форматирования изменений проходят.

# Автоматическое сохранение my-jarvis

Назначение: `https://github.com/JelizavetaKirsanova/chushpan.git`, ветка `main`.
Существующая история сохраняется. Синхронизатор не выполняет force push, rebase,
reset, автоматическое слияние или публикацию контрольных точек.

## Когда сохраняется код

1. Codex следует корневому `AGENTS.md`: перед изменениями запускает `begin`,
   после проверок — `complete -m "fix: описание изменения"`.
2. Поддерживаемый Codex `notify` (`agent-turn-complete`) дополнительно запускает
   `complete`. Существующий уведомитель Codex сохранён и вызывается первым.
   Обработчик установлен вне checkout, не записывает текст запросов или ответов,
   запускает синхронизацию только для этого проекта. Новая конфигурация notify
   применяется к новым сессиям Codex; для уже открытой сессии используется команда
   из `AGENTS.md` и фоновая проверка. Дополнительное подтверждение hooks не требуется.
3. LaunchAgent `com.chushpan.git-sync` проверяет изменения каждые 300 секунд,
   включая повтор push ранее сохранённых коммитов после восстановления связи.
   Перед периодическим коммитом файлы должны перестать изменяться минимум на
   120 секунд. Между `begin` и `complete` периодические коммиты приостановлены.
4. Обычный ручной `git commit` проходит проверку секретов и после сохранения
   автоматически пытается выполнить push. Ошибка сети не отменяет локальный коммит.

Один процесс обслуживает репозиторий за раз (`flock`). Незавершённые Git-операции,
конфликты, другая ветка, изменённый origin, недоступный сканер или секреты блокируют
публикацию. При чужих коммитах на GitHub локальная работа сохраняется; объединение
нужно выполнить осознанно, после чего обычный sync возобновит отправку.
Если Codex был прерван, маркер активной работы сохраняется: после проверки
незаконченных изменений выполните `complete`.

## Команды

Из корня проекта:

```sh
.venv/bin/python scripts/git_sync.py begin
.venv/bin/python scripts/git_sync.py complete -m "fix: исправить обработку команды"
.venv/bin/python scripts/git_sync.py status
.venv/bin/python scripts/git_sync.py backup
```

`synced` означает совпадение удалённого SHA с локальным после чтения GitHub.
`pending_push` означает, что коммиты сохранены, отправка/проверка пока не удалась.
`blocked` требует устранить указанную причину; `deferred` — ожидание завершения
работы или стабилизации файлов. Состояние и ограниченный журнал без секретов:
`.git/chushpan-sync/status.json` и `.git/chushpan-sync/events.jsonl`.
Ошибки авторизации и недоступность сети не выдают себя за успешную синхронизацию.

Автоматические сообщения перечисляют изменённые части проекта; Codex передаёт
более конкретный заголовок через `-m`. В теле коммита сохраняется перечень файлов.

## Проверка секретов и личные настройки

Gitleaks 8.30.1 установлен из официального релиза с проверкой SHA-256.
Перед коммитом проверяется точное содержимое индекса, перед push — вся доступная
история всех refs. Чистый результат истории кешируется по refs и бинарному сканеру.
Используются стандартные правила сканера; комментарии `gitleaks:allow`, переменные
GITLEAKS и репозиторные исключения не отключают проверку. Отчёты содержат только
правило, путь, строку и SHA, без значений секретов. Приватные пути дополнительно
блокируются независимо от `.gitignore`. При найденном секрете публикация
останавливается: сначала отзовите ключ и согласуйте очистку истории. Удаления
секрета из последнего файла недостаточно. Синхронизатор сам историю не переписывает.
Сканер снижает риск утечки; он не умеет распознавать любые личные сведения в прозе.

`config.yaml` содержит общие настройки без разрешённых Shortcut и активного BLE
устройства. Текущие значения этой установки сохранены в игнорируемом
`config.local.yaml`. Приоритет: общие YAML → локальные YAML → `.env` → окружение.
Настраивайте свою установку в `config.local.yaml` и `.env`. Память, диалоги,
авторизация и состояние устройств остаются в `data/` и `private/`, вне Git.
Для личного варианта характера можно указать `persona.file: private/personality.md`.
Локальные диагностические экспорты исключены; их файлы остаются на диске и в backup.
Старая история не переписывалась; её проверка не обнаружила секретов.

## Резервные копии и восстановление

Папка: `~/Library/Application Support/Chushpan/Backups/`.
Перед синхронизацией создаётся снимок `.env`, обоих YAML, `personality.md`,
`private/`, `data/` и локальных диагностических экспортов. Настроенные внешние
каталоги данных и файлы авторизации также включаются. Бинарники приложения,
кеш native и блокировки не копируются. Символические ссылки не разыменовываются.
SQLite копируется через online backup API, проверяется `quick_check` и переводится
в самодостаточный файл без зависимости от WAL. Каталоги имеют права 700, файлы — 600.
Это локальные незашифрованные копии с ограниченными правами, они не отправляются
в GitHub. Одинаковые снимки не дублируются. Хранятся 48 последних снимков и
по одному за 30 дней с копиями; первоначальная копия сохраняется отдельно.

В каждом снимке есть `manifest.json` с SHA-256 файлов. Для восстановления сначала
остановите Чушпана, сохраните отдельный снимок текущего состояния, проверьте
манифест выбранного backup, затем скопируйте нужные локальные файлы обратно.
При восстановлении `data/jarvis.db` удалите старые `jarvis.db-wal` и `jarvis.db-shm`
только после остановки приложения и создания страховочной копии. Новый запуск
прочитает восстановленные настройки и базу. Не публикуйте backup через Git.

Контрольные точки кода хранятся локально в `refs/checkpoints/*`; они включают
неотслеживаемые исходники, проходят сканер и не меняют рабочие файлы или индекс.
Просмотр: `git for-each-ref refs/checkpoints` и `git show <ref>:путь`.

## Установка заново и отключение

В новом checkout подготовьте Python-окружение и проверенный официальный Gitleaks:

```sh
.venv/bin/python -m scripts.install_git_sync --gitleaks /path/to/gitleaks
```

Установщик сохраняет сторонние настройки Codex и отказывается перезаписывать
неизвестные Git hooks или одноимённый LaunchAgent. Код не хранит GitHub токен:
Git использует существующий macOS Keychain (`osxkeychain`). Сканер и локальное
состояние находятся в `.git/chushpan-sync/`, LaunchAgent — в `~/Library/LaunchAgents/`.
В клоне установка не запускается автоматически; Git намеренно не клонирует hooks.

Для отключения остановите LaunchAgent (`launchctl bootout gui/$(id -u)/com.chushpan.git-sync`),
уберите его plist и восстановите прежний `notify` из
`.git/chushpan-sync/codex-config.before.toml`, сохранив более поздние изменения других
настроек. `git config --unset core.hooksPath` отключает проектные Git hooks.
Резервные копии и исходники при этом не удаляются.

Документация Codex: [notify](https://learn.chatgpt.com/docs/config-file/config-advanced#notifications).
Тесты `tests/test_git_sync.py` используют временные bare-репозитории, поддельный
сканер и настоящую SQLite в WAL. Рабочий проект дополнительно проверен настоящим
Gitleaks и обычным push с проверкой SHA удалённой ветки.

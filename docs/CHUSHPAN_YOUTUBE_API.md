# YouTube Data API и видео для сна — этап 6

YouTube Video и YouTube Music независимы. Новый модуль читает обычный публичный
или доступный по ссылке плейлист, выбирает ролик и проверяет воспроизведение в Safari.
Он не редактирует аккаунт, подписки или плейлисты и не получает историю YouTube.
Собственная история Чушпана хранится в той же локальной SQLite-базе.

Реальные видео при разработке не запускались. При первоначальной разработке
API проверялось на mocks; последующая живая проверка описана ниже. Gemini не используется
для получения списка или выбора видео, его ключ и fallback не изменены.

**Живая проверка 30 октября 2026 после настройки:** плейлист по умолчанию —
`PLSuZQXqwb2Uw` («Для сна»). Отдельный ключ оформлен в локальном `.env`;
официальный API вернул 31 доступное по его данным видео за 3 запроса.
Список и 31 запись `unwatched` сохранены в SQLite; новый процесс прочитал кэш
без сетевых запросов. Реальное воспроизведение в этой проверке не запускалось.
Текущий плейлист уже настроен; повторно передавать ссылку не требуется.

## Архитектура

1. `backend/media/youtube_api.py`: строго три официальных GET-метода,
   `playlists.list`, `playlistItems.list`, `videos.list`; страницы и пакеты по 50,
   без `search.list`. Метаданные: ID/название плейлиста, видео, канал/ID канала,
   длительность ISO 8601, позиция, доступность по API, канонический URL.
2. `VideoLibrary`: транзакционный кэш полного списка и история. Ошибка промежуточной
   страницы не заменяет полный старый список неполным. Старые факты, беседы и
   `youtube_music` не мигрируются и не удаляются.
3. `select_video`: доступность → исключения → длительность/канал → недавние запуски →
   непросмотренные → порядок/случайный выбор. Неизвестная/нулевая длительность
   не подходит для сна. Фильтры не ослабляются молча.
4. `backend/media/sleep_video.py`: один инструмент `youtube_sleep`, строгая
   проверка соответствия аргументов текущей русской команде. Его получают и LLM,
   и детерминированный маршрут общего `Conversation` для чата/голоса.
5. `backend/media/youtube_playback.py` и `youtube_safari.swift`: отдельный закрытый
   порт Safari. Набор фиксированных AppleScript/JavaScript в исходнике; модель
   передаёт только проверенные параметры, не скрипты, команды или пути.
   Переиспользованы компилятор, обработка Accessibility и кэш native bridge.

Данные playlist/video ID отправляются только официальному YouTube API; SQLite,
персональные факты и тексты бесед туда не отправляются. Браузер обращается к
YouTube обычным способом, с его рекламой, cookies, настройками и ограничениями.
Прогресс запрашивается только по команде; фонового опроса API/браузера нет.

## Настройка Google Cloud

1. В [Google Cloud Console](https://console.cloud.google.com/) выбери проект,
   открой **APIs & Services → Library → YouTube Data API v3 → Enable**.
2. **Credentials → Create credentials → API key**. Создай отдельный ключ YouTube,
   открой его ограничения: **API restrictions → Restrict key → YouTube Data API v3**.
   Не расширяй ограничения ключа Gemini ради этого этапа.
3. Для Python backend ограничения по HTTP referrer, Android или iOS не подходят.
   Если есть постоянный исходящий IP, настрой IP restriction; при динамическом
   домашнем IP сначала оцени его смену. В любом случае API restriction обязателен.
   Не публикуй ключ в скриншотах, Shortcut, чате, Git или frontend.
4. Добавь в существующий локальный `.env` только эти значения:

   ```dotenv
   YOUTUBE_API_KEY=свой_отдельный_ключ_только_локально
   YOUTUBE_SLEEP_PLAYLIST_URL=https://www.youtube.com/playlist?list=ID_ПЛЕЙЛИСТА
   YOUTUBE_CACHE_TTL=21600
   ```

   Не заменяй весь `.env`. Секреты должны читаться только владельцем (`chmod 600 .env`);
   в текущем проекте эти права уже установлены. Перезапусти
   ассистента обычным способом после сохранения.
   Пустые примеры добавлены в `.env.example`; сам `.env` исключён из Git.
5. В обычном YouTube создай плейлист с доступом **Открытый** или **По ссылке**,
   добавь доступные длинные ролики и скопируй ссылку. «Посмотреть позже» и история
   аккаунта не являются обычными доступными API-плейлистами.
6. В чате вставь ссылку целиком либо скажи «Запомни мой плейлист для сна» при
   активной странице плейлиста в Safari. Сохраняется ID, а не произвольный URL.
   Сохранение ссылки ещё не доказывает доступность ключа: проверь следующей командой.
7. «Какие видео есть в моём плейлисте?» — первая реальная проверка ключа,
   разрешённого API и доступности списка. Ключ не вводи в сообщение ассистенту.

Ограничения ключа в Console нельзя вывести из его строки. В этой сессии они не
проверялись в аккаунте Google; успешный API-запрос не доказывает полноту ограничений.
При 403 система честно
просит проверить включение API, ограничения и публичность, не переходит на Gemini.

Приватные плейлисты без OAuth недоступны. OAuth-поток/хранилище refresh-токенов
на этом этапе не добавлены: предусмотренный заданием рабочий вариант — публичный
или доступный по ссылке плейлист с ключом. Если понадобится приватный доступ,
потребуется отдельное подключение с минимальным `youtube.readonly`; права записи
или удаления не нужны. Токены сейчас нигде не создаются и не сохраняются.

## Настройки выбора и экрана

Необязательный раздел `config.yaml` (добавляется пользователем при необходимости):

```yaml
youtube_video:
  mode: random                 # random | order | longest | shortest
  min_seconds: 0
  max_seconds: 86400
  exclude_recent_hours: 24
  allow_repeat: false
  preferred_screen: external   # external | current
  external_uuid: null          # null → UUID из night.external_uuid
  fullscreen: true
  night_autoplay: false
  max_requests: 100            # включая повторы, на одно обновление; максимум 500
  timeout_s: 6
```

UUID сопоставляется с актуальными дисплеями при каждом запуске. Числовой display ID
не сохраняется как постоянный адрес. Если выбранный телевизор отключён, ролик
остаётся на текущем экране, ответ предупреждает об этом; физический телевизор не
включается. Если UUID не выбран, автоматически угадывать один из нескольких экранов
нельзя — используй текущий экран или настрой UUID.

Перенос и полноэкранный режим применяются только к отдельному окну с одной вкладкой.
Окно с посторонними вкладками не перемещается. Для полноэкранного режима требуется
однозначное соответствие Safari window ID и AXWindowNumber; если macOS его не даёт,
появится сообщение включить режим вручную. Результат переноса проверяется по bounds.
Новая функция не меняет BetterDisplay, яркость, аудиовыход HDMI или раскладку других окон.

## Команды

- «Добавь этот плейлист для сна» / «Запомни мой плейлист для засыпания».
- Вставка `https://www.youtube.com/playlist?list=...` в чат.
- «Какие видео есть в моём плейлисте?» — первые 10 названий в ответе, полный
  список в кэше. «Обнови плейлист» — явное обновление. «Сколько там осталось
  непросмотренных видео?» — счётчик доступных непомеченных роликов текущего списка.
- «Включи видео для сна», «Включи что-нибудь из моего плейлиста»,
  «Включи то, что я ещё не смотрела», «Включи непросмотренное видео для сна».
- «Включи случайное непросмотренное», «Включи самое длинное видео»,
  «Включи самое короткое видео», «Включи следующее видео из плейлиста».
- «Включи что-нибудь на два часа» — диапазон 108–132 минуты, а не обещание
  точной двухчасовой длительности. «Включи видео от 30 минут до 3 часов»;
  «Включи видео с канала Название» — точное имя без учёта регистра или ID канала.
- «Найди видео подлиннее», «Не включай то, что было вчера» — при выбранном видео.
  Последняя команда сохраняет исключение запусков за 48 часов для следующих
  выборов, не начинает воспроизведение. Это консервативное окно, не календарный день.
- «Включи повторно видео для сна» — явное разрешение повтора, если свежих нет;
  остальные фильтры, включая недавние запуски, остаются в силе.
- «Поставь на паузу», «Продолжи видео», «Следующее видео», «Что сейчас играет?»,
  «Сколько длится этот видос?», «Сколько ещё осталось?» — выбранное Чушпаном видео.
- «Я это уже смотрела» / «Отметь видео просмотренным»,
  «Это видео ещё не смотрела», «Больше не включай это видео».
- «Сбрось историю моего плейлиста» — отдельный свежий четырёхзначный код,
  привязанный к устройству, сессии, плейлисту и версии истории. «Да» не подходит.

«Включи музыку» остаётся музыкальной командой. После успешной музыкальной команды
общая «Пауза»/«Что сейчас играет?» возвращается музыкальному маршруту; явное
«Продолжи видео» выбирает видео. Запуск видеоплейлиста не изменяет основной
Favourite Songs и назначения YouTube Music. Независимые внешние приложения
пользователь может запускать параллельно; глобальный микшер звука не добавлен.

## История и достоверность

Новые таблицы `youtube_playlist_cache`, `youtube_video_history`, namespace
`preferences.youtube_video`. Запись по `(playlist_id, video_id)` содержит название,
последний подтверждённый запуск, число запусков, статус, длительность, прогресс,
источник, updated_at и исключение. `prior_status` сохраняет прежнюю отметку при
временной недоступности. История переживает перезапуск; исчезновение из плейлиста
не удаляет её. Сброс очищает отметки/счётчики только выбранного плейлиста.

- `unwatched`: Чушпан не подтвердил воспроизведение; ручной сброс тоже возвращает сюда.
- `started`: точный video ID действительно играет, реклама не принята за ролик.
- `partially_watched`: получена достоверная позиция, длительность согласуется с API.
- `watched`: пользователь отметил или наблюдалось `ended` у того же ролика
  с позицией у конца. Просто близость к концу без `ended` не доказывает завершение.
- `skipped`: исключён явной командой, пока не помечен непросмотренным или не сброшен.
- `unavailable`: API не вернул видео, оно приватное/не обработано и т. п.

Открытая ссылка, успешный HTTP и запущенная реклама не увеличивают счётчик просмотров.
Если позже пользователь сам нажала Play, Чушпан не приписывает себе этот запуск:
без подтверждённого старта остаётся исходная отметка, пока не дана ручная команда.
Непросмотренное означает «по данным Чушпана», а не полную историю аккаунта YouTube.
Региональные/возрастные/аккаунтные ограничения могут выясниться только в браузере.

## Safari и разрешения

Текущий поддержанный браузер — уже используемый проектом Safari. Нужны Accessibility
для процесса ассистента и Automation → Safari, а в Safari **Develop → Allow JavaScript
from Apple Events**. Разрешения не выдаются кодом и настройки не переключаются скрыто.
Не требуется Screen Recording, чтение cookies или перехват клавиатуры.

Проверенные канонические `https://www.youtube.com/watch?v=VIDEO_ID` создаются из ID.
Нет переходов по произвольным ссылкам. Один подходящий YouTube watch-tab переиспользуется;
если его нет — создаётся отдельное окно, последующие запуски используют его. Несколько
роликов или неоднозначный live/shorts требуют ручного выбора; посторонние вкладки не
закрываются. Перед заменой старый плеер ставится на паузу.

Автопроигрывание YouTube выключается обычным контролом плеера; очереди `list=` нет.
Если выключение не подтверждено, плеер приостанавливается и успех не объявляется.
Play может быть заблокирован браузером; реклама, consent-dialog и изменения DOM также
дают неподтверждённый результат. Нажми Play/выключи Autoplay вручную при необходимости.
Автоматического перехода к следующему ролику после окончания модуль не делает.

## Совместимость с «Я спать»

Существующий `Youtube sleep` сохранён, UUID `1646EE92-B628-481D-9499-CED5B05EC32D`.
Его тело проверено на этапе 5: он каждые пять секунд читает `video.ended` в
**текущей вкладке переднего окна Safari**, затем через System Events усыпляет Mac.
Он сам не открывает видео. На этапе 6 повторно проверены наличие и UUID, запусков
или изменений Shortcut не было. System Events/Automation могут потребовать разрешения.

По умолчанию `night_autoplay: false`: старый сценарий остаётся встроенный 10% →
телевизор 25% → один Youtube sleep. Можно заранее выбрать видео новой командой,
сделать его активным в Safari, затем попросить «Я спать» и подтвердить код.

При явной настройке `night_autoplay: true` в подтверждении перечисляются плейлист,
порядок, фильтры и экран. После яркости модуль выбирает и проверяет один ролик,
потом проверяет, что он остаётся активным в Safari, и только после этого запускает
один Youtube sleep. Неуспех воспроизведения блокирует запуск наблюдателя.
Журнал исключает повтор видео/Shortcut после дублирования команды или перезапуска.

Пока журнал говорит, что наблюдатель мог работать, замена видео отдельной командой
блокируется. Останови Shortcut вручную в Командах, затем:

```sh
uv run python -m backend night status
uv run python -m backend night reset --confirm-stopped
```

Сброс не останавливает процессы: он требует уже выполненной ручной остановки.
После старта Shortcut пользователь всё ещё может вручную сменить Safari-вкладку;
сохранённый Shortcut последует за ней. Исправление этого ограничения потребовало бы
изменения самого Shortcut и отдельного согласия. Если видео уже окончилось,
существующая команда может усыпить Mac очень быстро.

## Кэш, квота и ошибки

TTL по умолчанию 6 часов, максимум 30 дней. Каждый из трёх использованных list-методов
стоит примерно 1 quota unit за вызов; повторы и страницы тоже расходуют квоту.
Для N элементов без недоступных ID оценка обновления:
`1 + ceil(N / 50) + ceil(N / 50)` (для пустого списка 2 запроса).
51 ролик — обычно 5 units; `search.list` не используется. Это оценка, фактическую
квоту и ограничения проверяй в Google Cloud Console своего проекта.

На запрос максимум одна повторная попытка транспортной ошибки/5xx, без скрытых SDK
повторов. На обновление максимум 30 секунд и `max_requests` попыток, включая повторные.
Очень большой список может потребовать увеличить лимит до 500, иначе неполный список
не сохраняется. 429 сразу даёт паузу 60 секунд, quota 403 — 5 минут на живой API-instance;
это предохранитель, не обещание времени сброса дневной квоты Google.

400/401/прочие 403/404 не скрываются кэшем. Временные ошибки позволяют использовать
последний полный список моложе 30 дней с предупреждением. После перезапуска свежий
SQLite-кэш работает без нового обращения; просроченный без ключа требует настройки.
Постоянных таймеров запросов нет. В логах только метод, число запросов и оценка units;
httpx INFO с URL этих endpoints подавлен. Ключ передаётся `x-goog-api-key`, не в URL.

## Ручная приёмка после настройки

1. Запусти обычный текстовый режим: `uv run python -m backend chat`.
2. Передай ссылку, запроси список, проверь названия/каналы/порядок и число
   непросмотренных. Повтори запрос — список берётся из кэша.
3. Только когда готова к реальному видео, скажи «Включи непросмотренное видео для сна».
   Проверь один ролик/одну вкладку, имя и длительность. Если запуск заблокирован,
   проверь разрешения выше, отключи Autoplay и нажми Play вручную.
4. Подключи HDMI-телевизор, настрой его UUID при необходимости, повтори осознанный
   запуск. Проверь расположение окна/полный экран; неподтверждённые шаги назовутся.
   Повтори с отключённым телевизором: должно быть явное предупреждение.
5. Проверь паузу/продолжение, оставшееся время, ручную отметку «Я это уже смотрела».
   Перезапусти ассистента, запроси оставшееся число: история должна сохраниться.
6. Проверь «Включи музыку» и паузу музыки; видеоплейлист не должен открыться.
7. Для ночной приёмки сохрани документы, оставь выбранное видео активным в Safari,
   попроси «Я спать», прочти подтверждение и только при готовности введи код:
   это реально меняет яркость и может позже усыпить Mac. Для автоматического выбора
   сначала явно выставь `night_autoplay: true` и перезапусти ассистента.
8. Не меняй активную вкладку во время Youtube sleep. После проверки останови команду
   и очисти её журнал указанным CLI; не запускай её параллельно ещё раз.
9. «Сбрось историю моего плейлиста» → «Отмена» проверяет отмену. Ввод корректного кода
   сбрасывает локальные отметки этого плейлиста; историю аккаунта YouTube не затрагивает.
